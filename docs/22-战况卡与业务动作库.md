# 22 · 战况卡与业务动作库（P0–P4 施工图）

> 来源：2026-10-24 用户完整描述用法后重新对齐。核心诉求只有一句：
> **"我不知道它打到什么、这个洞能干什么、我该说什么。"**
> 页面职责收敛为两屏：**会话（有新东西吗）→ 战况（我能做什么）**。

---

## 一、总览

| 阶段 | 内容 | 判据 |
|---|---|---|
| **P0** | 战况合并卡（等级 + 已拿到 + 每洞"能换到什么"AI 总结）+ 战果白话 + 未读红点 | 打开任务顶部一张卡能回答"我在哪/我有什么/能干嘛"；战果每行是白话；有新战果时胶囊有数字 |
| **P1** | 动态快捷短语（按当前漏洞生成 3–5 条，点一下填入，不自动发） | 输入框上方出现与"这个站"匹配的短语；点后只填入 |
| **P2** | 业务影响动作库（转账/加号/看密码/挂马/劫持/开号…） | 战况卡列出"你现在能做到的现实后果"，**默认不执行**；用户发话才做并留证 |
| **P3** | 通知 + 审查官结构化动作 | 红点/标题/桌面通知；审查官能下 kill/steer/ask 动作并绑定链 |
| **P4** | 收尾（详情页缺 id 回列表、允许/拒绝按钮收敛成一行说明） | 不再出现"任务已被删除"误报；授权只剩"在对话里说" |

## 二、P0 数据结构

```go
// GET /api/tasks/{id}/brief  —— 战况卡的唯一数据源（一次拿全，避免多请求拼接）
type Brief struct {
    Level      int      `json:"level"`        // E0–E5
    LevelLabel string   `json:"level_label"`
    Has        []Item   `json:"has"`          // 已拿到：后台会话 / 凭据 / 立足点 / 数据样本
    Can        []Ability `json:"can"`         // 每个漏洞能换到什么（AI 总结，按证据 hash 缓存）
    Actions    []Action `json:"actions"`      // 业务影响动作（P2），默认 state=idle
    SayThis    string   `json:"say_this"`     // 一句话：想做就去会话里说「…」
    NewSince   int64    `json:"new_since"`    // 未读战果条数（红点）
}
type Ability struct {
    FindingID int64  `json:"finding_id"`
    Title     string `json:"title"`   // 漏洞一句话
    Grants    string `json:"grants"`  // AI：这个洞能换来什么（不改动目标）
    Doable    bool   `json:"doable"`  // 现在就能做（有授权/有权限）
    Cached    bool   `json:"cached"`
}
```

规则：
- `Can` 的 AI 文本按 `sha256(finding 证据)` 缓存（复用 `loot_explanations` 的做法），失败回落规则模板；
- `SayThis` 是确定性模板：`想做哪一步，直接在下面主对话里说「<第一条可做动作的指令>」`；
- 全部只读，不写任何目标。

## 三、P2 业务动作库（黑客视角）

| class | 动作 | 前置 | 默认 | 留证 |
|---|---|---|---|---|
| `money_adjust` | 给账号加钱/改余额 | 后台或写库 | 不执行 | 请求+响应+变更前后 |
| `money_approve` | 把提款/订单审批通过 | 后台 | 不执行 | 同上 |
| `money_transfer` | 转账到指定地址 | 后台 | 不执行 | 同上 |
| `account_create` | 开一个管理员账号 | 后台或命令执行 | 不执行 | 同上 |
| `account_read` | 看用户名/密码/hash | 后台或 DB | 不执行 | 脱敏后展示 |
| `data_export` | 按条件导出（>样本量） | 注入/越权/DB | 不执行 | 行数+样本 3 条 |
| `deface` | 改首页/换收款地址/挂马 | 上传/写权限 | 不执行 | 前后对比截图 |
| `persist` | 留账号/计划任务 | 命令执行 | 不执行 | 命令+输出 |

纪律：**这些只出现在"你能做到"的清单里，永远不自动执行**；用户在主对话说「帮我…」才执行（沿用 0.11.7 的对话即授权），执行后把证据写回该 finding。

## 四、P3 审查官升级（与 P0/P2 同一套数据）

现在它只是"参谋"：写正文、引证据、给纠正提示，`actions` 一直是 0。升级三件事：

1. **结构化动作**：允许输出 `kill_intent / steer_intent / ask_human`，写进 `review_runs.actions`，
   界面可点采纳（复用现有 review_apply 通道）；
2. **与链/战况绑定**：读 `Brief`；链卡在"已授权但无收益"超过 N 轮 → 必须给一条具体动作；
   有可做的业务动作但用户没发话 → 只提醒一次，不重复。
3. **动作必须带判据**：每条动作要有"做完怎么算成功"（expectation），否则不落库（已有该字段，未强制）。

> 顺序理由：审查官要读 `Brief`，所以必须在 P0 之后；它的动作要和 P2 的动作库对齐，所以和 P2 一起收。

## 五、验收（每阶段一条命令级判据）

```sql
-- P0：战况卡数据齐全
curl -s /api/tasks/<id>/brief | jq '.level_label, (.has|length), (.can|length)'
-- P0-c：AI 版「能换到什么」（按证据 hash 缓存，失败回落规则版）
curl -s -XPOST /api/tasks/<id>/brief/ai | jq '.asked, .filled, ([.can[]|select(.source=="ai")]|length)'
psql -c "select finding_id,evidence_hash,left(text,30) from finding_abilities where task_id=<id>"   # 落库
curl -s /api/tasks/<id>/brief | jq '[.can[]|{id:.finding_id,source,cached}]'                        # 二次进页面应为 ai+true
-- P0-b：胶囊未读红点（打开战果面板即清零）
curl -s /api/tasks/<id>/brief | jq '.new_since'      # 有战果时应 > 0
curl -s -XPOST /api/tasks/<id>/loot/seen | jq .ok    # 打开面板时前端自动调
curl -s /api/tasks/<id>/brief | jq '.new_since'      # 期望 0（游标表 0014_loot_seen）
-- P1：动态短语
curl -s /api/tasks/<id>/phrases | jq '.phrases|length'      # 期望 3–5
-- P2：动作库只展示不执行（state 恒 idle；执行状态在 run_state）
curl -s /api/tasks/<id>/brief | jq '[.actions[].state]|unique'   # 期望 ["idle"]
-- P2：对话即授权 → 工单 → 留证（0016_action_runs）
curl -s -XPOST -H 'Content-Type: application/json'   -d '{"class":"data_export","say_it":"帮我把它数据库里的订单表数据拉出来"}'   /api/tasks/<id>/actions | jq '.run|{id,state,base_ref}'
curl -s /api/tasks/<id>/brief | jq '.actions[]|select(.class=="data_export")|{state,run_state,evidence_need}'
curl -s -XPOST -H 'Content-Type: application/json' -d '{"state":"done"}'   /api/tasks/<id>/actions/<run>/result            # 期望被拒：done 必须带证据
curl -s -XPOST -H 'Content-Type: application/json'   -d '{"state":"done","evidence":"取到 3 条样本，共 1284 行"}'   /api/tasks/<id>/actions/<run>/result            # 期望 ok
psql -c "select id,action_class,state,base_ref,evidence_ref from action_runs where task_id=<id>"
-- P3：审查官有动作
select count(*) from review_runs where task_id=<id> and jsonb_array_length(actions)>0
-- P4：缺 id 自动回列表（人工）
open /function/tasks/detail/  →  应跳回任务列表
```
