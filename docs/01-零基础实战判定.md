# 零基础实战判定 + 改造方向

> 回答两个问题：**现在给一个网址，能不能自动渗透成功？** · **该往哪里改？**
> **具体施工规格不在本文件，在 [`02-P8执行手册.md`](./02-P8执行手册.md)**（每一条都写到文件/函数/表/验收）。
> 本文件只负责说清“现状能到哪”和“为什么”。

---

## 1. 判定（分四档，别混着说）

| 目标档位 | 现在能到哪 | 判断 |
|---|---|---|
| **A. 本地靶场**（DVWA / DSVW / Juice Shop / VulHub 单机） | 1–2 分钟出首个确认战果，能出 PoC、能进台账、能出报告（DSVW 实测 52–82s） | **达标** |
| **B. 有已知漏洞族的老站点**（ThinkPHP/Struts/未打补丁的 CMS、默认口令后台） | 侦察 → 版本指纹 → 已知链验证 → 读文件/进后台，多数能到"读权限"，能否 shell 看有没有上传/命令注入面 | **基本达标**，但需要人在菜单上点"继续深挖" |
| **C. XBOW 式设计好的 Web 靶标**（104 个挑战题，18 类漏洞） | 头部产品能到 **85–97%**，但**用的都是 Opus 4.5 级模型**；本项目现在实测用的是 `deepseek-v4.1-flash`（最弱一档） | **未验证**，缺基准；换强模型 + 加基准后有机会追平中位 |
| **D. 现代真实业务站**（WAF + 业务逻辑 + 无已知 CVE） | 头部产品也打不穿。400 次重复实验（4 模型 × 100 次，同一 Juice Shop）没有任何模型给出完整攻击链；ICLR 2026 在 8000 台主机的真实校园网上对比 10 名职业渗透师，AI 仍落后 | **不可能**，不要承诺 |

**所以"零基础给个网址就能渗透成功"这句话，只在 A/B/C 三档成立，而且 C 档必须先把标尺建起来。**

现在卡住的不是"能力不够"，是 **A/B 档的体验断层 + C 档没有标尺**。下面两个小节分别说。

---

## 2. 零基础旅程的 6 道闸（每道闸断在哪）

```
开机 → 登录 → 配模型 → 配代理 → 建任务 → 跑 → 看菜单 → 点继续 → 出报告
 ①       ②        ③        ④       ⑤      ⑥      ⑦        ⑧       ⑨
```

| 闸 | 现状 | 断点 | 修法 |
|---|---|---|---|
| ① 装 | `start.bat` + `config.json` | **必须先有一个 PostgreSQL**。零基础用户装 PG 就是一道墙 | 内置嵌入式 PG（代码里已经用过嵌入式 PG18 做验收），默认零配置启动 |
| ② 登录 | 首次 setup 设密码 | 无问题 | — |
| ③ 配模型 | 系统 → LLM，填 provider/model/key/base_url | 不知道"该用哪个模型"。**用了 flash 级模型 → 表现必然差，用户会以为平台不行** | 首启向导 + 模型档位提示（planner 用强模型、worker 用便宜模型，已支持 per-agent 绑定，只是没引导） |
| ④ 配代理 | 默认 `net.proxy_http=127.0.0.1:7897` | 没起 Clash → 任务一建就 `paused`，错误只在活动流闪一次；且**UI 里改代理改的是 `global_proxy`，不是 netguard 读的 `net.proxy_http`** | 建任务前做一次"出口自检"，失败给三条人话选项（起 Clash / 填代理 / 只打本地靶场） |
| ⑤ 建任务 | 表单要填 `description` + `goal` | 零基础用户不会写 goal。后端对空 goal 不校验 → planner 直接判 done | 一个输入框：贴 URL → 自动生成 goal 模板 + 自动 `seed_first_intent` |
| ⑥ 跑 | planner 28 工具 / worker 41 工具 | 工具太多，模型选错工具概率上升；且**注入层此前只覆盖 planner/worker，主对话和 Auto 没有** | 本轮已补对话页；工具面按任务类型再裁 |
| ⑦ 看菜单 | 能力卡 13 组 91 项，白话渲染 | 只有 `SyncCapabilities` 自动派生（恒为 inferred / ≤P2），模型不主动调 `record_capability` 就没有 P3 卡 | worker 提示词里加一句"确认可利用时调 `record_capability`" |
| ⑧ 点继续 | 三档按钮 | `switch`（换目标）的 `FreezeAssetIDs` 算完没人消费 → 点了等于只写了一句 hint | 给 `add_intent` 加一个 `frozen_assets` 检查 |
| ⑨ 出报告 | `/api/report` 含能力菜单 + 台账 + 证据 | **`report_finding` 不过三门校验** → 幻觉条目能直接进报告 | 接进门（见 P8-3） |

**一句话**：能力层已经很厚（32 个机制 22 个 ✅），但**入口太窄、出口没有把关**。这是"感觉不如原版好用"的真实来源，不是能力不足。

## 3. 和头部开源的真实位置（2026-10）

| 项目 | 规模 | 架构 | 零基础入口 | 我们的位置 |
|---|---|---|---|---|
| **Strix**（usestrix） | 70.8k★ Apache-2.0 | Python + openai-agents SDK，**每扫描一个 Docker 沙箱**，Caido 代理，浏览器工具 | `strix -t <target>` 一行；也有 GitHub Action | 沙箱隔离比我们强；我们有资产台账/能力菜单/台账复查，它没有 |
| **PentAGI**（vxcontrol） | 31.7k★ MIT | Go + React + Docker Compose，多 provider，终端/浏览器沙箱 | `docker compose up -d` → `localhost:8443` → admin/admin → 填 goal | **最接近我们的形态**；它的 flow/goal 就是我们的任务/goal，多了完整沙箱 |
| **HexStrike-AI** | 生态级 | Python MCP server，150+ 工具，12+ agent 决策引擎 | 挂到 Claude/Cursor 当 MCP | 我们是自建编排，不是 MCP 桥 |
| **ARTEX 上游**（RuoJi6） | 468–1.9k★ | planner/worker + 双图 + 流量证据 | 同上，但**没有三门/能力卡/台账/注入** | 二开层确实更厚 |

**XBOW 基准公开榜**（104 题、18 类、黑盒）：RedPick 104/104、BoxPwnr 97.1%、Shannon 96.15%（白盒）、RedAmon 101/104、KinoSec 92.3%、**PentestGPT v2 91% peak / 89% mean（Opus 4.5）**、XBOW 85%、Cyber-AutoAgent 84.6%、deadend-cli 77.6%、MAPTA 76.9%。

三个可以直接抄的判断：

1. **模型档位是第一变量，不是架构**。PentestGPT v2 从 61% → 91% 靠换模型；我们用 flash 测 DSVW 拿到 82s，那只能证明"链路通"，不能证明"能打"。
2. **"一行命令 + 一个沙箱"是零基础的门槛线**，Strix 和 PentAGI 都做到了。我们还差一个"贴 URL 就开跑"。
3. **没人把"资产长期持有"做成产品**——Strix/PentAGI 都是"扫完就出报告"。台账 + 复查 + 能力菜单是我们的差异点，值得继续押。

## 4. 比原版强在哪（三条实的、三条虚的）

**实的**
1. 真相层收口：三门 + verifier 双判 + 证据时间线 —— 原版只有 `report_finding` 一段文本。**（但三门还没接进门，见 P8-3）**
2. 资产层：`assets_owned` / `access_refs` / `routes` / `asset_checks` 台账 + 到期复查 —— 原版打完就散。
3. 体验层：能力菜单白话化 + 三档决策 + 案例库正负样本 —— 原版要人自己读图。

**虚的（别信）**
1. "28 天造完、指标全达成" —— 工期数字四个版本互不相等，指标没有标尺。
2. "外部技能 818 条" —— 落地是 236 条，其中执行层只有 8 条。
3. "能力卡 13 组 82 项" —— 是 91 项；而且自动派生的卡恒为 inferred。

## 5. P8 改造清单（概览，详细施工规格见 `02-P8执行手册.md`）

> 原则：**先建标尺，再改能力**。没有 P8-1，后面 8 条改完你依然不知道有没有变强。

### P8-1 内置基准跑分（2d，最高 ROI）

做 `bench/`：Docker Compose 拉 XBOW 风格靶标子集（先取 10 题：SQLi / 命令注入 / 路径穿越 / 上传 / 反序列化 / SSRF / IDOR / 认证绕过 / 模板注入 / 弱口令），
一键 `scripts/bench_run.sh --set 10 --model <profile>` 跑批，产出 `bench/results/<ts>.json`（题目 / 通过 / 耗时 / token / 首个 finding 时间）+ 前端 `/system/bench` 看板。

**验收**：连续两次跑同一基准，通过率差异 ≤20%；每次改完机制都必须贴一张基准对比图，否则不许说"优化了"。

### P8-2 注入层收口（0.5d，本轮已完成主体）

已完成：内置默认人设（`internal/inject/persona_default.go`）、人设每请求现取（改完下一轮生效）、对话页覆盖、注入页不再强改 mode。
剩余：mainagent 也挂上 `WrapProvider`；在注入页把人设"每轮都发"的真实成本写清楚（planner/worker 的 system 每轮重拼，`cached` 与 `every-turn` 实际等价）。

**验收**：新装实例不改任何设置，问一句带攻击性的问题不出现拒答；改人设保存后，正在跑的任务下一轮就带上新人设。

### P8-3 三门接进 `report_finding`（1d，可信度硬门）

`agent/tools.go` 的 `addFinding` 前调 `verify.Check`：`rejected` → 只写 `record_fact(confidence=inferred)` 并返回"证据不足，已记为待验证"；`inferred` → 允许入库但 `proof_level≤P2` 且报告里标"未独立复现"。

**验收**：构造一条"只有版本号、没有实际触发"的 finding，必须被降为 inferred；报告里不得出现它作为"确认漏洞"。

### P8-4 一条链入口（1.5d，零基础门槛）

首页放一个输入框：贴 URL → 选目标档位（靶场 / 已知漏洞老站 / 公网站点）→ 自动：
① 出口自检（不通给三选项）② 生成 goal 模板 ③ `seed_first_intent=true` ④ 默认 `workers=3` ⑤ 跑起来后自动跳到能力菜单页。

**验收**：新装用户不打开任何设置页，只贴一个 DVWA 地址，3 分钟内看到第一张能力卡。

### P8-5 台账状态机 + 决策冻结消费者（0.5d）

`internal/ledger`：单次失败→`stale`，连续 3 次→`lost`，`verified` 超过 `stale_days` 未复查→`stale`。
`agent/tools.go` `addOneIntent`：读 `FreezeAssetIDs`（决策 `switch` 写过），命中就直接拒绝派单。

**验收**：手动把一台标的端口关掉，3 次复查后自动 `lost`；点"换目标"后 planner 不再派该资产的意图。

### P8-6 netguard 覆盖 Bash 与 WebFetch（0.5d）

`guard.preToolUse` 里对 `Bash` / `WebFetch` 调 `egress.Guard`；`net.verify_every_s` 真正生效（缓存出口 IP，默认 300s）。

**验收**：`ARTEX_ALLOW_DIRECT` 未开 + 代理不可用时，worker 的 `curl` 直连被拦并返回"出口未就绪"，而不是静默超时。

### P8-7 凭据 key 与首启向导（0.5d）

`ARTEX_CRED_KEY` 为空时：首次启动自动生成并写进 `config.json`（0600），不再静默 ephemeral；系统页显示"凭据加密：已启用（key 指纹 xxxx）"。
首启向导把 PG / 密码 / 模型 / 代理四步串成一页，每步可跳过并提示后果。

**验收**：删掉 key 重启，旧凭据仍可解；向导全程不跳设置页也能跑起一个本地靶场任务。

### P8-8 错误可解释面板（1d）

把 `errclass` 的三类（target_blocked / self_error / env_error）在任务页顶部聚合成一行：
"当前卡在：环境（代理不可用）×3 ｜ 工具缺失（sqlmap）×1 ｜ 目标拒绝（403）×5"，每条带"一键修 / 一键降级"。

**验收**：代理拔掉再跑任务，用户不看活动流就知道该修什么。

### P8-9 模型分层引导（0.5d）

建任务时按"目标档位"推荐绑定：planner=强模型、worker=便宜模型、verifier=中档。per-agent 绑定已支持，只缺 UI 引导和默认值。

**验收**：新任务默认 planner 用高能力档，worker 用便宜档；回放页能看到两档的成本差。

## 6. 现在就可以做的一件事（不需要等 P8）

打开 `系统 → 注入层`，确认：
1. "启用"打着勾；
2. "内置人设"开着（默认就开着）；
3. 人设正文留空 → 生效的是内置的《默认攻防操作员》。

然后建一个任务，goal 写：

```
目标 http://<你的靶场>/ ，先做只读侦察并输出能力菜单；只测这个地址，超时 30 分钟。
```

这是当前配置下最短的"能出东西"的路径。
