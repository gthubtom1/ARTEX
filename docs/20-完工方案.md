# 20 · 完工方案（唯一验收标准）

> 起因：2026-10-24 用户提出问题——「审查官你昨天说做好了，为什么今天还是我发现的？」
> 根因不是某个 bug，而是**"做完"的定义错了**：过去我把「代码写完 + build 过 + 单测过」
> 当成完成；真正该算完成的是「**在真实任务里产生可观察的效果**」。
> 本文件把「可观察」写成判据，逐条可执行、可复算。没有判据的功能一律不算完成。

## 1. 「完成」的判定（四条硬判据，缺一不算）

1. **可观察**：该功能在真实任务里留下痕迹（DB 行 / 接口字段 / 界面元素 / 日志行），
   且痕迹能被一条命令复算出来。
2. **有判据**：本文件 §3 的每一行都写着"怎么复查"；写不出判据的功能直接删掉，不留在界面上。
3. **失败可见**：功能不可用时，界面必须显形（不是静默降级），例如"审查官：本轮未引用证据（低可信）"。
4. **零基础可走通**：只填网址（或选一个模板）→ 出结论，中间不需要懂命令。

> 过去的反例（都是"代码做完但没判据"）：审查官写卡片但会话流无记录；
> 战果两态写了但没人标过；复核结论写库被外键吃掉却没报警。

## 2. 零基础主链路（这就是产品本身）

```
贴网址 / 选模板  →  ① 判断值不值得打  →  ② 摸入口  →  ③ 找洞取证  →  ④ 拿数据  →  ⑤ 出报告
                        ↑ 每步都有：结构化结论 + 证据 + 边界（只读/需批准）
```

现状差距（按影响排序）：

| # | 差距 | 现在的表现 | 判据（做完怎么验） |
|---|---|---|---|
| A1 | **没有"值不值得打"的结论卡** | 结论埋在 fact/hint 里，人要在活动流里翻 | 任务首页出现卡片：值得/不值得 + 3 条理由 + 攻击面列表（每项可点） |
| A2 | **没有阶段门** | 一上来就四处探，容易东一榔头西一棒 | ①模板任务里工具调用只出现只读侦察类；未产出结论前不出现漏洞利用类调用 |
| A3 | **审查官结论不带证据** | `cites=null`，卡片显示"（它没给依据）" | cites 非空且 id 全部能在库里查到；为空则自动降级为"低可信·不采纳" |
| A4 | **审查官对执行层无动作** | `actions=[]` 常态，等于只看不说 | ①任务里至少产生 1 条 `steer/kill/add_intent` 且有 `review_feedback` 行 |
| A5 | **报告不在任务首页** | 只在漏洞详情里 | 报告 Tab 能直接打开并复制 Markdown |

## 4. 执行顺序（按"对零基础的收益 / 成本"排）

### 阶段 A：把"可信"补上（1 天，收益最大）
1. **A1 值不值得打卡**：从 fact/finding 里抽结构化结论（值得/不值得 + 理由 + 攻击面），
   任务首页展示，可点进证据。
2. **A3 审查官可信度**：cites 为空 → verdict 降级为 `continue` + 标「低可信·不采纳」+
   不写 notes；非空则校验 id 必须存在于 intents/findings，非法剔除。
3. **A5 报告首页可达**：任务「报告」Tab 直接渲染 `findings.report`。

### 阶段 B：把"阶段"立起来（1–2 天）
4. **A2 阶段门**：模板带 `stage`；①阶段工具白名单（只读侦察类），产出结论后才放开；
   越界调用给"先出结论"的提示（不硬拦任务）。
5. 模板②③④⑤ 各自的结束条件写进 planner 提示（"没达到 X 不许收尾"）。

### 阶段 C：把 6 个"0 行"定性（半天）
6. 逐个跑一遍：能触发的补判据；确实无消费的**从界面删掉**（不留假旋钮）。
   - `routes`：确认是否仍有消费方，无则删表引用与页面
   - `assets_owned/asset_checks/recheck_state`：用带立足点的靶场验一次
   - `finding_cases`：同一漏洞打两次看是否建案例
   - `finding_traffic_bindings`：开流量捕获验一次
   - `loot_row_states`：UI 标一次 na 验一次

### 阶段 D：交付（半天）
7. 重新发版（当前 Release 是 v0.7.4-p9，代码已到 0.7.14；两者不一致就是"又一个静默缺陷"）。
8. 清掉 `/opt/artex/artex.bak-*`（39 个 ≈2.3GB）。
9. 文档同步：BACKLOG / RESUME / 使用教程 / 部署教程 对齐本轮 9 个版本。
10. 真机验收：干净 Linux 跑 `deploy/bootstrap.sh --with-asm` + `status.sh PASS`。

## 5. 我为什么之前会漏（承诺三条防复发）

1. **不再用"代码写完"当完成**：每个功能先写判据（§3），跑出数据才算完。
2. **每个功能上线必须带一条自检**：单测或审计脚本；`scripts/feature-audit.sh` 一次跑完 §3 的表格。
3. **每轮改完必须在一个真实任务里验**：不开新任务验证的修复，写进 BACKLOG 的"未验证"栏，
   不许标 ✅。

## 6. 反面清单（明确不做，避免又跑偏）

- 不做"多一个页面就更强"——页面只在有判据时加。
- 不做代码合并（两套系统保持两进程，只做接线）。
- 不为了"跑通"删 `.gitignore` / 绕过报错 / 强推 main。
- 不把模型选择做成开关（默认最优化；只在 Agent 页允许改绑定）。
