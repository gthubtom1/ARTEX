# 两阶段模式：侦察出菜单 → 你决策 → 再执行

> 只保留**能力卡 + 决策面板 + 侦察白名单**。目标获取/测绘/赏金流水线**不做**——目标是学校给的，不是筛出来的。
> 架构保持原作者的设计（planner / worker / 双图 / 记录代理），我们只在这一层内做增强。

---

## A.1 为什么必须分两阶段

| 全自动 | 两阶段 |
|---|---|
| 它自己决定打到什么程度 | **它只做侦察与验证，把"可选项"列给你** |
| 你不知道它到底拿到了什么 | 每个选项都有**证据 + 置信度 + 代价** |
| 一旦误判，伤害已造成 | 决策点在你手上，误判只损失时间 |
| 竞赛里容易越界丢分 | 越界动作进不了第二阶段 |

**核心认知**：侦察阶段的价值不是"发现漏洞"，是**产出"攻击面菜单"**。

菜单共 **13 组 82 项**（完整表：`kb/capabilities/taxonomy.md`），最常看的四类：
**能读数据 / 能拿管理员 / 能执行命令（挂后门）/ 能改数据**；另有凭据、文件、提权、横向、云、业务影响等组。
每项标三样：**几分熟（证明级别）、值多少钱（价值星级）、现在能不能做（阶段）**。

---

## A.2 能力卡（Capability Card）——第一阶段唯一产物

```yaml
id: cap-0007
group: 数据                  # 13 组之一
item: 1.2                    # 组内编号，便于统计覆盖面
can: 读取任意订单（含手机号/地址/金额）
surface: /api/order/detail?id=          # 完整入口
evidence:
  - "GET /api/order/detail?id=1002 + A 的 token → 200，返回 B 的手机号 138****1234"
proof_level: P2              # P1只读证明 / P2单条样本 / P3可利用 / P4批量持久
confidence: observed         # observed=亲眼看到 / inferred=推断
impact: 万级订单可枚举（PII 泄露）
bounty_value: ★★★★
risk: 读 1 条也留访问日志
next_if_approved: 枚举 1001-2000 并导出 CSV（需你确认）
forbidden: 全量导出 / 写库 / 删数据
```

**白话渲染（给你看的，直接出现在页面上）**：

```
■ 这个站我能做四件事（按价值排序）
1) 【能看数据】任意订单详情 —— 换成别人的订单号就能看到手机号、地址、金额
   证据：我用 A 的账号请求了 B 的订单 1002，返回里确实有 B 的手机号（已存证）
   要不要继续？继续的话我会批量拉 1000 条（会留访问日志）
2) 【能进后台】/admin 用 admin/admin 进去了，能看到用户列表
3) 【可能能执行命令】上传点允许 .php，但目录访问 404 —— 还差一个"包含点"
4) 【做不到】没注入（试了 6 种，2 次对照请求都无差异），数据库没对外
■ 建议先做：1（成本最低、证据最硬）
■ 我不建议做：3 的继续找包含点（这台机器 3 轮没进展了）
```

**第 4 条（做不到什么）同样重要**——负结论是下次省时间的资产。

## A.2.1 数据能力：分四级证明（你最关心的"能拿多少数据"）

| 级别 | 证据 | 允许的操作 |
|---|---|---|
| **D1 结构可见** | 表名/列名 | `information_schema.tables/columns`、`SHOW TABLES` |
| **D2 规模可知** | 行数 | `SELECT COUNT(*)`（**只 count，不 select 数据**） |
| **D3 敏感字段确认** | 列存在 + 格式 | `SELECT col FROM t LIMIT 1`（**最多 1 行，打码**） |
| **D4 可导出** | 具备导出能力 | **只记录，不执行** |

```
【能看数据】用户库可达，规模 12.4 万条
  表：users(124,301) / orders(88,102) / addresses(31,450)
  敏感列：phone / email / address / id_card（已确认存在）
  证据：information_schema 查询结果 + SELECT COUNT(*) 返回 124301
  能做到：可读取全部用户手机号与收货地址（D3 已验证，D4 未执行）
  风险：读 1 条也会留访问日志；批量导出会触发风控并违规
  要你决定：A) 到此为止（够交报告） B) 只多取 1 条证明可关联
```

**硬边界**：禁 `mysqldump` / `sqlmap --dump` / 全表 `SELECT *`；样本 ≤ 1 行且打码；`UPDATE/DELETE/INSERT` 任何阶段都禁。
**理由**：证明"可达 + 规模"就能拿分；**导出全量不会多拿分，只会多一条违规证据**。
细则：`kb/tactics/data-access-proof.md`

## A.3 阶段的硬边界（代码层，不靠模型自觉）

```go
type TaskMode string
const (
    ModeRecon  TaskMode = "recon"   // 只允许 P1/P2 证明，禁止武器化
    ModeAttack TaskMode = "attack"  // 允许 P3，但仍要过三门校验
)
```

- `recon` 模式：`StageAllowed()` **最高只到 `access`**，`foothold` 之后一律拒绝
- `recon` 的 Bash 白名单只放只读：`curl -s`(GET)、`nmap -sT`、限速 `ffuf`、`dig`、`whois`
- 任何 POST 写操作、上传、爆破、`sqlmap --dump` → 需 `attack` + 你显式批准
- 侦察结束自动生成：能力卡列表 + **"我做不到什么"清单**

## A.4 决策面板：只给三个按钮

| 你点 | 系统做什么 |
|---|---|
| **只拿证据**（默认） | 该卡升级到 P2（单条数据/单条命令输出），停 |
| **继续深挖** | 解冻该方向，允许 P3，但限定预算（15 分钟 / 20 轮） |
| **换目标** | 该 host 冻结，跳下一台 |

**默认必须是"只拿证据"**。你零基础，不该被要求做技术决策，只该做"要不要继续"的商业决策。
裁决结果回写能力卡状态，形成**队列**（一次列 N 个待裁决项），机器继续跑下一个。

## 附：明确不做的事

| 不做 | 原因 |
|---|---|
| 从测绘引擎（FOFA/Hunter/Quake）**批量捞目标** | 目标由学校/任务**给定**，不需要“全网搜” |
| 赏金 scope 管理与目标池打分 | 无赏金项目；且目标池是“筛出来的”，我们是“给定的” |

**明确要做（之前误删，现补回）**：

| 要做 | 说明 |
|---|---|
| **目标范围内的扩展** | 给了主域名 → 可以枚举子域、同 IP 旁站、同证书资产（站群）；这些属于“目标内部”，不是测绘 |
| **公网靶机支持** | 目标可以是互联网上的真实站点，不限制内网；内网/公网都走同一套流程 |
| **出口隔离** | 打公网目标必须经代理，不能暴露本机 IP（见《全局出口与网络守卫》） |

**边界**：只增强原作者架构内的一层——能力卡、决策面板、三门校验、接力、知识库、注入层、顾问与冻结门。
