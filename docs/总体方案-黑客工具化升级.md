# 总体方案：把 ARTEX 做成一台"作战机器"

> **定位**：它不是漏洞扫描器（那是"工具"），是**作战平台**——目标 → 情报 → 决策 → 执行 → 持有。
> **一句话**：**它替你做判断，你只做决定。**
> **前提**：目标由任务给定（公网或内网皆可），只在授权范围内动作。

---

## §0 什么叫"牛逼"：五条可检验的标准

| # | 标准 | 现状 | 目标 |
|---|---|---|---|
| 1 | 同一台靶机，别人 3 小时，它 **40 分钟出可复现战果** | 常在一处空转 | ✅ |
| 2 | **不会在错的地方挖到底**（有减法：冻结/预算/证伪） | 无 | ✅ |
| 3 | 说得出"**我能做什么、做不到什么**"（能力菜单） | 无 | ✅ |
| 4 | 打下来的东西 **10 天后还在账上、还能当跳板** | 无 | ✅ |
| 5 | 全程**不卡死、不乱报、不泄露本机 IP** | 部分 | ✅ |

这五条就是本项目所有改动的验收口径。**做不到这五条，加多少功能都是花架子。**

## §1 能力成熟度：现在在哪一级，要爬到哪一级

| 级 | 名字 | 判据（做到什么才算这级） | ARTEX 现状 |
|---|---|---|---|
| L0 | 扫描器 | 能跑端口/指纹/目录 | ✅（Bash + nmap） |
| L1 | 打点器 | 能验证单个漏洞、能拿 shell | ✅（planner/worker） |
| L2 | **作战单元** | 阶段门 + 能力图 + 三门校验 | ❌ 全无 |
| L3 | **战役单元** | 立足点池 + 凭据流 + 横移 | ❌ 全无 |
| L4 | **持有资产** | 台账 + 定期复查 + 跳板复用 | ❌ 全无 |
| L5 | 经验机器 | 知识库 + 正负案例 + 顾问纠偏 | 🟡 半（kb 已有骨架） |
| L6 | 规模化 | 多目标并发 + 预算调度 | ❌ 不做（时间不够） |

**目标：L4 站稳，L5 可用。** L6 明确不做——竞赛和个人使用都不需要。

## §2 五个"力量放大器"（让它强，这是本体）

### ① 工具面（Toolbelt）——没有工具就没有一切

- Kali 全量预装 + `tool_registry.json`（caps/check/install/verify/**fallback**）
- 缺工具三段式：**探测 → 自动装（官方源）→ 装不上降级**
- **禁止**把 `command not found` 甩给模型（它一看到就开始乱搓）
- 详见 `环境适配与工具自愈.md`

### ② 会话与立足点（Foothold Pool）——从"打一下"到"站住"

- 现在 `shell_open/shell_send` 是**会话级**，每个 worker 独立 run → **一个 worker 拿的 shell 另一个用不了**
- 补：`footholds` 表（host/user/proto/proxy_port/status）+ 跨 worker 共享 + 保活
- 判据：A worker 拿的 shell，B worker 能直接执行命令

### ③ 凭据流（Creds Graph）——横移的燃料

- 已有：`insert_assets.auth`、`record_intelligence`（存凭据）
- 缺：`发现 → 验证 → 复用(≤3 目标) → 过期检测` 的闭环
- 判据：一条口令自动试 22/3306/后台并记录结果；改密后被标记 `cred_stale`

### ④ 跳板与出口（Pivot + NetGuard）——能不能打到"下一跳"，以及会不会暴露自己

- `pivots` 表 + `resolveRoute(target)`；超过 3 跳不自动展开
- NetGuard：全流量走 Clash Verge、**出击前验出口 IP**、**代理挂了就停（fail-closed）**
- 判据：出口 IP 恒等于代理 IP；关掉代理任务拒绝启动
- 详见 `全局出口与网络守卫.md`

### ⑤ 知识与经验（Knowledge）——"见过"和"没见过"的差别

- `kb/`：13 组 82 项能力清单、7 个手法、接口形状、指纹→漏洞族、最小 payload
- `kb/cases/`：**正案例 + 负案例**（死路也要记，跨会话免疫）
- 判据：同指纹任务的"首次成功耗时"逐月下降

## §3 三个"纪律放大器"（让它稳，这是护栏）

| 纪律 | 治什么 | 手段 |
|---|---|---|
| **阶段门** | 没立足就跑去扫内网、没提权就谈 dump | `addOneIntent` 硬校验 stage + requires |
| **三门校验** | 把猜测当战果（幻觉） | grounding / negation / interrogation，未过门只能记 inferred |
| **冻结 + ROI** | 在错误的地方越挖越深 | 同方向 4 次无产出 → 代码层拒绝派单；方向预算；假设账本 |

> 三条纪律全部**写在代码里**，不靠提示词自觉。这是和"调 API 的参赛队"最大的差别。

## §4 两张交互面（零基础也看得懂）

### 任务页：一句话 → 菜单 → 决定

```
输入：target-a.school.edu
  ↓  recon（只读，零写操作）
输出：能力菜单（13 组 82 项里命中的那几条，白话）
  【数据】★★★★ 用户库 12.4 万条，含手机号/地址（D3 已验证）
  【凭据】★★★★ 配置里有 MySQL 明文口令
  【权限】★★★★ 普通用户可改 role 变管理员
  【做不到】注入（6 种无差异）/ 云元数据（无 SSRF）
  按钮：[只拿证据]  [继续深挖]  [换目标]
```

```
| # | 资产 | 权限 | 类型 | 拿下 | 最近复查 | 状态 | 跳板 |
| 1 | target-a | root | shell | 10-20 | 10-22 ✅ | verified | — |
| 2 | 10.20.3.15 | user | webshell | 10-20 | 10-22 ✅ | verified | #1 |
```

## §5 六周建造计划（每周一个可验收成果）

| 周 | 做什么 | 验收（当场能测） |
|---|---|---|
| **W1** | `netguard`（验 IP/切节点/fail-closed）+ `tool_registry` + toolbelt 镜像 | 关掉代理 → 任务拒绝启动；卸载 sqlmap → 自动装回或正确降级 |
| **W2** | `tasks.mode`(recon/attack) + 阶段门 + recon 白名单 | recon 任务零写操作，`foothold+` 意图被拒 |
| **W3** | `capabilities` 表 + 白话渲染 + 决策队列（三档按钮） | 跑一台：≥3 张能力卡 + ≥1 条负结论 |
| **W4** | 三门校验 + 声明式提交（只提交写进证据文件的） | 幻觉 finding → 0；报告可复现 |
| **W5** | `footholds` + 凭据流 + `pivots` 路由 | 跨 worker 复用 shell；经跳板打第二台，出口 IP = 跳板 IP |
| **W6** | `assets_owned` + 计划复查 + 台账导出 + cases 自动沉淀 | 10 天后复查仍 verified；台账可导出 |

**底线是 W1–W3**（三周）：做完就有"不泄 IP + 不乱跑 + 出菜单"的可用形态。
**W4–W6 是加分**：决定它是"能演示"还是"真能打"。

## §6 验收指标（可量化，别用"感觉"）

| 指标 | 怎么量 | 目标 |
|---|---|---|
| 打穿率 | 10 台靶机里拿下多少台 | ≥5 |
| 首次成功耗时 | 从任务开始到第一条确认战果 | 比基线 −40% |
| 幻觉率 | 误报 finding / 总 finding | < 10% |
| 空转率 | 无产出的 run / 总 run | < 20% |
| token/任务 | LLM 记录页统计 | 有上限，不失控 |
| 资产存活率 | 7 天复查后仍 verified 的比例 | ≥70% |
| 卡死率 | 需要人工干预的任务比例 | < 10% |

## §7 明确不做（防止越做越散）

| 不做 | 原因 |
|---|---|
| 自建测绘层（子域爆破/指纹库/target_pool） | 原项目已有资产图 + enrich + ScopeSentry 同步 + api-recon |
| 重写 agent 运行时 | norma SDK 成熟，重造更差 |
| 自建 C2 / 持久化框架 | 竞赛用不上，风险高；webshell 只在必要时用且赛后清理 |
| 多目标并发调度（L6） | 时间不够，收益低于 L2–L4 |
| DoS / 破坏性操作 | 一律禁止 |

## §8 风险与对策

| 风险 | 对策 |
|---|---|
| token 烧光 | planner 用强模型、worker 用便宜模型；难度自适应采样；每任务硬上限 |
| 会话边界断进度 | MEMORY.md 三段式接力 + 实例保活 |
| 模型拒答 | 注入层（可换词、按需注入） |
| 工具缺失/环境坏 | toolbelt + fallback + 降级记录 |
| 误报进报告 | 三门校验 + 声明式提交 |
| 暴露本机 IP | netguard fail-closed |
| 时间不够 | W1–W3 是底线，其余按周裁剪 |

---

## §9 一句话

**"强"不是模型更强，是它有地图（资产图）、有纪律（门/校验/冻结）、有记忆（接力/知识库）、有存量（资产台账）。**
这四样，全部能在六周内装进现有架构——**不需要换技术栈，也不需要重写。**
