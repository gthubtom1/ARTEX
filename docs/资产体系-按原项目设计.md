# 资产体系：按原项目的设计用，不另建测绘层

> 结论：**原项目自带一整套资产体系**（资产图 + 自动补全 + 外部 ASM 同步 + 前端侦察技能）。
> 我们要做的是**用它**，而不是再造一套。之前我提的"内网测绘 / target_pool"已经删掉——那是多余的。

---

## §1 原项目自带什么（代码事实）

| 组件 | 位置 | 作用 |
|---|---|---|
| **资产图** | `db/assets.go` | 节点：`root_domain / subdomain / ip / service / app / endpoint`；归属公司；父子关系与去重 key 由程序算 |
| **自动补全 enrich** | `enrich/enrich.go` | 引擎侧**非 AI** 异步池：`dnsx` 解析域名、经记录代理探 HTTP，回写 IP/端口节点与 `resolves/exposes` 边，填 `attrs.dns/attrs.http`。**HTTP 探测受 RoE 门控** |
| **外部 ASM 同步** | `server/sync_scopesentry.go` + `skills/scopesentry/` | 通过 **MCP** 从 ScopeSentry（ASM 平台）按项目/任务拉子域、Web 应用、服务，映射成"公司 + 资产"；后台批量同步，不走审批弹窗 |
| **前端接口侦察技能** | `skills/api-recon/`（含 5 个脚本） | JS 抓取、路由表、静态资源、运行时 hook（Playwright + mock），产出 API 面 |
| **MCP 挂载** | `mcphttp/` | 任何外部能力（测绘/扫描/情报）都能以 MCP 接入，不改主进程 |
| **被动发现** | 记录型 MITM 代理 + `traffic_*` 工具 | 所有请求留痕，可从流量里回捞资产与端点 |

**它没有内置的**：端口扫描器、子域爆破器、指纹库。这些靠两条路：① Bash 里跑 nmap/subfinder；② ScopeSentry 这类外部 ASM 同步进来。

---

## §2 正确的用法（一句话）

```
目标给定 → （可选）ScopeSentry 同步拿一批资产 → 资产图落地
        → enrich 自动补全（DNS/HTTP，非 AI，便宜）
        → api-recon 技能补"接口面"
        → planner 在资产图上派意图（add_task_scope 决定覆盖度分母）
        → worker 用 Bash/MCP 打点 → insert_assets 回写
```

**这就是原作者的路线**，我们不改它。

---

## §3 我们唯一要加的：把"已持有"和"可达"补进同一张图

原资产图回答"**目标有什么**"（root_domain→subdomain→ip→service→endpoint）。
它**不回答**两个问题：

1. **我手里有什么**（哪些已经打下来了、还能不能连）
2. **从这里能到哪**（哪台机器能当跳板，能到哪个网段）

这两件事不需要新建"测绘层"，只需要**在资产图上加两类边/两个属性**：

| 补充 | 挂在原模型上 | 字段 |
|---|---|---|
| 已持有 | `assets` 加 `owned_at / own_status / privilege / access_ref`（或独立表 `assets_owned` 以外键指向 assets.id） | 生命周期：owned→verified→stale→lost |
| 可达 | 新表 `pivots(asset_id, proxy_endpoint, reachable_cidrs)` | 供 `resolveRoute(target)` 选出口 |

**原则**：**新增字段/边，不新增节点类型，不新增采集器。** 这样原来的父子关系、覆盖度、去重逻辑全部照旧生效。

---

## §4 与"不做"清单的对齐

| 不做 | 原因 |
|---|---|
| 自建测绘引擎（子域爆破器/指纹库/端口库） | 原项目用 Bash + ScopeSentry + MCP 解决，重造无收益 |
| `target_pool` 目标池、赏金 scope、FOFA 批量捞目标 | 目标是给定的 |
| 新节点类型（internal_hosts 之类） | 会破坏原有覆盖度与血缘；用属性和边表达即可 |

| 要做 | 落在哪 |
|---|---|
| 目标**内部**扩展（子域/旁站/同证书） | 用现成的 `add_task_scope` / `add_company_scope` + Bash 工具 |
| 已持有资产台账与定期复查 | `assets_owned` + `asset_checks` + 现有计划任务 |
| 跳板可达性 | `pivots` 表 + `resolveRoute()` |

---

## §5 验收

- 跑一个任务：资产图里出现 subdomain→ip→service→endpoint 链，且 `enrich` 自动补上了 DNS/HTTP 属性（不需要 agent 手动 curl）
- ScopeSentry 同步 100 条资产 → 公司/资产正确归并，无重复节点
- 打下一台 → 资产图上该节点带 `owned` 状态 → 台账可见 → 7 天后自动复查
- 用跳板打第二台 → 出口 IP = 跳板 IP（见《全局出口与网络守卫》）
