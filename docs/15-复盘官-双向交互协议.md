# 复盘官 · 双向交互协议（终稿）

> 回答三个问题：①它要不要知道主 Agent 在想什么？②接受/拒绝之后它该干什么？③怎么保证它让系统变强而不是变慢。
> 依据：`docs/13`（防抖）、`docs/14`（四层判断/ack），外加三篇实证研究（见 §6）。

---

## 1. 核心结论（先给答案）

1. **不读主 Agent 的思考，只读它的产出**（事实/漏洞/意图状态/回执）。读推理会传染同一个隧道。
2. **必须先独立下判断，再看主 Agent 的回执**（commit-first）。研究显示：先看候选答案再评判，误判率高达 0.719；先独立作答再比对，误判显著下降。
3. **需要双向，但只走结构化回执**：`accepted / rejected / expired` + 理由 + 真实 id。不要自然语言长对话。
4. **每条建议必须带"可观测的预期信号"**（例如"3 轮内出现一条涉及 IIS 配置的新事实"）。**写不出预期信号的建议不许发。**
5. **接受后必须回访**（观察窗口）：到点比对预期信号；达成→记功并写经验；未达成→升级建议或判死。
6. **保留审查官，但以"能否证明提升产出率"为准**；证不出就自动降级为只读提示（可关）。

---

## 2. 它看什么 / 不看什么

| 看（结构化） | 不看 |
|---|---|
| 意图状态、尝试次数、最近产出时间 | 主 Agent 的 thinking / 对话原文 |
| 事实与漏洞（含 id 与证据摘要） | worker 的推理过程 |
| 错误分类计数（self_error / target_blocked） | planner 的规划正文 |
| 预算/轮次 | 自己上一次的结论正文（只看笔记摘要） |
| **主 Agent 的结构化回执**（结论+依据 id） | — |
| KB 命中片段、死路台账 | — |

**commit-first 落地**：每次介入分两步——先只喂"事实"让它写出判断（存为 `draft`），再喂"主 Agent 上次回执"让它做对比；若两步结论相反，必须写明"被哪条证据推翻"。

---

## 3. 一条建议的完整生命周期（含所有分支）

```
proposed ──(自检五问 + 必须有预期信号)──> dropped（不发，只记日志）
   ↓
delivered（红点 + 90s ack 窗口）
   ├─ accepted ──> observing（观察窗：10 分钟 / 3 轮）
   │                   ├─ 预期信号出现   → effective：记功，写进 notes/经验
   │                   ├─ 信号没出现     → ineffective：升级（换方向/判死）或降级建议
   │                   └─ 出现反驳证据   → voided：撤回建议，写明被哪条证据推翻
   ├─ rejected ──> 读理由
   │                   ├─ 理由已被新证据推翻 → 复提 1 次（必须带新证据）
   │                   └─ 理由成立           → 同类降权（2 次后只留红点），写入"被拒原因"
   └─ expired（90s 无人） ──> 按档位自动处理 ──> observing（同上）
```

**关键新增：`observing` 与 `voided`。** 没有这两个状态，它只会"说"不会"负责"。

---

## 4. 主 Agent 侧义务（已有协议 + 新增两条）

已有（`docs/13` §2）：收到建议 → 读现状 → 对照 → 判断影响 → 三行回执。

新增：
1. **回执必须带"我打算怎么验证"**：例如"接受：重开 #70，预期 3 轮内出现涉及 IIS 配置的新事实"。
2. **拒绝必须给可核对的理由**：引用真实 id 与状态（"#70 已在 running，重开会空转"），不能只写"不需要"。

---

## 5. 防"越帮越忙"的 7 条硬约束

| # | 约束 | 违反后果 |
|---|---|---|
| E1 | 没有可观测预期信号 → 不许发 | 空话建议直接丢弃 |
| E2 | 同类建议冷却 5 分钟、每任务 ≤10 次、自动动作 ≤5 次 | 频率失控 |
| E3 | 被拒 2 次 → 同类只留红点，不再投递 | 反复顶撞 |
| E4 | 观察窗内无改善 ≥3 次 → 熔断转 observe | 越改越乱 |
| E5 | 建议必须引用真实 id 或 KB 命中 | 幻觉 |
| E6 | 不读推理 + commit-first | 继承同一误区 |
| E7 | 它的任何动作都不得改目标/改证据/收工 | 越权 |

**唯一保留标准**：介入后 3 轮内的事实产出率（fact velocity）是否上升。持续下降 → 自动降频 → 静默。

## 6. 外部参考（实证结论，不是感觉）

- **CRITIC**（OpenReview）：批评必须能"用工具验证"，否则纠正不可靠 → 对应我们给它**只读**核验能力（graph/findings/KB），不给执行权。
- **Reviewer Capability Governs Rejection Targeting**（arXiv 2609.04270）：验证阶段并非总是有益；审查者能力决定"拒得准不准"→ 对应我们**给它强模型 + 只允许拒"可判定"的事**。
- **Commit-first LLM judging**（arXiv 2609.00088）：先看候选答案再评判，误判率 0.719；先独立作答再比对才有效 → 对应我们的 **commit-first 两步介入**。

## 8. 一句话总结

**它不是一个"会提意见的聊天框"，而是一个"提了意见要负责到底的负责人"：说之前先独立判断，说之后盯着结果，错了要认、对了要记。**
