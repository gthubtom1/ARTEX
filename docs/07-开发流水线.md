# 开发流水线（门禁 + 防漂移）

> 目的：让"做出来"和"想做的"是同一个东西。
> 本文件定义**六道门**和**四条机械约束**。任何一条不过，不许进下一步。

---

## 0. 先回答一个问题：为什么过去"编译过、没 bug，但用起来不对"

因为过去的验收只证明了一件事：**它能跑。**
没有证明另一件更重要的事：**它值得存在。**

| 一句话渗透卡（昨天的教训） | 发生了什么 |
|---|---|
| G2 实现门 | ✅ 过了（编译、点击、接口都通） |
| **G3 真实路径门** | ❌ **从来没设过这道门** |
| 结果 | 功能是真的、可用的、也是没用的——因为使用者真实路径上不需要它 |

**所以补的这道门叫 G3：不看代码，只走一遍真实使用路径。**
以及 **G4 反向门：证明"不做它会怎样"。** 这两道门是过去缺的，也是"出发点好、结果不行"的直接原因。

---

## 1. 六道门

| 门 | 谁过 | 判据（可机检 / 可复现） | 不过怎么办 |
|---|---|---|---|
| **G0 前置门** | 提想法的人 | 三问答得出来：①谁在什么场景用 ②解决的是哪一件具体事 ③现有页面为什么不够（写清"它在哪个页面、缺哪一步"）。独立新建还须过三条门槛（问题没家 / 输入拿不到 / 不造第二真相源） | 打回，不做 |
| **G1 规格门** | 设计 | 详设 13 项必填（见 §2），缺一项不许开工；**规格里出现"待定/TBD"= 不过** | 补规格 |
| **G2 实现门** | 实现 | `go build ./...` + 相关单测 + `go vet` + `tsc --noEmit`（前端）全绿；`git diff --name-only` 必须在任务卡白名单内 | 修 |
| **G3 真实路径门** | **使用者路径** | 按《验收-真实路径》模板交一份：环境 + 步骤 + 每步截图 + "用户能否在 X 秒内完成 Y"的实测；**必须有一次是别人（不是我）照文档走** | 不过 = 功能不算交付 |
| **G4 反向门** | 设计 | 证明"不做会怎样"：拿掉功能后，使用者卡在哪一步、卡多久、多花多少钱。**写不出来 = 这个功能可以不做** | 砍掉 |
| **G5 交付门** | 数据 | 命中率看板：16 张表写入情况 + 该功能自己的埋点计数；三档裁决 ≥1 次这类"被使用"证据 | 回炉 |

**门是顺序的，不许跳。** 唯一例外：纯 bug 修复（不新增界面/不新增表）可跳过 G0/G1，但 G3 不能跳过。

## 2. 详设 13 项（L2 必填，缺一不过）

```
 1  用户故事（谁 / 什么场景 / 想完成什么 / 成功长什么样）
 2  G0 三问的答案（含"为什么不是合并进现有页面"）
 3  界面规格（线框 + 每个元素作用 + 空态 / 加载态 / 失败态）
 4  状态机（每个可变元素的状态与转移条件）
 5  数据结构（新增表/字段 + 为什么不是第二份真相源）
 6  接口契约（方法 / 路径 / 入参 / 出参 / 错误码 / 超时）
 7  字段来源映射（每个展示字段 ← 哪张表哪一列，写不出来就是猜）
 8  失败态与降级（逐条：依赖挂了怎么办、AI 挂了怎么办、无数据怎么办）
 9  成本与性能（轮询间隔 / AI 调用上限 / 缓存键 / 单次 token 估算）
10  权限与安全（谁能调 / 危险动作如何限制 / 不变量）
11  埋点（怎么知道它被用了、怎么知道它没用）
12  验收（G3 步骤 + G4 反向证明 + G5 判据）
13  不许动清单 + 已知坑 + 停止条件
```

## 3. 四条机械约束（不靠自觉，靠脚本）

| # | 约束 | 实现 | 违反时 |
|---|---|---|---|
| M1 | 一个 commit 只对应一张卡 | commit message 必须含 `CARD-<id>` | `scripts/gate/commit-check.sh` 拦截 |
| M2 | 改动文件必须在卡的白名单内 | `scripts/gate/diff-whitelist.sh CARD-B01` | 脚本报红，人工确认或改卡 |
| M3 | 上游页面 diff 必须为 0 | 白名单里显式列"禁止修改"文件 | 同上 |
| M4 | 每轮开工先读冻结表 | 任务卡第 0 行固定写 `先读 docs/06-判定标准-冻结.md` | 无自动手段，靠卡约束 |

**M2 是关键**：它把"我又顺手改了别的"这件事从"靠自觉"变成"脚本报警"。

## 4. 上下文压缩后怎么恢复（执行者必读）

压缩后**不要重新理解需求**，按顺序读四样东西，读完直接开工：

```
1  docs/06-判定标准-冻结.md          ← 判断标准，不许改
2  本卡的详设（docs/08-*）           ← 要做什么，缺一项不写就说
3  任务卡（docs/06-任务卡/CARD-xx.md）← 改哪、不许动什么、怎么验
4  git log --oneline -10             ← 已经做到哪
```

**禁止**：重读全套方案、重新推导判断标准、凭印象补细节。
**允许**：发现规格自相矛盾 → 停下回报，不许自己挑一个解释。

---

## 5. 测试怎么做才不"假过"

| 层次 | 做什么 | 不算数 |
|---|---|---|
| 单元 | 纯函数（去重键、状态判定、文案模板） | — |
| 集成 | 真 PG 上跑一次写入/查询 | 用 mock 代替真库 |
| **真实路径（G3）** | 开真界面、点真按钮、贴截图、记时间 | "我看代码是对的" |
| **反向（G4）** | 拿掉功能，演示卡点 | "不做也能用"（等于自证多余） |
| 数据（G5） | 命中率看板 + 埋点计数 | "我觉得它有用" |

**G3 的硬要求**：截图里必须能看见**时间戳**和**目标任务号**；步骤必须能被第二个人照着复现；判据必须是"秒数/点击次数"这种硬指标，不许写"体验更好了"。

```
docs/08-详设-*            每个功能的 L2 详设（13 项）
docs/06-任务卡/CARD-*     每张卡：文件/行/diff/验收/坑
```

**冲突时优先级**：06 冻结表 > 07 流水线 > 08 详设 > 05 方案。
