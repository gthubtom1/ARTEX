# 27 · 产品重设计（黑客视角 → 零基础用户）

> 要求：不要用"AI 助手"的身份看这个项目，用**20 年经验的攻击者 + 产品经理**的身份，
> 把"一个完全不懂技术的人，拿着一个网址，想拿到后台或拖库"这件事，从头到尾走一遍，
> 看每个节点上**工具该说什么、该给什么按钮**。
>
> 本文是结论；实现分步进行，每步都在真机验（Kali VM）。

---

## 一、用户心智 vs 现状：五个断层

| # | 用户此刻的想法 | 现状（0.11.40） | 断层 |
|---|---|---|---|
| 1 | "我有 10 个洞，够不够拿后台？" | 战况卡有"三段式 + 目标对齐" | **洞≠可利用**：三段式是"证据→能力"，但用户看不出"这条洞离拿后台还差哪一步、值不值得继续" |
| 2 | "我该跟它说什么？" | 有 `say_it`（模板句） | **模板句不匹配站点**：同一个"拖库"，注入站和越权站该说的话完全不同 |
| 3 | "我这站到底有没有数据库？" | 目标下拉里有"拖库" | **目标是选的，不是推出来的**：站里没有 DB 迹象时，它照样让你"拖库"，用户会白烧 token |
| 4 | "这些洞能不能串起来？" | 有利用链（chain），但是派生展示 | **没有"往哪儿深究"的建议**：用户不知道下一步该推哪条、代价多大 |
| 5 | "它说能读库，是真的吗？" | 三段式 + 能力佐证 | 用户不知道"证据强度"：是"报错回显"还是"真的读到一行" |

## 二、攻击者会怎么走（7 个节点）——这才是工具的骨架

| 节点 | 攻击者脑子里在想 | 工具必须给的 | 现状缺口 |
|---|---|---|---|
| **N1 看站** | 这是什么东西？动静？有没有登录面？ | 站点画像：技术栈/CDN/WAF/入口/是否有动态参数 | 有（侦察），但没有"一句话结论：这站像什么类型" |
| **N2 找入口** | 哪个参数能被我动？ | 可打点清单（URL + 参数 + 为什么可疑） | 有（意图/发现），但没有"按可利用性排序" |
| **N3 试一个** | 先打最便宜的（未授权/默认口令/IDOR） | 每条洞的"验证成本 + 成功长什么样" | 部分（三段式缺"成本/成功特征"） |
| **N4 确认能不能用** | 报错 ≠ 能读；要看到一行数据 | **证据强度**：回显/时间差/一行数据 | 有（proof_state），但界面没强调 |
| **N5 往上推** | 这个洞让我拿到了什么位置？ | 位置坐标（前台/后台/库/主机）+ 下一步换什么 | 有等级，但缺"位置 → 下一步清单" |
| **N6 串联** | 两个洞合起来能不能绕过某个限制 | 链建议 + 缺口（缺哪个能力卡住了哪条链） | 有链，缺"建议往哪串" |
| **N7 拿结果** | 后台/数据/钱 | 目标对齐 + 证据 + 一页纸 | 目标对齐刚做，**一页纸还没有** |

## 三、五个具体的设计决定

### 决定 1：目标不是"选"的，是"推"的（自适应）
列表里 8 个目标只是**兜底词汇表**。真正显示给你的是**这个站可能达成的后果**，每个带可信度：

```
这个站看起来能做的（按把握排序）：
  ✓ 进后台                 把握高   —— 观测到 /admin 登录面 + 默认口令类线索
  ?  拖库                  把握低   —— 没看到注入点/连接串/越权读库；要试才有结论
  ✗ 改钱                   基本不可能 —— 需要先有后台+写库
```
判据（确定性）：站点是否出现该类目标的**必要条件**（登录面、动态参数、上传点、SQL 报错、连接串……）。
**"把握低/不可能"就不是给你个按钮，而是明确告诉你"这条要先证明站点有 X，否则别花这个钱"。**

### 决定 2："该说什么"= 证据 + 缺口 → 一句话（不是模板）
模板的错在于它对所有站一样。正确做法是**三段拼装**：

```
[我现在的判断] + [我要你去验的那一件事] + [成功长什么样]
例：这台站有登录面但还没拿过会话；你去试一次出厂默认口令（只试 3 组），
    成功的话后台首页能打开、左侧有用户管理菜单 —— 拿到就停，别继续爆破。
```
- 句式由**当前证据 + 缺口**拼出来（确定性），保证与你屏幕上看到的一致；
- 提供 3 个口味：`继续（按建议）` / `换路线（给两个备选）` / `收工（出结论）`，都是一句话，点了只填入不发送；
- 不懂术语也能用：句子里不出现"盲注/时间注入"这类词，只说"去掉 payload 再发一遍看差异"。

### 决定 3：漏洞卡片必须带"成本 + 成功特征 + 证据强度"
每条洞一行说完：

```
#341 未认证接口泄露上游配置   证据强度：中（响应里有配置片段，未取到业务数据）
      验证成本：1 次请求     成功长相：返回 200 且响应里出现 "accounts" 字段
      下一步：带这个接口去试 /api/account/list，一次即可
```
"成本"决定先后，"成功长相"决定怎么判断，"证据强度"决定能不能写进报告。

### 决定 4：往哪儿深究 = Top3 建议（按 ROI，不是按模型感觉）
ROI = 缺口距离（越近越先做）× 证据强度 × 风险（写操作靠后）。给三条，每条一句话，
并明确"这条要花多少（请求数/时间）/可能拿到什么/失败了怎么办"。

### 决定 5：一页纸（交付物）在"拿到东西"的那一刻自动生成
`能进哪 → 拿到什么数据 → 影响多大 → 还差什么 → 怎么修`。不再让用户从技术报告里自己摘。

## 四、按这个重设计，界面变成什么样

```
战况卡（一屏）
  ① 这站像什么        [/admin 登录面] [SQL 报错] [CDN 挡着]        ← 画像，一句话一个
  ② 我在哪 / 我有什么   E2 应用控制 · 后台会话、数据样本
  ③ 我的目标          [拿后台 ▾] 现在就能做到 → [就做这个]
                      拖库：把握低（缺“数据库查询”，且没看到注入点）
  ④ 往哪儿深究（Top3） 1) 试默认口令（1 次请求，成功=后台首页可开）
                       2) 拿 #341 去试 /api/account/list（1 次）
                       3) 换路线：先摸上传点
  ⑤ 卡在哪            target_blocked ×12（WAF）→ 换手法/降频
  ⑥ 三个说法          [继续] [换路线] [收工]   ← 点了只填入输入框
折叠：每个洞（成本/成功长相/证据强度）| 利用链 | 越界动作 | 任务管理
```

## 五、落地顺序（每步真机验）

| # | 做什么 | 判据 |
|---|---|---|
| 1 | **自适应目标**：`goal_fits` 增加 `applicable(likely/unlikely/unknown)` + 依据 | 没 DB 迹象的站，拖库显示"把握低/不可能"并说明为什么 |
| 2 | **一句话说法**（证据+缺口拼装）+ 三个口味（继续/换路线/收工） | 同一目标在"注入站"和"越权站"给出不同句子 |
| 3 | **Next Top3**（ROI 排序：缺口距离×证据强度×风险） | 三条都带"成本/成功长相/失败怎么办" |
| 4 | **漏洞卡片三要素**（成本 / 成功长相 / 证据强度） | 每条洞一眼看出"值不值得试" |
| 5 | **一页纸报告** | 拿到东西后一键生成，无术语 |
| 6 | **再跑通一条完整链**（当前版本） | 从给网址到读到数据，全程留证 |

## 六、不做（避免又变成加功能）

- 不做"目标越多越好"：8 个只是词汇表，展示按站点推断；
- 不用模板句冒充"该说什么"：句子必须由当前证据拼；
- 不让 AI 决定"能不能做到"：判定确定性，AI 只写措辞（沿用 docs/23）；
- 不做"自动执行"：一切执行由人一句话说出去。
