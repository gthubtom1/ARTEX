# 终极形态：同类项目横评 + 最终架构 + 建造顺序

> 本文是四篇设计（顾问/冻结 · 知识库 · 注入层 · 战役纪律）的**收口**：
> 把同类项目全部拆一遍，明确"偷什么"，给出最终架构与建造顺序。
> 判据只有一个：**一句话题目 → 零人工 → 拿到高分**（竞赛语义）。

---

## §1 同类项目横评（2026-10 实测数据）

## §3 最硬的四条（hxbai 从第 14 到第 1 的真实原因）

它的成绩：**单模型 deepseek-v4-flash，69/74 flag，准确率 93.2%，4 小时，14466 step，零人工**。
四个改动，按贡献排序：

### 3.1 提交前三门校验（治幻觉，贡献最大）

每个候选结论先按"有罪"处理：

1. **grounding**：逐字检查它**出现在某条真实命令输出里**；凭空出现直接判幻觉。
2. **negation**：一个**只看证据、看不到肯定推理**的怀疑者去反驳，只给它"产出该结论那条命令的聚焦证据窗口"，多票，多数反驳即否决。
3. **interrogation**：why/how 清单逐项追问来源命令、输出唯一可解释性、格式匹配。

**任何一门掉线 → 降级为"待定"，绝不硬报 confirmed。**
再叠置信分级：逐字命中的直接提交（不耗 LLM）；改写/大小写命中的才走对抗门；诱饵与低熵的不交。

**移植到 ARTEX**：
- 这就是我在 `跑偏判别与纠正.md` 里写的"证据门"，但它把"谁来判"说清楚了——**不是同一个人判自己**，而是一个只看证据的否定者。
- 落在 `agent/finding_workflow.go` + 新 `verify/` 包；`report_finding` 先跑三门，未过则转 `record_fact(confidence=inferred)`。

### 3.2 声明式提交（治"什么都交"）

只提交 agent **明确写进工作区 FLAG 文件**的候选；`session-id`、`request-id`、埋的诱饵串一律拦在门外，再按 flag 去重、单题错交封顶。

**移植**：`report_finding` 增加必填 `declared_file`（指向 `tasks/<id>/evidence/flag.txt` 或 PoC 文件），没写文件就不许报。

### 3.3 三段式接力（治"死在会话边界"）

每次会话结束，往该题的 `MEMORY.md` **顶部**写一段结构化接力块：

```
## 接力（第 N 段）
已完成原语：<最小复现命令，地址参数化成 $TARGET>
已证死路：<方向 + 为什么死>
下一步：<具体到命令>
```

下次重访直接从"下一步"接着干，不重复侦察。配合**实例保活**（不 close、IP 不漂）。

**移植**：ARTEX 的 worker 每次 run 结束已经有 transcript，但**没有"给下一个 worker 的便条"**。加 `MEMORY.md` 读写即可，成本极低、收益极高。

### 3.4 跨题学习 + 负知识

解出确认的技法按 ATT&CK 编号入库，按指纹召回给后面的题；**连走死的路也入库、跨会话免疫**。

**移植**：`kb/cases/` 增加 `result: success| dead-end` 两态；
顾问在出建议前先查"这条指纹上有没有已证死路"——**负知识比正知识更省钱**。

## §4 最终架构（六层，每层都有现成落点）

```
┌ L6 预算层  难度自适应采样 / 时间盒 / 实例保活            （新，纯 Go）
├ L5 接力层  MEMORY.md 三段式 + 证据目录规范              （新，纯文件）
├ L4 校验层  三门 grounding/negation/interrogation        （新 verify/）
├ L3 知识层  kb/ + MCP 暴露（context1337 式）+ 818 技能索引（已有，补 MCP）
├ L2 执行层  recon / exploit / postexploit 分工            （改造 agent_prompts）
├ L1 控制器  planner + adviser + 阶段门 + 能力图 + 冻结    （改 engine/tools）
└ L0 运行时  norma SDK（工具/压缩/长上下文）——**绝不重造**
```

**最重要的一条纪律（hxbai 原话）**：*薄编排 + 成熟运行时*。工具调用、上下文压缩这些别再自己写，力气全花在方法论内核上。
ARTEX 已经有 norma SDK 这一层，正好符合——**所以不要动 SDK，只加控制器能力。**

## §6 建造顺序（按"每步都能单独验收"排）

| # | 做什么 | 工期 | 验收（同一台靶机，改前/改后） |
|---|---|---|---|
| 1 | 注入层（provider 装饰器 + 2 表） | 2d | 拒答后能续跑；system token 增量 < 30% |
| 2 | **三段式接力 MEMORY.md**（最便宜的高收益） | 1d | 同一题二次进入不再重复侦察（step 数下降 ≥ 20%） |
| 3 | **三门校验 + 声明式提交** | 3d | 误报（幻觉 finding）→ 0；准确率可测 |
| 4 | 顾问 + 冻结门 | 3d | 同方向最大意图数 ≤ 4 |
| 5 | 知识层 MCP + 818 技能索引 | 2d | `kb_search` 命中率 ≥ 60% |
| 6 | 阶段门 + 能力图 | 3d | 无"没 shell 试内网"的意图 |
| 7 | 立足点池 + 路由 + toolbelt | 4d | 跨 worker 复用 shell；经代理打通 1 台内网 |
| 8 | 凭据引擎 + 分工（recon/exploit/postexploit） | 4d | 同任务 token −30%，提权成功率↑ |
| 9 | 预算层（自适应采样/保活/时间盒） | 2d | 难题不被会话边界切断 |

**总计 ≈ 24 个工作日**。若只做 1–4（≈9 天），就已经能打赢大多数"只会调 API"的参赛队——因为**准确率和小步快跑才是竞赛的分数来源**。

## §7 竞赛六域对齐（你现在只强在 web）

Tsecbench 类赛制把进攻拆六域，按占比给分。ARTEX 现状与补法：

| 域 | 占比 | ARTEX 现状 | 要补 |
|---|---|---|---|
| Web 漏洞挖掘 | 20% | **强**（指纹表 + 形状表 + 最小 payload） | 补业务逻辑/竞态 |
| 漏洞利用 | 20% | 中 | 补 PoC 落盘规范 + 三门校验 |
| 多阶段渗透 | 20% | **弱**（无立足点池/路由） | §6 第 7 步 |
| 二进制漏洞挖掘 | 15% | **无** | toolbelt 加 `pwntools / gdb / radare2 / checksec`；`skills/pwn` |
| 云攻击 | 15% | **无** | 加 `awscli/azcli/kubectl` + `skills/cloud`（device-code / SAS / metadata） |
| 对抗规避 | 10% | **无** | 差分探测闭环（喂样本 → 读检测信号 → 变异） |

**结论**：如果你的校内赛也有多域，**只做 web 最多拿 20%**。二进制和云是"有工具就有分"的域，性价比高于把 web 打磨到极致。

## §8 诚实边界（别被"很强"骗了）

1. **一句话拿全，在真实企业目标上仍不成立**；在**竞赛靶场**上成立，因为靶场有唯一解、有 flag、有边界。
2. 上面九步做完，能到"**比对手更少犯错**"，不是"AI 会魔法"。
3. **成本**：hxbai 一场 4 小时 14466 step。按 ARTEX 的多 agent 结构，同规模一场要几十到几百元 token（取决于模型）。**预算层不是优化项，是及格线。**
4. 你零基础这件事，真正的风险不是技术，是**没有能力判断"它说的对不对"**——所以 §3.1 的三门校验不是锦上添花，是给零基础的人用的**安全带**。

## §9 一句话

**ARTEX 的图是地基，别人的校验/接力/知识层是钢筋。把钢筋插进地基，它才立得住。**
顺序上：先做**便宜且立刻降错**的（接力、三门校验），再做**结构性**的（阶段门、立足点池），最后做**锦上添花**的（UI、面板）。
