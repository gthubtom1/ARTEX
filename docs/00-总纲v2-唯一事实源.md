# ARTEX 二开 · 总纲 v2（唯一事实源）

> 写这份文件的原因：`docs/` 下 24 份设计与记录互相覆盖，同一个机制有 2–4 个名字、3 个数字、2 套阈值，
> 结果每次换会话都要重新读一遍并重新裁决。**从现在起，本文件是唯一事实源。**
>
> 裁决顺序：**本文件 > `docs/进度台账.md`（活账）> `docs/最终方案-v1.md`（历史总纲）> 其余 21 份**。
> 与其余文档冲突时以本文件为准，并**不再回头改那 21 份**（它们留作历史，不参与决策）。
>
> 状态口径只有三种，别再用别的词：
> **✅ 主链路真调用｜⚠️ 有代码但主链路缺环｜❌ 只有包/文案，没有消费者**

## 0. 一句话

给一句话 → 自主推进 → 每一步有证据 → 把"能做什么"翻译成白话菜单 → 打下的资产进台账并定期复查 → 出可复现报告。
技术底子是 `planner / worker × 探索图 / 资产图`，二开只做增强层，**不重写运行时**。

## 3. 不可返工的决定（14 条，编号唯一）

前 8 条来自 `RESUME.md`（保留原文语义），后 6 条是本轮新增的裁决。

| # | 决定 | 为什么不能改 |
|---|---|---|
| D01 | **零权限门**：不做开关分级，提示词不出现「禁止/不允许」 | 一旦出现负面文案，模型会在无关步骤上脑补规则并拒执行 |
| D02 | 默认全开，用**可回滚**兜底（写前快照） | 用"禁止"控风险会让模型变笨；用"能撤销"控风险不会 |
| D03 | 目标清单与出口放**网络层**，模型看不见 | 让模型看到"你不许打 X"，等于给它一条拒绝的理由 |
| D04 | 迁移走 `schema_migrations` 账本，runner 剥离文件内 `BEGIN/COMMIT` | 手工 psql 必然会漂 |
| D05 | 表名 `local_tools_cache`（不是 `tools_cache`） | 与 `mcp_tools_cache` / `tools` 混淆过 |
| D06 | `creds_vault` 只存加密秘密本体；`task_intelligence(kind=credential)` 存叙述性情报 | 两套语义混一起会泄密 |
| D07 | 交付物表（capabilities/assumptions/evidence_timeline）任务外键 `SET NULL` | CASCADE 会静默丢证据 |
| D08 | `audit_log` 无外键、只追加 | 审计表不能因为删任务而断链 |
| D09 | 幂等键 = `keyFor(task,intent,step,tool,input)`，重复写回返回"已存在" | 重复写回报错会让 worker 误以为失败而重试 |
| D10 | **注入层挂在 provider 层**（不是改 `agent_prompts` 正文） | 正文改不了"按上下文开关"；provider 每次请求都能决策 |
| D11 | **减法用代码层硬拒绝**（同方向 4 次 0 产出），不用提示词劝告 | 提示词劝告会被"换个说法"绕过；代码拒绝不会 |
| D12 | **能力卡派生自 finding，不独立维护** | 两套真相必然不一致 |
| D13 | 六层架构固定为 §1 那六层，其他分层说法作废 | 分层漂移会导致重复造轮子 |
| D14 | **没有基准跑分就不许说"变强了"** | 24 份文档里所有"更强/更快"的判断，全都没有标尺 |

## 6. 现在真实的能力边界（不许再乐观表述）

**能做的**：本地靶场（DVWA / DSVW / Juice Shop 级）在 1–2 分钟内出首个确认战果；有已知漏洞族的老站点能打到读权限并出 PoC；打下的资产能进台账、能复查、能出报告。

**做不到的**：
1. 现代真实业务站（有 WAF + 业务逻辑复杂 + 无已知 CVE）一把打穿 —— 头部产品也一样（见 `docs/01-零基础实战判定.md` §3）。
2. 全程无人值守：`intercept_auto_decide=off` 时高危动作会挂起等人。
3. "零基础零配置"：仍然必须准备 PostgreSQL + LLM，以及**宿主层**能出网（VPS 直连或 VM 的 TUN；应用内不再有代理配置）（见 §7）。

**唯一可以把"能不能"变成客观问题的办法**：接一个基准跑分（P8-1）。在这之前，所有强弱判断都是感觉。

## 7. 零基础必须准备的 6 项（当前硬门槛）

| # | 项 | 不填的后果 |
|---|---|---|
| 1 | PostgreSQL 连接（`ARTEX_PG_DSN` 或 `config.json`） | 进程起不来 |
| 2 | 管理员密码（≥8 位） | 无法登录 |
| 3 | LLM：provider + model + api_key（+ base_url） | 任务排队，永不启动 |
| 4 | **宿主层能出网**（VPS 直连；本机打靶场启动时加 `ARTEX_ALLOW_DIRECT=1`） | 任务创建后立刻 `paused`（fail-closed） |
| 5 | 任务描述 | 后端兜底"未命名任务" |
| 6 | 任务目标 `goal` | 后端不校验；空 goal → planner 直接判 done |

> 第 1、2 项在 VPS 上已经由 `scripts/deploy_vps.sh` 一条命令做掉（装 docker + 生成随机 Postgres 密码 + 起服务），
> Windows 用户看 `install.sh` 打印的指引（Git Bash 下 `exit 2` = 需人工介入，不是脚本坏了）。
>
> 第 4 项**不再是应用配置**：D1 已删掉应用内代理，网络在宿主层解决，应用只保留"出口 IP 自检"
> 来发现 TUN 掉线 / 换机房 / 路由泄漏。它仍是最容易踩的坑——宿主出不去网，任务一建就 `paused`，
> 而错误只在活动流里出现一次。

### C.2 §2 M13（数据定位）行注（D1–D4 硬边界）

| 级别 | 证据 | 允许的操作 |
|---|---|---|
| **D1 结构可见** | 表名/列名 | `information_schema.tables/columns`、`SHOW TABLES` |
| **D2 规模可知** | 行数 | `SELECT COUNT(*)`（**只 count，不 select 数据**） |
| **D3 敏感字段确认** | 列存在 + 格式 | `SELECT col FROM t LIMIT 1`（**最多 1 行，打码**） |
| **D4 可导出** | 具备导出能力 | **只记录，不执行** |

**硬边界**：禁 `mysqldump` / `sqlmap --dump` / 全表 `SELECT *`；样本 ≤ 1 行且打码；
`UPDATE/DELETE/INSERT` **任何阶段都禁**。理由：证明"可达 + 规模"就能拿分，导出全量只会多一条违规证据。
细则：`kb/tactics/data-access-proof.md`。

### C.3 为什么必须"两阶段"（A.1 的原始论证）

| 全自动 | 两阶段 |
|---|---|
| 它自己决定打到什么程度 | **它只做侦察与验证，把"可选项"列给你** |
| 你不知道它到底拿到了什么 | 每个选项都有**证据 + 置信度 + 代价** |
| 一旦误判，伤害已造成 | 决策点在你手上，误判只损失时间 |
| 竞赛里容易越界丢分 | 越界动作进不了第二阶段 |

**核心认知**：侦察阶段的价值不是"发现漏洞"，是**产出"攻击面菜单"**；**负结论（做不到什么）是下次省时间的资产**。

- 人设另有一套开关：`PersonaMode = cached`（缺失时补）| `every-turn`；planner/worker 上两者等价（§5 最后一条）。

### E.2 拒答分流纪律（唯一真正该保留的方法论）

注入层会**掩盖真实失败**：模型拒答有时是因为"这步真的做不了"（缺工具、目标不可达、超出范围），注再多词也没用。
所以每次拒答必须带上文（哪条 intent、哪个工具、什么参数），交给顾问判断：
**拒答是"不敢"还是"不能" —— 前者注入，后者换路线。** 这个分流不做，注入层会变成噪声放大器。

### E.3 未实现部分（已在 §5 作废清单，不要重做）

### F.1 §2 M14（持有台账）行注：五态状态机

```
owned ──回访成功──▶ verified ──7天没动静──▶ stale ──连续3次失败──▶ lost
  │                    │                                          │
  └────────── 赛后清理 ─┴────────────▶ cleaned（保留记录，删后门）
```

| 状态 | 含义 | 系统动作 |
|---|---|---|
| `owned` | 刚拿下，未复查 | 24 小时内安排首次复查 |
| `verified` | 最近一次复查成功 | 按 `asset.recheck_minutes`（默认 60）复查 |
| `stale` | 未验证超过阈值（默认 **7 天**）或本次失败 | 每次失败再记一次，连续 **3 次** → `lost` |
| `lost` | 权限没了（改密/补丁/下线） | 归档，写一条负案例；**仍缺"自动重登记提示"** |
| `cleaned` | 主动清理（赛后） | 只留记录，不再探测 |

**台账导出样例（报告附录格式，原文档的成品形态）**：

```markdown
| # | 资产 | 权限 | 类型 | 拿下时间 | 最近复查 | 状态 | 跳板 |
|---|---|---|---|---|---|---|---|
| 1 | target-a.school.edu | root | shell | 10-20 14:32 | 10-22 03:00 ✅ | verified | — |
| 2 | 10.20.3.15 | user | webshell | 10-20 16:10 | 10-22 03:00 ✅ | verified | #1 |
| 3 | target-b.school.edu | admin | 后台 | 10-21 09:05 | 10-22 03:00 ⚠️ 改密 | stale | #1 |
```

（导出入口：`/function/owned` →「导出 JSON」；报告会把台账当附录。旧文档的 `artex assets export --format md` 不存在。）

- 代码口径：`internal/ledger/nextstate.go`（`DefaultMaxFails = 3`、`DefaultStaleAfter = 7*24h`）。
- 跳板纪律：`depth`（`assets_owned.depth`）记录跳数，**超过 3 跳不自动展开**（会话脆弱、链路易断）；
  跳板本身也要复查（它挂了整条链都断）；**不用别人的资产当跳板**（`via_asset` 必须能追溯到自己台账）。
- **作废**：`pivots` 表（用 `routes`）、"日历式计划任务"做复查（用 `recheck_loop.go` 独立 goroutine，C11）、
  `artex assets export --format md` 这个 CLI（不存在；导出走「持有台账 → 导出 JSON」）。

### F.2 §2 M15（自动复查）行注：复查五件事

```bash
# ① 网络层：端口还在吗
nmap -sT -Pn -p PORT HOST
# ② 应用层：页面/接口还一样吗（内容 hash 对比）
curl -s -o /tmp/p.html -w '%{http_code} %{size_download}\n' http://HOST/ && sha256sum /tmp/p.html
# ③ 证书变化（域名换供应商/证书轮换）
echo | openssl s_client -connect HOST:443 2>/dev/null | openssl x509 -noout -fingerprint -dates
# ④ 权限层：webshell/账号还能用吗（只执行 id）
curl -s "http://HOST/shell.php?cmd=id" | head -1
ssh -o BatchMode=yes -o ConnectTimeout=5 user@HOST 'id'
# ⑤ 版本变化（可能被打了补丁）
curl -sI http://HOST/ | grep -i server
```

**判据**：端口通 + 认证成功 + 命令回显正常 → `verified`；端口通但认证失败 → 标 `cred_stale` 并试池里其它凭据；
端口不通/页面 404 → `stale` → 三次后 `lost`。
**纪律**：复查只用**最小只读命令**（`id`、状态码、证书），不重复利用、不触发告警。

### F.3 `change_events` 四类比对项（来自 `docs/资产与漏洞生命周期-借鉴融合.md` §2②，并入 M15 行注）

| 比对项 | 怎么取 | 变化意味着 |
|---|---|---|
| 开放端口集合 | nmap 结果 diff | 新服务上线 / 防守加了端口 |
| 子域集合 | 与上次枚举 diff | 新业务上线（最有价值） |

| 证书指纹 + 到期日 | openssl | 换供应商 / 快过期（可做钓鱼/接管） |

**告警不做消息轰炸**：只在"新增"时提示（消失一般是下线，不重要）。

### F.4 凭据生命周期（来自同文件 §2⑤）

```
discovered → verified → in_use → rotated → invalid → archived
```

- `verified` 必须有"真实认证成功"的证据（不是"看起来能用"）。

- `rotated`/`invalid` **自动检测**：复查时登录失败 → 自动改状态。
- 全字段加密存储，报告/日志/知识库只出现引用 id（D06 / A11）。
