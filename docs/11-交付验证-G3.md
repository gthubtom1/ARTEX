## 2. G3 过程中抓到的三个真 bug（编译和单测都没抓到）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 迁移在真库上失败：`must be owner of table cando_annotations` | 我先用 postgres 手工建了表，属主是 postgres，应用用户 artex 再跑 `CREATE INDEX IF NOT EXISTS` 需要属主 | 删表让应用自己建（并记入坑：勿手工预建） |
| 2 | 复盘官 500 `快照生成失败` | SQL 里 `'%'||n.id||'%'`（text 拼 bigint）在 PG 报类型错 | 改客户端匹配：取最近错误事件，在 Go 里 `strings.Contains` |
| 3 | 同上，日志显示 `column "task_id" does not exist` | `explorations` 表没有 `task_id`（任务→探索在 `tasks.exploration_id`） | 全部改为 `exploration_id = (SELECT exploration_id FROM tasks WHERE id=$1)` |

第 3 条连带着发现：**cando 的"正在攻"查询一直静默失败**（错误被吞），所以画布上没有呼吸点——已一并修复。

### 第三轮验证：复盘官走通模型版

```
review_runs#15  model=adviser  verdict=continue  body=389 字
body（模型原文）：「目前手里已经握住的有三样：论坛网站的管理员账号可以被我们改掉口令并成功登录进去；
网站存放内容的系统能被我们直接读取里面的数据，包括用户账号和密码一类的东西；
服务器上的文件也能被我们任意读取…还差的是最关键那一步——在服务器上真正执行命令，至今没做成…」
review_notes = version 1（目标 / 方向数 / 漏洞数 / 死路 / 我方故障 / 判断基线）
命中率看板：capabilities=2  review_runs=15  review_notes=1  evidence_timeline=0  assumptions=0
```

**这次改对的关键**：不再要求模型输出 JSON（这个小模型会写超长 JSON 被截断），改成
**“规则引擎出动作（确定性、不编造）＋ 模型只出人话”**。动作仍可点、可审计；正文是真的人话。

### 第四轮验证：D01 钩子在**新任务**上真实生效

任务 #3（钩子验证-2，同一目标只读侦察）跑 8 分钟后：

```
findings = 1        evidence_timeline = 1     ← 任务 #2 是 0（钩子在其跑完后才上线）
capabilities = 2    evidence 里的 P2 = 1      ← H3 生效：能力级别由漏洞自动升到「已证实」
assumptions = 0     assets_owned = 0          ← 本任务无否定结论事实、无命令执行类漏洞（符合预期）
```

判定：**H1（证据时间线）、H3（能力级别升级）已在真实任务上验证**；H4/H5 需要“否定结论事实 /
命令执行漏洞”才触发，本任务没有，不算未通过。

### 第五轮验证：复盘官在任务 #3 上给出“资深视角”的判断

```
POST /api/tasks/3/review  →  model=adviser  verdict=continue
body（模型原文）：「你们手里已经有两处实打实的确认结果：网站搜索框那里可以被注入，
模板页面那里可以被用来读取服务器上的任意文件，连系统配置和数据库连接信息都能读到。
这两处都已经作为高危问题登记上报，但目前每一份都只写了结论，配套的复现证据还没补上，
所以还不能算可以直接交给对方看的完整材料…时间也已经用完了，再开新方向不值得…」

任务 #3 命中率：capabilities=2 creds_vault=1 evidence_timeline=2 review_notes=1 review_runs=1 tool_usage=20
```

这一段的价值在三个判断上：① 分清“已确认 vs 只写了结论”（证据不足）；② 指出超范围的
动作不必做；③ 直接给出“不要再开新方向”的收口建议——正是委托人自己做不出来的判断。
