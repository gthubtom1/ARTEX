# 最终方案 v1.0（唯一总纲）

> 本文是**整个对话的收口**。与 `docs/` 其它文档冲突时，**以本文为准**（作废清单见 §10）。
> 读者：零基础使用者（你）。你要能看懂"这东西最后长什么样、怎么建、先建哪块"。

---

## §0 一句话定位

**把 ARTEX 从"AI 打点器"改造成一个「给一句话 → 自己判断 → 自己打 → 有证据 → 长期持有」的作战平台。**
原则：**模型侧零限制（不写任何"禁止"），系统侧只保留两根看不见的管子（目标清单 + 出口隧道），其余靠"可回滚"兜底。**

## §2 项目现状（源码事实，不是猜测）

| 项 | 事实 |
|---|---|
| 技术栈 | Go 单体 + 内嵌 Next.js + PostgreSQL；agent 能力来自 `norma` SDK |
| 核心机制 | planner（唯一意图生成者）+ worker×N（只做领到的意图）+ 双图（资产图/探索图）+ 事件驱动闭环 |
| 已有的好东西 | 资产图与锚点、记录型 MITM 代理（traffic_*）、intercept 审批、llmpool 熔断、transcript 续跑、coldgraph 压缩、计划任务、report/reporter |

| 权限现状 | `PermissionMode: Bypass`（SDK 审批关闭）；intercept 规则可 ask；RoE 范围机制已被删除（只剩提示词约束） |

## §3 最终架构

### 3.1 六层

```
L6 体验   能力菜单 / 决策队列 / 台账 / 报告 / 看板
L5 持有   assets_owned / access_refs / routes / 复查 / 清理
L4 战役   凭据收割→复用 / 提权决策 / 横移 / 数据定位 / 交互 shell
L3 真相   三门校验 / 声明式提交 / 能力卡派生 / 证据时间线
L2 编排   planner + adviser + 去重/排序 + MEMORY 接力 + 预算
L1 通道   netguard（出口）/ tool_registry（工具）/ OAST / 记录代理
L0 运行时 norma SDK —— 绝不重造
```

### 3.2 数据模型（**先定这个，否则必返工**）

复用原表：`assets`、`exploration_nodes`、`task_scope`、`assets_intercept`、`finding_cases`、`traffic_*`。

新增 10 张：

| 表 | 关键字段 |
|---|---|
| `assets_owned` | asset_key(全局唯一)、access_type、privilege、depth、via_asset、status(owned/verified/stale/lost/cleaned)、first_task_id、last_verified_at |
| `access_refs` | asset_id、proto(shell/webshell/ssh/vpn/admin/db)、conn jsonb(不含明文)、cred_ref |
| `routes` | cidr、via_asset、proxy_endpoint、hops、status |
| `asset_checks` | asset_id、kind(http/ssh/port/login/webshell)、ok、latency、changed |
| `change_events` | asset_id、kind(port/subdomain/tech/cert)、before、after、ts |
| `capabilities` | task_id、group(1–13)、item、can、proof_level(P1–P4/D1–D4)、confidence、source_node_ids[] |
| `creds_vault` | 加密值(AES-GCM)、kind、verified、status、used_on[]、rotated_at |
| `assumptions` | task_id、text、status(unverified/verified/refuted)、evidence_node |
| `evidence_timeline` | task_id、asset_id、finding_id、kind、content_ref、sha256、actor |
| `audit_log` | ts、actor、tool、target、args_digest、result、task_id |
| （+`finding_retests`、`asset_events`可选） | |

**四条硬约束**：
1. `assets_owned` 是**全局**（跨任务同一条），带 `first_task_id`。
2. 凭据**加密存储**、只给引用；报告/日志/知识库永不含明文。
3. `capabilities` **派生自 finding/fact**，不独立维护。
4. 全部写回带 **幂等键**（task+intent+step hash）。

### 3.3 一次命令的完整链路（所有钩子挂在这）

```
planner 派 intent（带 stage/asset_ids/parents）
  → GateChain：去重 + 优先级排序（不拒绝、无"禁止"文案）
frontier → worker claim
  → policy：无权限门（全部可用）
  → PreToolUse：tool_presence（缺工具→装/降级，不许把 command not found 抛给模型）
  → resolveRoute(target)（查 routes）→ proxy_endpoint
  → netguard.Verify（出口 IP 校验；失败即停）
  → proxyEnv 注入（Clash mixed-port 7897 + CA）
  → 记录代理（MITM 留痕）
目标
  ← 响应（traffic_* 可查）
  ← 写回：insert_assets / record_fact / report_finding（→ 三门）
  ← 能力卡重算 → 证据时间线追加 → MEMORY.md 追加
  ← 图变更唤醒 planner（闭环）
```

## §4 模块总表（22 个，全部可独立验收）

| # | 模块 | 作用 | 工期 | 验收 |
|---|---|---|---|---|
| M1 | `netguard` | 出口验 IP、切节点、fail-closed、订阅状态 | 1.5d | 关代理→任务拒绝启动；出口 IP 恒等代理 IP |
| M2a | 全局工具发现 | 五层扫描（PATH/常见目录/包管理/桌面启动器/**全盘**）+ 哈希/strings 指纹 + 缓存 | 1.5d | 把 sqlmap 移出 PATH 仍能发现；ffuf 改名仍能认出 |
| M2b | 安装与降级 | apt/pipx/go/GitHub Release（sha256）+ 幂等 + profile + fallback | 1d | 删掉 nuclei→自动装回或降级 |
| M2c | **工具适配器** | 每个工具 typed wrapper，输出 JSON（nmap -oX / httpx -json / nuclei -jsonl / ffuf -of json…） | 1.5d | 输出结构化，token −50%，无命令拼错 |
| M2d | 资源治理 | 并发/超时/输出上限/速率/内存磁盘保护 | 0.5d | 3 个并发扫描不把 VM 打崩 |
| M3 | `OAST` | DNS/HTTP 带外通道 | 1d | 无回显注入能判定 |
| M4 | `capabilities` | 13 组 82 项能力卡（D1–D4） | 3d | 跑一台出 ≥3 卡 + ≥1 负结论 |
| M5 | 决策队列 | 三档按钮（只拿证据/继续/换目标） | 1.5d | 裁决后任务继续，不打断 |
| M6 | `GateChain` | 去重 + 排序（无拒绝） | 1d | 同意图两次→合并 |
| M7 | `adviser` | 诊断跑偏，出 hint/steer/kill | 3d | 同方向 4 次无产出→被降优先 |
| M8 | 三门校验 | grounding/negation/interrogation | 3d | 假 finding→降 inferred |
| M9 | 声明式提交 | 只认写进证据文件的结论 | 1d | 诱饵串不被提交 |
| M10 | `MEMORY.md` 接力 | 跨 worker/会话交接块 | 1d | 二次进入 step −20% |
| M11 | `access_refs` + shell 池 | 跨 worker 共享会话 | 2d | A 的 shell B 能用 |
| M12 | 凭据收割 + 复用 | 配置/历史/DPAPI/云元数据 → 池 | 2d | 一条口令自动试 22/3306/后台 |
| M13 | 提权决策器 | LinPEAS/WinPEAS 解析 + GTFOBins 排序 | 2d | 给出 3 条可执行提权路径 |
| M14 | 横移执行器 | SSH/SMB/WMI/WinRM/DB | 2d | 经跳板拿下第二台 |
| M15 | 数据定位器 | 找 flag/敏感表（不导出） | 1d | 输出表名+行数+敏感列 |
| M16 | `assets_owned` + 复查 + 台账 | 长期持有 | 3d | 改密→下次复查 stale；台账可导出 |

| M18 | 注入层 | 可换词、按需注入（on-miss/on-refusal） | 2d | 拒答后能续跑；token 增量 <30% |
| M19 | 知识库 + MCP | kb 检索 + 818 技能索引 + 负案例 | 2d | 命中率 ≥60% |

| M21 | 回放 A/B + 看板 | 同 transcript 重跑；耗时/成本/成功率 | 2d | 能对比两次改动的效果 |

## §4.1 本轮补充的 12 个遗漏点（都已并入模块表）

| # | 遗漏 | 落点 |
|---|---|---|
| 1 | 只 `which` 会漏掉非 PATH 工具（`~/tools`、`/opt`、snap、pipx、go/bin、桌面启动器、改名二进制） | M2a 五层扫描 |
| 2 | 全盘扫描必须 `-xdev` 并排除 `/proc /sys /dev /run`、`node_modules`，否则会挂死 | M2a |
| 3 | 认不出改名的二进制 | M2a：sha256 指纹 + `strings` 特征串 |
| 4 | 工具装了但没数据（nuclei 无模板、ffuf 无字典、msf 无模块） | M2a：素材扫描（seclists/templates/wordlists/nmapservices） |
| 5 | 没有结构化输出，模型读一屏文字 → 读错/烧 token | M2c 适配器层 |
| 6 | 工具在但不可用（缺 python 依赖/缺 sudo/需 root） | M2a `healthy` 自检 + `id -u` / `sudo -n true` 探测 |
| 7 | 忽略 docker/snap 里的工具 | M2a 扫 `docker images` / `snap list` |
| 8 | 忽略"网络接口"清单（做隧道/跳板要知道有哪些网卡） | 环境快照里加 `ip -br a` |
| 9 | 忽略 GPU/hashcat、磁盘空间、内存上限 | M2d 治理 + 环境画像 |
| 10 | 无网环境装不上就会卡死 | M2b 降级表 + 离线模式（local apt cache / 预置二进制） |
| 11 | 版本不记录 → 结果不可复现 | `tools_cache.version` + 每条 finding 记录工具版本 |
| 12 | 危险操作前无 VM 快照 | M22 快照回滚 + 建议 Kali VM snapshot |

## §5 决策记录（ADR，共 14 条）

| # | 决策 | 理由 |
|---|---|---|
| A1 | 数据模型**先定后写** | 否则每加功能都要改表 |
| A2 | **零权限门、零负面文案**（不设开关/分级） | 提示词里出现"禁止 X"，模型会在无关步骤误拒 |
| A3 | 目标清单与出口隧道放**网络层**，模型不可见 | 不打断动作，但仍防出局/泄 IP |
| A4 | **可回滚代替禁止**（写前快照） | 决定"做错能不能救回来"，比"能不能做"重要 |
| A5 | 阶段门改**正向排序提示**，不拒绝 | 硬拒绝会产生错误文案，被模型误读 |
| A6 | 冻结改**完全去重 + 低优先标记** | 保留防绕圈收益，去掉拒绝副作用 |
| A7 | 三门校验改**"提交前三步核实"** | 产物是事实分类，不是拒绝 |
| A8 | 能力卡**派生自 finding** | 两套真相必不一致 |
| A9 | 顾问**无 `add_intent`** | 与 planner 抢职责会绕圈 |
| A10 | `MEMORY.md` 只做**跨 worker 交接**；transcript 做同 intent 续跑 | 避免重复 |
| A11 | 凭据**加密 + 只存引用** | 明文是最容易出事的地方 |
| A12 | 全部写回带**幂等键** + 并发锁 | 重跑/并发污染图谱 |
| A13 | 每模块**先写验收脚本再写实现** | 否则无法判断做完没有 |
| A14 | 复用原项目资产体系（资产图/enrich/ScopeSentry/api-recon），**不自建测绘层** | 重造无收益，且会破覆盖度 |

## §9 明确不做

| 不做 | 原因 |
|---|---|
| 外部测绘引擎批量捞目标 / `target_pool` / 赏金 scope | 目标是给定的 |
| 自建测绘层（子域爆破/指纹库/端口库） | 原项目已有 |
| 重写 agent 运行时 | norma 成熟 |
| 自建 C2 / 持久化框架 / 多目标并发（L6） | 竞赛用不上，风险高 |
| 权限开关/风险分级/运行期确认 | 会引发误拒（R11） |
| DoS / 破坏性清库 / 清除系统日志后继续运行 | 出局或不可逆；反取证只做"包装层 + 审计" |
| 臃肿的 CMDB/工单/合规映射/多租户 | 无实战价值 |
