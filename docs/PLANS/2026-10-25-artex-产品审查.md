## 一、PREPARE

### 1.1 用户原话（不改写）

> "我是一个完全不懂技术的人。我想拿一个网站，用这个工具去把它的漏洞找出来，然后我想知道这些漏洞到底能不能让我拿到后台权限、或者把数据库拖下来。
> 我看不懂那些漏洞名字，也不知道该跟主对话说什么话。现在我有一堆漏洞，我的目标就是拖库——这些洞够不够？该往哪个方向再深究？
> 这个工具要让我这种人能用：打开就知道现在到哪一步、能干什么、下一步该说什么话；说一句话它就去做，做完有证据；
> 不要烧我太多 token；它不能自己乱来。"

### 1.2 产品目标（一句话 → 六段链路）

> **给网址 → 找洞 → 判断这些洞能不能达成业务目标（进后台/拖库/改钱）→ 告诉我下一步说什么话 → 真去执行 → 留证据 → 出一页纸能交出去的结论。**

链路拆成六段，每段都必须能被用户"看见并验证"：
`① 输入 → ② 发现(L1) → ③ 判定(L2 拿到了什么) → ④ 目标对齐(L3 能不能换到后果) → ⑤ 一句话执行 + 留证 → ⑥ 一页纸交付`

### 1.3 目标用户

- 完全不懂技术；不认识"盲注/IDOR/CSRF"，也不该被要求认识。
- 只做**商业决策**（继续/换目标/收工），不做**技术决策**（用哪种注入手法）。
- 时间是碎片的：打开就想知道"现在能做什么"，不想读流水账。
- 怕两件事：**白花钱**（token）、**它自己乱动**（不可逆副作用）。

### 1.4 验收期望（用户能自己判断"成了没有"）

| # | 期望 | 用户怎么自己验 |
|---|---|---|
| A | 打开 5 秒说得出"我现在能做什么" | 主视线一张卡，不超过 3 条可做 + 证据号 |
| B | "这些洞够不够拖库"有确定性答案 | 答案由证据算，不由模型措辞算；换个模型答案不变 |
| C | 知道"该说什么" | 一句话可直接复制，且含"针对这个站"的具体目标/成功长相 |
| D | 说了就去做，做完有证据 | 对话→工单→证据三处能对上号 |
| E | 不烧钱 | 能看到已花多少；到点自己停；AI 按钮标明花不花钱 |
| F | 不自己乱来 | 破坏性/越权动作一律先问人；授权能收回 |
| G | 能交出去 | 一页纸、无术语、四件事齐全、没拿到就不许说拿到 |

### 1.5 硬约束（产品级不可让）

1. 不做自动执行（尤其写业务数据 / 留后门 / 删改）；执行必须由人一句话发起。
2. 判定必须确定性（Basilisk 原则：不问卷子模型"成没成"，只认证据）——这也是 `docs/23` §一 铁律 2。
3. 没证据不许点亮（`docs/25` §一 第 2 条）。
4. 花钱必须由人亲手点（`docs/24` §九）。
5. 结论要能复算（同一批证据，重算结果一致）。

## 六、我这个规划师看到的三个最大风险

1. **"能不能拖库"这件事目前仍由模型的措辞决定，而不是由证据决定** —— 等级 E3/E4 靠 `vulnclass/evidence` 里出现 "rce/样本" 这类字（`server/impact_api.go:229-243`），能力还会跨洞复用（`server/brief.go:288-350`）；后果是**用户可能拿到一份"看起来已成立、实际没打通"的结论**，而他会拿这份结论去做商业判断。
2. **"下一步该说什么"有四套说法且互不一致**（战况卡 Top3 / 会话顶横条 / 短语 / 战果行 next_prompt），其中主视线那套还是用错的证据源（`server/phrases.go:99-120`）；零基础用户没有能力裁决哪句对，一定会照最错的那句去花钱。
3. **授权这条线两头都漏**：一头是"改业务数据/开管理员号"既不拦也不要求授权（`guard/guard.go:91-135` 只有 4 类，`db/db.go:489-560`+`:620-680` 只禁 DROP/TRUNCATE/DELETE），另一头是拦了以后让人去点一个**已经不存在的按钮**（`guard/guard.go:425`），而且授权之后**没有撤销入口**（`web/src` 零处调用 `grant`）——"它不能自己乱来"目前还是话术，不是机制。
