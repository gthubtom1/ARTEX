> **命名统一（2026-10-23）**：这个角色只有一个 agent —— `agentKey=adviser`。

## 1. 用户故事

**谁**：不懂技术的委托人。
**什么时候**：任务跑到第 10 分钟以后，他开始不确定"这样打下去对不对、还要不要继续"。
**想完成什么**：有个"从外面看进来的资深的人"告诉他：现在这条方向还成不成立、哪条该扔、哪条该押、有没有漏掉最值钱的那一步；并且他能一句话否掉它。
**成功长什么样**：他不用看任何技术页面，只读一段话就知道该点哪个按钮；点完任务真的变了。

## 2. G0 三问

1. **谁在什么场景用**：任务运行中 + 收尾时，任务详情的「会话」tab。
2. **解决哪一件具体事**：整条战略方向对不对、该不该收口——不是"这条洞是真是假"（那是 verifier），不是"这张卡要不要深挖"（那是能力菜单）。
3. **现有页面为什么不够**：
   - `adviser`（LLM 顾问）只把纠偏写成 hint 节点给 planner，**人在会话里看不见**；实测 45 分钟里它在人类界面零可见。
   - `verifier` 只判单条证据真假。
   - `stall`（规则）只输出数字（`no_progress_rounds=3`），不给人话，也不给建议动作。

**为什么不是"新建第 8 个 agent"**：`adviser` 已经有独立 `agentKey`、可在 Agent 页绑模型、有冷却与 JSON 输出。**复用它的注册与模型绑定，新增的是"调用路径 + 输入快照 + 输出形态"。** 这满足独立三门槛的第 3 条（不造第二个真相源）。

## 4. 状态机

### 4.1 介入（一次评审运行）

```
idle ──触发──> queued ──(拿到锁)──> running ──> done
                        │                    ├─> superseded（落地对账：已有新进展）
                        │                    └─> self_resolved（要说的已被解决）
                        └─> failed（超时/限流/模型挂 → 退回规则版结论）
```

**触发三种**：条件（默认开）／定时（默认 10 分钟）／手动（胶囊菜单）。
**互斥**：同任务同时 1 个 running，最多 1 个 queued；冷却 5 分钟；每任务上限 10 次。

### 4.2 结论（给人的那张卡）

```
new ──采纳──> applied ──(3 轮内有新 fact)──> effective
 │                    └─(3 轮内无新 fact)──> neutral
 ├──反驳──> rebutted ──(它改口并写"旧结论+推翻证据")──> revised
 └──(证据变化)──> stale（标"已过期"，不自动重算）
```

## 5. 数据结构

```sql
-- 它自己的记忆（唯一的"全局观"载体）
CREATE TABLE IF NOT EXISTS review_notes (
  task_id   BIGINT PRIMARY KEY,
  version   INT NOT NULL DEFAULT 1,
  text      TEXT NOT NULL,              -- ≤400 token，格式见 §5.1
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 每一次介入（含快照指纹与结论，可回放）
CREATE TABLE IF NOT EXISTS review_runs (
  id        BIGSERIAL PRIMARY KEY,
  task_id   BIGINT NOT NULL,
  trigger   TEXT NOT NULL,              -- cond|timer|manual
  snapshot_hash TEXT NOT NULL,          -- sha256(快照 JSON)
  round_no  BIGINT NOT NULL,
  facts     INT NOT NULL,
  status    TEXT NOT NULL,              -- queued|running|done|superseded|self_resolved|failed
  verdict   TEXT,                        -- continue|pivot|wrapup
  body      TEXT,                        -- 人话结论
  cites     JSONB NOT NULL DEFAULT '[]', -- [{"kind":"intent","id":20},...]
  actions   JSONB NOT NULL DEFAULT '[]', -- [{"kind":"kill_intent","intent":21,"why":"..."}]
  tokens_in INT DEFAULT 0, tokens_out INT DEFAULT 0,
  model     TEXT, error TEXT, notes_version INT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(), finished_at TIMESTAMPTZ
);
CREATE INDEX IF NOT EXISTS idx_review_runs_task ON review_runs(task_id, created_at DESC);

-- 采纳/反驳/效果的账本（可信度来源）
CREATE TABLE IF NOT EXISTS review_feedback (
  id BIGSERIAL PRIMARY KEY,
  run_id BIGINT NOT NULL REFERENCES review_runs(id) ON DELETE CASCADE,
  action TEXT NOT NULL,                 -- applied|rebutted|ignored
  by_user TEXT,
  rebuttal TEXT,
  outcome TEXT,                         -- effective|neutral|wrong（3 轮后回填）
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### 5.1 笔记格式（≤400 token，只写这六行）

```
目标：__ ｜ 现在：__
死路（N）：__ / __ / __
待验证（N）：__ / __
我的建议轨迹：21:31 弃盲注→已执行 ｜ 21:31 跑哈希→未执行
未决：__
判断基线：连续3轮无新fact=该换；同手法4次同结果=死路
```

## 6. 接口契约

| 方法 | 路径 | 入参 | 出参 | 错误 |
|---|---|---|---|---|
| POST | `/api/tasks/{id}/review` | `{trigger:"manual"}` | `202 {run_id}` 或 `200 {cached:true, run}` | 429 已有 running；409 超上限 |
| GET | `/api/tasks/{id}/review/latest` | — | `{run, notes_version}` | 404 无 |
| GET | `/api/tasks/{id}/review/runs?limit=20` | — | `{runs[]}` | — |
| POST | `/api/tasks/{id}/review/{run}/apply` | `{actions:[...]}` | `{applied:[...]}` | 400 空；403 任务终止 |
| POST | `/api/tasks/{id}/review/{run}/rebut` | `{text}` | `202 {run_id}`（它会重新评审一次并改口） | 400 空文本 |
| GET | `/api/tasks/{id}/review/notes` | — | `{version, text}` | 404 |

**apply 动作允许四类**（其余一律要人手点）：
`kill_intent`（标死一条已被证死的路）、`retry_intent`（重跑被 `self_error` 搞死的路）、
`set_next_stage`（换阶段）、`propose_intent`（**只提议新方向，它自己不派活**，必须有 KB 或证据依据）。
**永不自动**：删漏洞、改严重度、改 findings 状态、改目标、收工。`propose_intent` 与 `set_next_stage` **任何档位都不自动执行**。

> 本文之后的增补（2026-10-23）：自检五问 + 8 条防抖 + 三级投递 → `docs/13`；
> 四层判断 / ack 90s / 右栏四行布局 → `docs/14`；commit-first + 强制预期信号（E1）+ 10 分钟观察窗 outcome → `docs/15`。
> 三份都已在 `internal/review/gate.go`、`server/review_loop.go`、`review-panel.tsx` 落地。

## 7. 快照字段来源（喂给它的全部内容，逐字段可查）

| 快照字段 | 来源 | 缺失降级 |
|---|---|---|
| goal | `tasks.goal` | 空 → "未写目标" |
| round_no | `explorations.round_no` | — |
| budget | `tasks.timeout_seconds` / `first_run_at` / `llm_usage` 汇总 | 缺 → 省略 |
| intents[]（id, 摘要, stage, attempts, 最近产出时间, 状态, 末次错误类） | `exploration_nodes(kind='intent')` + `activity` + `task_error_events` | 缺错误类 → 记 "unknown" |
| findings[]（id, 级别, 一句摘要, proof） | `findings` | — |
| facts_recent（最近 10 条 fact 摘要 + 时间） | `exploration_nodes(kind='fact')` | — |
| errors_by_class | `task_error_events` 分组计数 | — |
| negatives | `negativesFromTask(t)` | 空 → [] |
| owned | `assets_owned`（本任务） | 空 → [] |
| notes | `review_notes.text` | 空 → "" |
| capabilities | `capabilities`（grp/item/can/proof） | 空 → [] |

**硬规则：快照里不出现对话文本、不出现 planner 的 thinking、不出现 worker 的推理。** 这是"不继承隧道视野"的物理保证。

## 8. 失败态与降级

| 情形 | 行为 |
|---|---|
| 模型 45s 超时 / 429 / 5xx | `failed` → 用 `internal/adviser` 规则版结论（确定性），正文标注「规则版」 |
| 已有 running | 排队 1 个；再触发返回 429 + "前面还有一个在看" |
| 超上限 10 次 | 409 + "这个任务已经看够了，需要的话手动重置计数" |
| 笔记写冲突（version 不符） | 基于最新版本重写，**不静默覆盖** |
| 落地时发现已自愈 | `self_resolved` → 只投递一行"你已经解决了 ✓"，不打扰 |
| PG 查询失败 | 整卡"评审暂时不可用"，不显示半截 |
| 任务已终止 | 仍可"现在看一次"（收尾复盘），但不产生自动动作 |

## 9. 成本与性能

- 单次：快照 1–2k + 笔记 0.3k + 提示 0.5k ≈ **3–5k 输入 / ≤800 输出**
- 每任务上限 **10 次** → 约 3–4 万 token（对比任务 2000 万：0.15%）
- 冷却 5 分钟；互斥 1 running + 1 queued
- 模型：`agentKey=adviser` 的绑定（Agent 页可选你 5 个配置里的任意一个）；失败不阻塞任务
- **不占 worker 并发槽**（独立调用，不走 worker 池）

## 10. 权限与安全

| 项 | 规则 |
|---|---|
| 谁能开 | 任务创建者（同任务详情权限） |
| 三档 | 只看（默认关自动）／**低风险自动（默认）**／全自动 |
| 低风险自动允许 | `kill_intent`（仅当 `target_blocked ≥3` 或同 payload 重复 ≥3）、`retry_intent`（仅当 `self_error`/`env_error`） |
| 必须人手点 | 换阶段、加力度、收工、换目标、任何写数据动作 |
| 不变量 | **不得改证据层**：不能删 findings、不能改 severity/status、不能改 goal |
| 审计 | 每次 apply 写 `audit_log`（谁、哪条、依据） |

## 13. 不许动 + 已知坑 + 停止条件

**不许动**
- `server/adviser_llm.go` 现有规则版路径与 `stall` 判定（只加不改）
- `agent/*` 的 worker/planner 主循环
- `capabilities` 表结构与能力菜单页
- 不新建 agent 行（复用 `agentKey=adviser`）

**已知坑**
1. **顾问的提示词是代码常量**（`adviserSystemPrompt`），Agent 页编辑的那份对它无效 —— 本次要改成"读 `agent_prompts` 当前版本，缺失回退常量"，否则你改了提示词以为生效、其实没生效。
2. `pause` 会打断流式输出并留 `aborted_streaming` 坏账（实测 3 条）→ 「停下来聊」必须用**软停**（不再派新意图），不许调 pause。
3. `tasks.status` 从不写 `running` → 判断"在跑"要用 `activity` 最近时间。
4. 同一任务并发评审会让笔记互相覆盖 → 必须互斥锁 + 版本号。
5. `llm_usage.worker` 目前有 42 条空值 → 评审的调用必须写 `worker='adviser'`，否则成本归因失真。
6. 结论卡里的"证据引用"必须是 `intent_id` / `finding_id` 这种真实 id，**不许写描述性引用**（如"某条注入"），否则无法点开核对。

**停止条件**
- 若 `negativesFromTask` / `assets_owned` 结构与预期不符 → 停下回报，不改它们。
- 若同一份快照两次评审结论差异极大（verdict 相反）→ 停下回报，说明快照信息不足，需重设字段而不是加次数。
- 若模型持续输出不可解析 JSON（>20%）→ 停下回报，改用"先人话后结构"的双段输出。
