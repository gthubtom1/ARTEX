# 资产管理：从"打一次"到"长期持有"

> 需求：打下来的站不是打完就丢。**10 天后还要能回访、还能用、还能当跳板。**
> 学校评分和真实项目都看这个：**资产台账 = 你的战果凭证。**

---

## §1 三种不同的"库"，别混

| 库 | 存什么 | 生命周期 |
|---|---|---|
| **知识库 kb/** | 经验（打法、payload、死路） | 永久，去重合并 |
| **案例库 kb/cases** | 一次任务的复盘 | 永久 |
| **资产管理 assets_owned** | **活的资产**（还能连、还能用） | 有状态：owned → verified → stale → lost |

前两个是"我学过什么"，第三个是"我手里有什么"。**竞赛评分看第三个。**

---

## §2 数据模型

```sql
-- 已持有资产（肉鸡池 / 战果台账）
CREATE TABLE assets_owned (
  id bigint PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  task_id bigint,                      -- 首次拿下的任务
  host text NOT NULL,                  -- 域名或 IP
  ip text, port int,
  access_type text,                    -- shell | webshell | vpn | jump | admin | db
  access_ref text,                     -- 指向 footholds.id / 凭据池 id（不存明文）
  privilege text,                      -- user | root | admin
  os text, tech jsonb,
  depth int DEFAULT 0,                 -- 距你几跳（0=直连可达，1=需跳板…）
  via_asset bigint,                    -- 经哪台资产打下来的（跳板链）
  status text DEFAULT 'owned',         -- owned | verified | stale | lost | cleaned
  first_owned_at timestamptz DEFAULT now(),
  last_verified_at timestamptz,
  next_check_at timestamptz,
  evidence text,                       -- 指向证据文件路径
  notes text
);

-- 每次回访的结果（形成健康曲线）
CREATE TABLE asset_checks (
  id bigint PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  asset_id bigint REFERENCES assets_owned(id),
  ts timestamptz DEFAULT now(),
  kind text,                           -- http | ssh | port | login | webshell
  ok boolean, latency_ms int,
  detail text,                         -- 状态码/版本/证书指纹变化
  changed boolean DEFAULT false         -- 与上次相比是否变化
);

-- 跳板可用性（横移时用）
CREATE TABLE pivots (
  id bigint PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  asset_id bigint REFERENCES assets_owned(id),
  proxy_endpoint text,                 -- socks5://127.0.0.1:1080
  reachable_cidrs text[],
  status text DEFAULT 'up',            -- up | down
  last_ok timestamptz
);
```

## §3 生命周期的五个状态（自动流转）

```
owned ──回访成功──▶ verified ──7天没动静──▶ stale ──连续3次失败──▶ lost
  │                    │                                          │
  └────────── 赛后清理 ─┴────────────▶ cleaned（保留记录，删后门）
```

| 状态 | 含义 | 系统动作 |
|---|---|---|
| `owned` | 刚拿下，未复查 | 24 小时内安排首次复查 |
| `verified` | 最近 7 天能连通 | 每 7 天自动复查 |
| `stale` | 7–30 天未验证 | 每天复查，失败 3 次转 lost |
| `lost` | 权限没了（改密/补丁/下线） | 归档，写一条 case（`result: dead-end`） |
| `cleaned` | 主动清理（赛后） | 只留记录，不再探测 |

## §4 复查做什么（不是简单 ping）

```bash
# ① 网络层：端口还在吗
nmap -sT -Pn -p PORT HOST
# ② 应用层：页面/接口还一样吗（内容 hash 对比）
curl -s -o /tmp/p.html -w '%{http_code} %{size_download}\n' http://HOST/
sha256sum /tmp/p.html
# ③ 证书变化（域名换供应商/证书轮换）
echo | openssl s_client -connect HOST:443 2>/dev/null | openssl x509 -noout -fingerprint -dates
# ④ 权限层：webshell/账号还能用吗
curl -s "http://HOST/shell.php?cmd=id" | head -1     # 只执行 id
ssh -o BatchMode=yes -o ConnectTimeout=5 user@HOST 'id'
# ⑤ 版本变化（可能被打了补丁）
curl -sI http://HOST/ | grep -i server
```

**判据**：
- 端口通 + 认证成功 + 命令回显正常 → `verified`
- 端口通但认证失败 → 标 `cred_stale`（凭据失效），尝试凭据池里其它凭据
- 端口不通 / 页面 404 → `stale` → 三次后 `lost`

**纪律**：复查只用**最小只读命令**（`id`、状态码、证书），不重复利用、不触发告警。

## §5 定时复查（用现有能力，不新写调度）

ARTEX 0.3.17 已有**日历式计划任务**（`/function/schedules` + `calendar_schedule.go`）。直接复用：

```
计划：每天 03:00  →  动作：recheck_assets(status in (owned, stale, verified))
计划：每周一 04:00 →  动作：generate_asset_ledger（导出台账）
```

**为什么用现成的**：新的调度器会带来新的 bug 和新的时区问题，而这个已经跑在线上。

## §6 当跳板用（肉鸡复用）

```
打新目标时，planner 先问一句：这个目标我直连可达吗？
  否 → 查 pivots 表里 status='up' 且 reachable_cidrs 覆盖该目标的资产
     → 有 → 走 via_asset，命令经该跳板执行
     → 无 → 先打一个"桥"（双网卡/公网可达的内网机器）
```

- `depth` 记录跳数，**超过 3 跳不自动展开**（会话脆弱、链路易断）
- 跳板本身也要复查（它挂了整条链都断）
- **纪律**：不用别人的资产当跳板；只用自己的（`assets_owned` 里 `via_asset` 链路可追）

## §7 台账（竞赛/汇报的交付物）

```bash
artex assets export --format md   # 生成台账
```

```markdown
| # | 资产 | 权限 | 类型 | 拿下时间 | 最近复查 | 状态 | 跳板 |
|---|---|---|---|---|---|---|---|
| 1 | target-a.school.edu | root | shell | 10-20 14:32 | 10-22 03:00 ✅ | verified | — |
| 2 | 10.20.3.15 | user | webshell | 10-20 16:10 | 10-22 03:00 ✅ | verified | #1 |
| 3 | target-b.school.edu | admin | 后台 | 10-21 09:05 | 10-22 03:00 ⚠️ 改密 | stale | #1 |
```

**这张表就是"长期资产管理"的成品**：一眼看出手里有什么、哪条链还能走、哪个掉了。

## §8 与 ARTEX 接线

| 位置 | 改动 |
|---|---|
| `db` | 三张表（`assets_owned` / `asset_checks` / `pivots`） |
| `agent/tools.go` | 新工具：`register_asset` / `recheck_asset` / `list_owned_assets` / `export_ledger` |
| `server/scheduler` | 复用计划任务，注册两个内置计划（复查/导出） |
| 路由（见《专家级…》§3.3） | `pivots` 表就是路由来源，`resolveRoute(target)` 查它 |
| 前端 | 「资产」页加 Tab：已持有资产（含状态灯、下次复查、跳板链） |
| 报告 | 台账作为报告附录（评分友好） |

**验收**：
- 打下一台 → 自动出现在台账，24h 内被复查一次
- 手动改掉靶机密码 → 下次复查标 `stale` 且标记 `cred_stale`
- 用台账里的跳板去打第二台 → 命令确实经跳板执行（出口 IP = 跳板 IP）
