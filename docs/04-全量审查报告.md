## 2. 待你定（0 条 —— 全部落地）

### ~~D-4 `internal/oast` 未接线~~ → **已接线，等你的 VPS 回填地址**

**它解决什么**：有些漏洞目标**不会回显**（盲 SSRF、盲命令注入、盲 XXE、JNDI）。判断"到底有没有执行"的唯一办法，是给它一个**你能收到信的地址**：目标一旦真去访问，你这边就收到回连 —— 收到就是漏洞成立，还带源 IP 与时间。

**已落地**：
- `GET /api/oast`（状态 + 全部回调记录）、`PUT /api/oast`（改配置并**热重启**）、`POST /api/oast/test`（生成一条探测地址自测）
- 「系统 → 带外通道」页：填**监听地址** + **外部可达基址**，保存即生效；有回连记录实时显示
- 通道启用时 worker 多 2 个工具：`oast_new_url`（申请专属地址）、`oast_hits`（查回连）；**关闭时不注入，零 token 开销**
- 回归测试 `TestOASTLoop`：配置→生成地址→真的访问它→命中被记录→`GET /api/oast` 能读出→通道关闭时工具为空→非法 `public_base` 被拒

**现在的状态**：默认关闭（`oast.http_addr` 为空 → 日志明确提示"带外通道关闭"）。Kali/NAT 下**留空即可**。

**等你有 VPS 时你要做的**：打开「系统 → 带外通道」，监听地址填 `:8888`，外部基址填 `http://你的公网IP:8888`（或域名），保存。然后在防火墙/安全组放行该端口即可。**不用改代码、不用重启进程。**
