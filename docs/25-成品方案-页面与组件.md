# 25 · 成品方案（页面 · 组件 · 状态机）— 唯一施工蓝本

> 这份是**终局**：页面怎么排、组件怎么切、每个按钮归谁、什么时候该停。
> 与 `docs/23`（数据与判定）、`docs/24`（信息层级与按钮总账）是**一体**：
> **23 定数据 / 24 定层级 / 25 定界面落地**。冲突时以 23 > 24 > 25 为准。
>
> 用户要求（2026-10-24）："我只要最终的一个成品方案，然后你去做。"

---

## 一、产品一句话

> **零基础的人打开任务，5 秒内知道"我现在真能做什么"，说一句话它就去做，做完给证据。**
> 不自动动手、不烧冤枉 token、不用看懂技术细节也能判断进度。

三条不可让：

1. **只回答一个问题**：每个屏只答一个问题（会话=有新东西吗/该说什么；战况=我能做什么）。
2. **能做的必须能证明**：任何"能做到"都要挂证据号；没证据的格子显示"还没试"。
3. **花钱要看得见**：`✦`=调模型（有缓存），`⟳`=免费重排，不静默产生费用。

## 二、页面总图（从任务列表到证据，一条线）

```
任务列表
  └─ 任务详情 ──┬─ 会话（默认）   有新东西吗 / 我该说什么 / 下指令
                ├─ 战况           我在哪 / 我有什么 / 能做什么 / 能不能做
                ├─ 发现           漏洞与证据（技术层，给需要时看）
                └─ 报告           现在的结论能不能交付
                （更多 ▾：探索链路 / 播报板 / 复测 / 测试资产 / 覆盖图 / 拦截审批 / 任务情报）
```

**Tab 收敛（11 → 4 + 更多 ▾）**：零基础只需要四个；其余是过程视图，折进「更多」。

## 四、会话页（任务详情默认页）

三栏，从左到右是"选谁 → 说什么 → 结果/把关"：

```
┌ 会话列表 ─────┬ 对话流 ────────────────────────┬ 右栏(互斥) ─────────┐
│ 主 Agent       │ [它] …                          │ 战果 5 (+2)  ←─┐   │
│ 规划者         │ [你] 帮我把它数据库…            │ ───────────────│──  │
│ Worker #3      │ [它] 拿到了，证据 #298          │ 每行白话        │   │
│ 系统           │                                 │ 点开看证据      │   │
│                ├─────────────────────────────────┤                │   │
│                │ 它下一步想做：…  [复制一句]     │ 或 审查官 卡片  │   │
│                │ 这个站现在能说 ⟳  [短语…]       │ （P3，见 §七）  │   │
│                │ [输入框                  ][发送] │                │   │
└────────────────┴─────────────────────────────────┴────────────────┘
```
组件：`SessionList` / `Transcript` / `StatusLine`（下一步想做 + 复制）/ `TaskPhrases`（短语+⟳）/ `Composer` / `LootPanel`|`ReviewPanel`（互斥）。

规则：会话页**不放**战况卡/链/AI 分析按钮；授权=在输入框说话。

## 五、战况页（一屏一问，主视线只有一张卡）

见 `docs/24` §二的线框图。要点：

| 行 | 内容 | 上限 |
|---|---|---|
| ① 我在哪 | `E2 应用控制` + E0–E5 进度点 + `已确认 6 个洞` | 1 行 |
| ② 我有什么 | 后台会话 / 数据样本 / 命令执行 胶囊 | 3 个 + `+N` |
| ③ 现在能做到 | 每条：白话 + 证据号 + `[就做这个]` | **3 条** + `还有 N 件` |
| ④ 差一步 | `3 个洞差一步 → 缺：管理员会话` | 1 行 |
| ⑤ 换不到 | `2 个洞目前换不到后果` | 1 行 |
| 底 | 固定说明 + `✦ 分析`（唯一 AI 按钮） | 1 行 |

折叠区（默认收起，标题带数量）：`N 个洞·每个能换到什么` / `N 件后台能做的事` / `N 条利用链` / `N 个越界动作` / `任务管理`（描述·目标·约束·token）。

组件：`BattleCard`（壳）→ `LevelBar` / `HasChips` / `DoableList` / `GapLine` / `NoGainLine` / `Footer` / `FoldSection`。

## 七、审查官（P3）— 卡片形态

```
审查官   [开/关]
─────────────────────────────────────
结论：链卡在"已授权但没收益" 12 分钟（low/medium/high）
动作（每条必须带判据，否则不落库）：
 ① [继续] 换手法：把注入从报错型改成盲注时间验证；成功=拿到一行数据
    [采纳] [忽略]
 ② [改道] 先打后台默认口令；成功=进后台并截图
 ③ [问人] 需要你提供测试账号；需要=1 个普通账号
─────────────────────────────────────
依据：#298 #316（点击跳证据）
```
纪律：动作写进 `review_runs.actions`；`[采纳]` 复用 `review_apply` 通道；
**必须有 expectation（做完怎么算成功）**，没有就不落库；同一动作 30 分钟内不重复提。

## 八、状态机（一个任务从生到死）

```
新建 ─→ 探测(recon) ─→ 攻击面(surface) ─→ 利用(exploit) ─→ 数据(data) ─→ 报告(full)
            │                │                 │                │
            └── 闸门1: recon 未出结论禁利用类命令（已有）
                闸门2: 同阶段 30 分钟无新证据 → 必须三选一(继续/换路线/收工)
                       连续两次 → 自动出当前结论报告并停（待做）
                闸门3: 模板硬超时（已有）
终态: 已出报告(done) / 失败(failed) / 超时(timeout) — 都可在会话里继续对话与复测
```

## 九、按钮总账（唯一，新增必须先登记）

见 `docs/24` §八。口诀：**`✦`=看（花钱有缓存）｜`⟳`=重排（免费）｜`就做这个`=填入不发｜输入框=真干活**。

## 十、施工顺序（7 步，按地基→上层，禁止插队）

| # | 做什么 | 判据 |
|---|---|---|
| 1 | 三段式 standing（`got/one_step/no_gain`，与 loot 映射同源） | `/brief` 每条 `can[]` 有 standing；同输入重算结果一致 |
| 2 | 战况页按 §五 重排 + Tab 收敛到 4+更多 | 主视线一张卡、可点按钮 ≤3、5 秒能答"我现在能做什么" |
| 3 | 一盏灯（分析缓存 + `✦`/`⟳` 两开关 + 四状态矩阵） | 点 `✦` 三处一起变并显示"已缓存"；点 `⟳` 免费且提示未分析 |
| 4 | 模板 8→3 开局 + 三段落文本（禁止"应该有 X"）+ 放弃判据 | 新建任务只有 3 个开局；模板文本不含"应该有" |
| 5 | 闸门2（投入产出） | 造无进展任务，30 分钟后出现三选一；两次后自动收工 |
| 6 | 审查官 P3（§七） | `review_runs.actions` 非空且每条带 expectation |
| 7 | 通知（列表红点/标题/桌面） | 新战果时列表与标题出现数字 |

每步都必须：本机单测/mock → 换装 Kali（备份+install+restart）→ 真库判据 → 截图 → BACKLOG 记实测。

## 十一、不做什么（防止再变成"零散加功能"）

- 不让 AI 决定"能不能做到"（AI 只写措辞，判定归规则+证据）；
- 不建第二套能力/战果统计（`loot` 是唯一口径）；
- 不恢复"允许/拒绝"按钮（授权=对话）；
- 不给没证据的格子补数据；
- 不在主视线堆按钮（≤3）；
- 不新增 Tab（要加先删一个）。

## 十二、终局审查的判据（用户 2026-10-24 追加，必须执行）

> 原话（整理）："不要只当代码没问题就算好了。你要把自己当成一个**零基础的人**去用这个软件，
>  逐页面看：组件能不能左右分布、方块型排版是不是比压缩的一行行清楚、
>  页面上**写了功能不等于能用**——布局位置、交互方式、逻辑都很重要。
>  要像一个真实程序员 + 产品经理那样审：多角度、多维度，做得完善、优美、好上手。"

审查必须四维并行，任一维不通过都算缺陷：

| 维度 | 具体查什么 | 不合格的例子 |
|---|---|---|
| **视觉/排版** | 信息分组用**方块/左右分栏**而不是压成一行行；层级靠大小/留白区分，不靠堆字；一屏内主次分明 | 7 件动作全挤成细行、标题与内容同字号、处处等宽 |
| **交互** | 每个可点元素有明确反馈；危险/花钱操作可见成本；空态/加载/失败都有话说；不用教就会点 | 点了没反应；AI 按钮不标是否花钱；失败只显示英文栈 |
| **逻辑** | 判定自洽（等级/已拿到/能做到三者不矛盾）、不跳步、不拿预设冒充结论 | E0 却高亮"看后台密码"（已修） |
| **产品** | 是否符合"5 秒说出现在能做什么"；多余功能是否该删；新人第一次用能不能走通 | 11 个 Tab；同一问题 3 个按钮 |

审查报告 `docs/26-终局审查报告.md` 每条必须写：**页面 / 现象 / 四维归类 / 判据 / 结论 / 修法 / 截图**。
纯代码层面的问题也要记，但**排在"会不会让零基础用户做错判断"之后**。

## 十三、目标对齐（Goal Fit）— 零基础用户真正的入口（2026-10-24）

用户原话："他现在有 10 个漏洞，我们的目标就是拖库……他看不懂啊，不知道这些漏洞能不能达到这个需求。"
这就是原版工作台最大的断层：**漏洞列表 ≠ 我的目标能不能达到**。

**设计（调研过的两条业界原则）**
1. **验证必须确定性**：Basilisk 的做法是"从不问模型某件事成没成，只认证据"。这里同样只用
   `impact.Stats`（凭据库/台账/证据词）判能力，AI 不参与。
2. **链式思维（Chain Thinking）**：每个洞只问一句"它让我拿到了什么下一个位置"。
   所以目标对齐的答案结构 = **需要哪几个能力 + 现在有哪几个 + 缺哪个 + 下一步一句话**。

**目标清单（8 个，人话）**：拖库 / 进后台 / 先看几条真实数据 / 改钱 / 开管理员号 / 改首页 / 控制服务器 / 留后门。
每个目标带：`需要的能力（战果行）+ 最低等级 + 风险 + 为什么需要`。

**接口**：`GET /api/tasks/{id}/fit` → `{guess, fits:[{key,label,status:yes|one_step|no,have,missing,why,risk,steps,say_it}]}`；
`/brief` 也内联了 `goal_fits / goal_guess / blockers`。

**界面**：战况卡「我在哪」下面一行 —— `我的目标是 [拖库 ▾] [现在就能做到/差一步/现在还做不到]`，
差一步时直接写 `还缺：数据库查询 · <下一步一句话>` + `[照这句说]`（只填入不发送）。

**真机验证（Kali 0.11.40）**
```
task 14（已有后台会话 + 数据样本）  data_dump=yes  admin_access=yes  sample=yes
task 18（E0，刚起）               data_dump=no（缺 数据库查询/数据拉取）  admin_access=no（缺 管理员/后台登录）
```
真机踩到并修掉的坑：最初用「战果行 done」判满足 —— 而 done 依赖"漏洞文字里出现关键词"，
#14 明明有后台会话和数据样本，却因为文字没匹配上被判成"做不到"。改成**能力优先**后与等级同源。
