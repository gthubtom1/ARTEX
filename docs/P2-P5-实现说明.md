## 二、自动闭环长什么样

```
planner 派意图
  → （可选）rank_intents 去重排序：同锚点同方向合并，负空间/未测资产/阶段加权
worker 执行
  → 打下东西：
      cred_add（加密入库）→ cred_reuse_plan（能试哪些服务）
      owned_register（台账）→ session_register（跨 worker 池）
      record_capability（三门校验 → 能力卡）
      privesc_plan / lateral_plan / route_plan（下一步怎么打）
每轮规划结束（server.progressHook）
  → stall.Detect 算信号 → adviser.Diagnose 出 hint
  → hint 与最近 50 条去重后写进图 → 唤醒 planner（真正换层）
  → 持有台账到期 → 写一条"该复查 N 台"的 hint（附只读确认命令）
  → 从 finding 自动派生能力卡（幂等，只补新 item）
```

**没有引入任何权限门/负向文案**：所有模块只做"加权 / 合并 / 建议 / 记账"，不产生拒绝路径。

## 三、agent 新增工具（18 个）

规划者（`P2PlannerTools`）：`rank_intents`、`diagnose_progress`、`list_capabilities`、
`verify_claim`、`cred_list`、`session_list`、`owned_list`、`owned_due`、`owned_export`。

执行者（`P2WorkerTools`）：以上读工具 + `record_capability`、`cred_add`、`cred_reuse_plan`、
`cred_verify`、`session_register`、`session_lease`、`session_release`、`owned_register`、
`owned_check`、`owned_status`、`owned_cleanup`、`privesc_plan`、`lateral_plan`、`route_plan`。

两者都拿到适配器工具：`nmap_scan`、`httpx_probe`、`nuclei_scan`（参数白名单校验，禁 shell 注入；
二进制缺失时返回"安装或等价降级"的可行动提示，而不是 command not found）。

## 四、只读面板 API（P6 前端直接用）

| 方法 | 路径 | 返回 |
|---|---|---|
| GET | `/api/capabilities?task_id=<id>` | 能力卡 + 13 组覆盖度 + 白话菜单 |
| GET | `/api/owned?status=` | 持有台账 + 各状态计数 |
| GET | `/api/owned/export` | 台账 JSON 下载（报告用） |
| GET | `/api/progress?task_id=<id>` | 停顿检测报告 + 顾问诊断 |
| GET | `/api/p2/audit?task_id=&limit=` | audit_log 最近 N 条（注意与既有 `/api/audit` 区分） |
| GET | `/api/report?task=<id>` | 原 Markdown 报告 + 能力菜单 + 覆盖度 + 台账（无需前端即可交报告） |

## 五、配置

`.env.example` 新增 `ARTEX_CRED_KEY`：

- 32 字节 hex（`openssl rand -hex 32`）→ AES-256-GCM 主密钥；
- 任意字符串 → SHA-256 派生；
- **留空** → 每次启动生成一次性密钥（旧密文不可解；明文永不落库是底线）。

复查周期沿用 settings：`asset.recheck_hours`（默认 24）、`asset.stale_days`（默认 7）。

## 七、已知口径

- 能力清单实际解析出 **91 项**（方案文档写 82，`kb/capabilities/taxonomy.md` 表格是 91 项；以表格为准）。
- `capabilities` 表唯一键是 `(task_id, grp, item)`：同一项不同入口会**合并**（surface 用 ` | ` 拼接），
  与 `capability.Derive` 的 (item, surface) 去重互补。
- `DiagnoseProgress` 的"轮数"用每条意图近似一轮（现有 schema 没有 per-round 计数），
  趋势判断足够；后续可在 activity 的 round marker 上做精确聚合。
