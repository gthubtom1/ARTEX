# 复盘官 · 最终方案（整合版）

> 把 `docs/13`（闭环与防抖）、上一轮"像老手"的缺口（KB / 提新方向 / 死路台账）、以及"无人值守"的交互（ack 窗口）合成一份。
> 用户确认后按 §7 顺序落地。

---

## 1. 它到底是个什么角色（一句话）

**一个 20 年经验的渗透负责人，被请来"隔一段时间看一眼这条路还对不对"——他不亲自打，但他说的话团队要听、也能反驳。**

三个必须同时成立的属性：

| 属性 | 含义 | 靠什么保证 |
|---|---|---|
| **不同视角** | 只看结构化事实，不看主 Agent 的对话与思考 | 快照只有数字/状态/证据 id（`internal/review`） |
| **有经验** | 知道"这个技术栈这条通常走不通" | **KB 检索**（`skills/` + `kb/`）+ **死路台账**（`assumptions`） |
| **能纠正** | 除了"别试了"，还能说"应该去打 B" | 新增动作 `propose_intent`（只提议，不自己派） |

---

## 2. 它怎么判断（四层，越往下越花钱）

| 层 | 判什么 | 谁做 | 成本 |
|---|---|---|---|
| L1 机械 | 我方故障≠死路、重复撞墙、预算烧完、连续无产出 | 规则（已有 `stall` + `errev`） | 0 |
| L2 证据 | 这条结论有没有真实 id 撑着；建议是不是已经过期 | 规则（自检五问） | 0 |
| L3 经验 | 这个栈/这类洞，常规下一步是什么；哪些路历史上就是死的 | **KB 检索（最多 2 次）+ 死路台账** | 2 次检索 |
| L4 表达 | 把上面三层说成 3–6 句人话 + 一条可执行的建议 | 模型（`agentKey=adviser`） | ~1k |

**分工原则**：状态（✓/试过未成/死路）永远是规则算，模型只写"解释与建议"。**模型不改状态、不碰证据。**

---

## 3. 动作白名单（现在 3 个，加到 4 个）

| 动作 | 谁执行 | 条件 |
|---|---|---|
| `kill_intent` | 低风险档可自动 | 目标侧明确拒绝 ≥3 次 |
| `retry_intent` | 低风险档可自动 | `self_error` / `env_error`（没真正试过） |
| `set_next_stage` | **必须人点** | 换阶段 |
| **`propose_intent`（新）** | **只提议**：写成一条建议给主 Agent/人，**它自己不派活** | 必须有 KB 或证据依据 |

`propose_intent` 的产物形如：

```
建议新方向：读 IIS applicationHost.config 找可写目录
依据：① finding#31（能读任意文件）② KB：IIS 8.5 写文件常规落点（命中 2 条）
预期：找到可写目录 → 落 ASP 后门 → 回显 whoami
[ 采纳并下发 ]  [ 只复制指令 ]  [ 不要 ]
```

## 4. 无人值守：ack 窗口（你不在，它才自己动）

```
它给出建议
   ├─ 面板亮起 + 按钮条出现 + 红点
   ├─ 倒计时 90 秒（可设 30/90/300）
   │     ├─ 你点了「我在，我自己处理」 → 取消投递，只留红点（本次不再自动）
   │     ├─ 你点了「采纳 / 执行」        → 立即执行（或下发）
   │     └─ 90 秒内你什么都没点          → 按档位自动处理
   └─ 自动处理时：低风险动作自己执行并留回执；需人确认的（换阶段/收工）→
      只以"建议"形式投给主 Agent（带"请核对后再决定"），不直接改任务
```

**这条就是你要的"我在就不自动、我不在就自动"。** 注意：自动也只做"减浪费"，不会替你收工。

## 5. 右栏 UI 设计（原则：一次只说一件事）

**问题**：之前把所有东西堆一屏，你看不懂。改为**三段定高 + 一条主结论 + 折叠细节**。

```
┌─ 复盘官 · 常驻●  ─────────────── 档位:低风险自动  [⋯]  ✕ ─┐
│  ● 它 12 分钟前看过 · 还有 2 条旧结论未读                  │  ← 段①状态条（一行，永远在这）
├──────────────────────────────────────────────────────────┤
│  ⚠ 建议放弃「入口3：盲注」                                 │  ← 段②主结论（一次只显示 1 条）
│  理由：入口1 已带内回显，快 10 倍；这条 3 轮无新事实         │
│  依据：intent#12 · finding#31 · KB「MSSQL 盲注优先级」      │  ← 依据可点开
│                                                          │
│  自动处理倒计时 90s  ●●●○○○                                │
│  [ 我在，我自己处理 ]  [ 采纳并执行 ]  [ 不要 ]              │  ← 三个按钮，最大的是"我在"
├──────────────────────────────────────────────────────────┤
│  ▸ 另外 2 条（已折叠：重开#70 / 放弃#43）                    │  ← 段③其余结论折叠
│  ▸ 它的笔记 v4（看它怎么积累判断）                           │
│  ▸ 问它一个问题…                                            │  ← 折叠的只读问答
└──────────────────────────────────────────────────────────┘
```

四条硬规则：

1. **一次只展开一条**（最新、最该处理的那条）；其余折叠成计数，点开才看。
2. **「我在，我自己处理」是最大按钮**——因为它是"阻止自动"的唯一钥匙；按下去后这次自动取消，并回执"好，我不动"。
3. **依据可点开**：`intent#12` 展开是那条方向的原话；`KB「…」` 展开是命中的知识片段原文。**它说错时你能立刻看出错在哪一层。**
4. **问答区默认折叠**，只读、不执行；答案是"它基于快照+笔记+这次检索"的解释。

## 6. 状态机（一条建议的一生）

```
drafted → (自检五问) → dropped
   ↓ 通过
shown(红点) ──你点「我在」──> held（本次不自动，留红点）
   ├──你点「采纳/执行」──> applied ──3 轮后──> effective | neutral
   ├──你点「不要」──────> rejected ──同类型降权（已实现）
   └──90s 无响应────────> escalated(按档位自动) ──> applied | suggested_to_main
```

落库：`review_runs.ack_status`（`held|accepted|rejected|escalated|expired`）+ `ack_at`。

| # | 做什么 | 文件 | 验收 |
