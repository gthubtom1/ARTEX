# 23 · 战况与后果 · 统一模型（先有模型，再加功能）

> 这份文件回答一个问题：**页面到底该怎么设计、AI 按钮到底该干什么。**
> 起因（2026-10-24 用户原话）：
>
> "有的网站虽然漏洞非常多，有高危、中危、超危，但它并没有说能让我们去处理一些事情……
>  你说它是误报吧，它也不属于误报，它只是漏洞，并没有造成'我现在能做到的现实后果'。"
>
> 结论先说：**漏洞存在 ≠ 能换到现实后果。** 之前的战况卡把这两件事混在一格里，
> 于是"AI 说能换到什么"听起来像"我现在就能干"，这是设计缺陷，不是文案问题。

---

## 一、三层模型（唯一事实源，不许再混）

| 层 | 回答的问题 | 谁能判定 | 存在哪 |
|---|---|---|---|
| **L1 漏洞** | 这个站有什么技术缺陷？ | 采集 + 证据（不可争辩的事实） | `exploration_nodes(kind=finding)` + evidence |
| **L2 能力** | 我**现在**拿到了什么权限/数据？ | **纯规则**（证据 + 台账） | 战果行 `loot`（admin/db/data/rce/filewrite/cred/lateral）+ 等级 E0–E5 |
| **L3 后果** | 凭这些，我能在业务上做成哪件事？ | 骨架=规则（前置可判定）；**措辞=AI（只写文案）** | `actionDefs`（7 骨架）+ AI 站点特有（待确认） |

三条铁律：

1. **L1 不能跳到 L3。** 有 SQL 注入（L1）不等于能读库（L2），更不等于能导订单（L3）。
   中间必须过 L2 的证据关：`loot` 那一行 `status=done` 才算。
2. **AI 只写 L3 的措辞，绝不定 L1/L2 的结论。** AI 说"能加钱"不算数，规则说能才算。
3. **每一格都必须能回答"凭什么"。** 答不出证据 id 的格子，宁可显示"换不到"，也不许显示"能"。

## 二、L1→L2→L3 的判定：三段式（standing）

给"每个漏洞能换到什么"加一个**确定性**状态（不是 AI 给的）：

| standing | 含义 | 判据（规则） | 界面 |
|---|---|---|---|
| `got` | **已经成立**：这个洞对应的能力行已拿到，有证据 | 该 finding 的 vulnclass ⇢ 映射到 loot 行 key，且该行 `done` | 绿：`已成立 · 证据 #N`；L3 里对应动作高亮「现在能做到」 |
| `one_step` | **差一步**：洞确认了，但还没换来能力 | 洞确认、映射行 `run/tried/blank` | 黄：`还差一步：<缺的那个能力>` |
| `no_gain` | **换不到东西**：这个洞目前不产生任何现实后果 | 洞确认，但映射不到任何 loot 行，或映射行被判 `na` | 灰：`这条现在换不到东西（不是误报，只是没到能用的程度）` |

**这就是用户那个问题的答案**：漏洞很多但全是 `one_step`/`no_gain` 时，战况卡会明说
"你有一堆洞，但一个现实后果都还没有" —— 而不是拿漏洞数量冒充战果。

映射表（与 `server/loot.go` 的 `lootRows` 同源，不许另写一份）：

```
SQL/注入        → db, data
IDOR/越权/未授权 → data
登录绕过/JWT/默认口令 → admin
XSS             → admin（接管会话后才算）
上传/写文件      → filewrite
RCE/命令执行     → rce
文件读取/穿越    → fileread
凭据/哈希        → cred
```

## 三、AI 按钮：只有一个语义

> **"把技术事实翻译成人话，并标注可信度。"** 绝不改变任何判定、绝不触发任何动作。

| 按钮 | 输入 | 输出 | 缓存键 | 失败回落 | 角标 |
|---|---|---|---|---|---|
| ✦ 用 AI 说清楚（战况卡·每个洞） | 该 finding 的标题/摘要/证据 | 一句话「它**可能**换来什么」+ **不改 standing** | `sha256(标题|摘要|证据)` | 规则模板 `abilityText` | `AI·待确认` |
| ✦ 补这个站特有的后果（战况卡·后果清单） | 任务目标 + 全部 finding 摘要 | 3–5 条**站点特有**后果 | `sha256(全部 finding 摘要)` | 不显示（宁缺勿造） | `AI·待确认`，恒 `doable=false` |
| ✦ 补这个站特有的项（战果面板） | 战果行 + finding 摘要 | 1–3 条能力行（status=blank） | 同上 | 空 | `AI 推断·待确认` |
| ⟳ 重算（动态短语） | 当前战果行 | 3–5 句"现在该说的话" | 无（纯规则，不花钱） | 保留上一次 | 无 |

四条约束：

- AI 输出**一律不能**变成"现在能做到"（`doable` 只由规则算）；
- AI 输出**必须**带 `·待确认` 字样，且悬停能看"依据哪几条 finding"；
- 点一次三个地方一起刷新（漏洞解释 / 站点特有后果 / 动态短语），不允许出现"点了一个别的没动"；
- 每次 AI 调用都必须有缓存键，重复点不重复花 token。

## 四、页面职责（两屏 + 一个闭环）

| 屏 | 只回答一件事 | 放什么 | 不放什么 |
|---|---|---|---|
| **会话** | 有新东西吗？我该说什么？ | 会话流 / 新战果红点 / 动态短语 / 工单状态（"已登记·等结果"） | 不放"允许/拒绝"按钮（授权=说一句话） |
| **战况** | 我在哪、我有什么、能换到什么、能做什么 | 等级 E0–E5 / 已拿到 / 每个洞三段式 / 后果清单（高亮能做的）/ 利用链 / 越界动作（只读） | 不做第二份同义卡（利用链/值不值得打都收在这一张） |
| **闭环** | 我说的话有没有被执行、有没有证据 | 人说一句 → 工单(requested) → 证据出现(自动收口 done) → 战况更新 | 不许自动执行 |

## 五、"别烧 token"：三道闸门（确定性，不靠模型自述）

1. **阶段门**（已有）：recon 阶段没出结论，禁利用类命令。
2. **投入产出闸门**（待做）：同阶段连续 30 分钟无新证据（证据 id 不增长）→
   规划者必须三选一「继续 / 换路线 / 收工」并写理由；**连续两次** → 自动降级为
   "出当前结论报告并停"。
3. **硬超时**（已有）：模板自带 20/30/40/60 分钟。

反向保护：闸门只在**证据 id 不增长**时触发，有推进就不会误停；第一次只要求说清楚，第二次才停。

## 六、模板：3 个开局 + 三段式文本

模板**只决定开局**（goal 引导语 + stage + 超时），运行中由规划者与对话推进。

保留 3 个开局：`判断值不值得打(20m)` / `打穿并取证(40m)` / `全面评估出报告(60m)`。
其余 5 个转成"常用语/动态短语"（它们是中途话术，不是开局）。

模板文本一律写成三段式，**禁止写"这个站应该有 X"**：

```
① 这一轮干什么（一句话）
② 怎么判断"有"：看到什么响应特征算有；没有就把这一项记为"不适用"，别硬凑
③ 什么时候必须停：给出硬判据（证据不再增长 / 连续两次无进展 / 超时）
```

续接不靠换模板：同一任务里对话即可；确实要开新任务时用**继承**（`task_relations`，
前任务发现作为只读上下文，见 `agent/tools.go relatedTaskOverviews`，上限 48K 字）。

## 七、施工顺序（按"地基 → 上层"，不再零散加）

| # | 做什么 | 为什么排这儿 | 判据 |
|---|---|---|---|
| 1 | **三段式 standing**（L1→L2 判定 + `can[]` 增加 `standing`/`gap`） | 所有页面都读它；不先定这个，后面都在猜 | `/brief` 的每条 `can[]` 有 `standing∈{got,one_step,no_gain}`；同一批 finding 重算结果不变（确定性） |
| 2 | 战况卡按三段式重排（漏洞分三组 + 后果清单高亮 + "一堆洞但没有后果"提示） | 直接回答用户的原始问题 | 打开任务一眼看出"洞多但换不到" vs "已经能干活" |
| 3 | AI 只写文案（`AI·待确认` + 依据 + 缓存），一次点击刷新三处 | 把 AI 放回它该在的位置 | 点一次：解释/特有后果/短语都变；重复点不再花 token |
| 4 | 模板重写（3 开局 + 三段式 + 放弃判据） | 决定"要不要继续"，直接影响 token | 新建任务只有 3 个开局；模板文本里不出现"应该有" |
| 5 | 投入产出闸门（无新证据 → 三选一 → 两次自动收工） | 防跑十几个小时 | 造一个"无进展"任务，30 分钟后应出现三选一 |
| 6 | 审查官 P3（读同一份 Brief，下 kill/steer/ask，动作必须带判据） | 它是"有人替你把关"，必须建在 1–2 之上 | `review_runs.actions` 非空且每条带 expectation |
| 7 | 通知（任务列表红点 / 标题 / 桌面） | 最后做：数据源齐了才有意义 | 新战果出现时列表与标题有数字 |

## 八、明确不做（避免又回到"零散加功能"）

- 不让 AI 决定"能不能做到"（只写文案）；
- 不做第二套战果/能力统计（loot 行是唯一口径）；
- 不恢复"允许/拒绝"按钮（授权=对话）；
- 不给没证据的格子补数据（"还没试"就显示"还没试"）。
