## 一、复盘官（C-01）

**原始意图（用户原话）**：像一个真人站在另一个视角，自动复核当前渗透任务**有没有偏移、有没有卡在某个地方**；不是要人盯着它、也不是又一个聊天框。

**规格（`docs/09`）与实现对照**

| 项 | 规格 | 现状 | 缺口 |
|---|---|---|---|
| 身份 | 外部评估者，只读快照 + 自己的笔记 | ✅ 已实现（`internal/review`） | — |
| 结论形态 | 继续 / 转向 / 该收口 + 依据 + 可执行动作 | ✅ 已实现（模型出人话 + 规则出动作） | — |
| **触发：手动** | 菜单「现在看一次」 | ✅ | — |
| **触发：条件（默认开）** | 连续 3 轮无新 fact / 连续 2 次 self_error / 预算过半无新洞 / 某路失败 ≥5 次 | ❌ **完全没做** | planner 轮末的钩子 |
| **触发：定时（默认 10 分钟）** | 任务在跑时按间隔自动看 | ❌ **完全没做** | 服务端 ticker + 每任务上次时间 |
| **未读提示** | 有新结论时按钮闪/红点，人不在就按权限自动处理 | ❌ **没做** | 未读标记 + 前端轮询 |
| **权限三档** | 只看 / 低风险自动（默认）/ 全自动 | ❌ **没做** | settings + apply 时按档位 |
| 动作语义 | `kill_intent` / `retry_intent` / `set_next_stage` | ✅ 已实现 | — |
| **动作回执** | 自动执行的也要留"我做了什么、依据是什么" | ⚠ 部分（apply 有 feedback 行，但无自动路径） | 与自动档一起做 |
| 反驳 | 必须写「旧结论 + 被哪条证据推翻」 | ✅ 已实现（重跑一次并把反驳塞进提示） | — |
| 与旁路提问的区别 | 旁路=你问它答；复盘官=**它主动看、主动留结论、按权限自己处理** | ❌ **现在两者几乎一样** | 见上面三条触发/未读/权限 |

**结论**：设计是对的，**实现只做了「手动」这一条腿**，所以它退化成了一个聊天框。

**闭环与防抖**：详见 **`docs/13-复盘官-闭环与防抖.md`**（消息流向 / 主 Agent 核对协议 / 自检五问 / 8 条防抖规则 / 熔断 / 落库字段）。

| 新增子项（原设计里有、后来差点说丢的） | 现状 |
|---|---|
| 主 Agent 收到建议必须**核对现状**后回「接受/拒绝/已过期 + 依据」 | ❌ |
| 复盘官投递前**自检五问**（重复/过期/有依据/是它的事/说了有用） | ❌ |
| **只对变化说话**（dedupe_key，状态未变不发第二次） | ❌ |
| 被拒 2 次 → 同类建议降权（只留红点） | ❌ |
| 自动动作≥3 次且无改善 → 熔断转 observe | ❌ |

**补齐方案（按依赖顺序）**

1. `review_runs` 加 `seen_at`（人看过的时间）→ 前端按钮显示红点 / 数字。
2. `settings: review.tier`（observe｜lowrisk｜auto）+ `review.interval_min`（默认 10）。
3. 条件触发：在 planner 每轮结束（已有 `stall` 计算处）调用 `maybeAutoReview(taskID, reason)`；带冷却 5 分钟 + 每任务上限 10 次。
4. 定时触发：服务端 ticker（60s）扫活跃任务，距上次 `review_runs.created_at` 超过 interval 就跑。
5. 自动执行：lowrisk 档只自动做 `kill_intent`（target_blocked≥3）/`retry_intent`（self_error|env_error）；其余留红点等人。每次自动执行写 `review_feedback(action='applied', by='auto')` 并在面板显示"它自己做了什么"。
6. UI：按钮红点（未读）+ 面板顶部"它自动看过 N 次 / 自动处理 M 次"。

## 二、能做到什么（B-01）

**原始意图**：不用切页面就知道"这个站我现在能拿到什么"，而且是**实时**的；不是又一个攻击链路图。

| 项 | 规格 | 现状 | 缺口 |
|---|---|---|---|
| 位置 | 会话页右上，和「旁路提问」**同一个框**（`side-question-workspace` 的 `ResizablePanel 38%/280px/65%`） | ⚠ 曾错做成独立 tab + 自绘画布；已定改为复用同一槽位 | 删 tab + 挂进槽位 |
| 形态 | **通用能力清单表**（后台/数据库/数据/读文件/写文件/命令执行/凭据/哈希还原/横向…）+ 只显示与本站相关的行 | ⚠ 后端接口 `/api/tasks/{id}/loot` 已按此实现 | 前端表格面板 |
| 状态 | ✓已拿到 / 正在试 / 试过未成 / 还没试 / 不适用 | ⚠ 后端只有 done/tried/blank | 补 run/todo/na |
| 交互 | 点行看依据 + 下一步 + 「让它去试」「复制下一步」「标为不适用」 | ❌ 未做 | 行内动作 |
| 刷新 | 手动 ⟳ + 自动开关（默认开 10s） | ❌ 未做 | — |
| AI 补站内特有项 | 模板猜不到的能力由 AI 补，且必须有证据锚点，没证据的标"待确认" | ❌ 未做 | 复用 annotate 管道 |
| 实时与面板无关 | 数据由后端实时算，面板只是显示 | ✅ 后端如此 | — |

## 四、写这张表的规矩

1. **任何功能在表里必须有一行**；新增功能先加行，再写代码。
2. 一行里的「现状」只能是 ✅ / ⚠ / ❌ / ⏸，不许写"基本完成"。
3. 每轮结束更新这张表；**只改现状列，不改意图列**（意图改动必须用户明确同意）。
