## 一、复盘官（C-01）

**原始意图（用户原话）**：像一个真人站在另一个视角，自动复核当前渗透任务**有没有偏移、有没有卡在某个地方**；不是要人盯着它、也不是又一个聊天框。

**规格（`docs/09`）与实现对照**

| 项 | 规格 | 现状 | 缺口 |
|---|---|---|---|
| 身份 | 外部评估者，只读快照 + 自己的笔记 | ✅ 已实现（`internal/review`） | — |
| 结论形态 | 继续 / 转向 / 该收口 + 依据 + 可执行动作 | ✅ 已实现（模型出人话 + 规则出动作） | — |
| **触发：手动** | 菜单「现在看一次」 | ✅ | — |
| **触发：条件（默认开）** | 连续 3 轮无新 fact / 某路失败 ≥5 次 / 预算过半无洞 / 停顿信号≥2 | ✅ `progressHook` → `reviewCondHit` + `reviewCondKick`（2026-10-23） | — |
| **触发：定时（默认 10 分钟）** | 任务在跑时按间隔自动看 | ✅ `server/review_loop.go` `reviewTicker`（每分钟扫活跃任务） | — |
| **未读提示** | 有新结论时按钮闪/红点，人不在就按权限自动处理 | ✅ `review_runs.seen_at` + `GET review/state` 轮询 + 胶囊红点 | — |
| **权限三档** | 只看 / 低风险自动（默认）/ 全自动 | ✅ `review.tier` + 任务级覆盖 `PUT review/tier` + `internal/review.Decide` | — |
| 动作语义 | `kill_intent` / `retry_intent` / `set_next_stage` | ✅ 已实现 | — |
| **动作回执** | 自动执行的也要留"我做了什么、依据是什么" | ✅ 自动路径写 `review_feedback(by='auto')` + `auto_applied` + `ack_status` | — |
| 反驳 | 必须写「旧结论 + 被哪条证据推翻」 | ✅ 已实现（重跑一次并把反驳塞进提示） | — |
| 与旁路提问的区别 | 旁路=你问它答；复盘官=**它主动看、主动留结论、按权限自己处理** | ❌ **现在两者几乎一样** | 见上面三条触发/未读/权限 |

**结论（2026-10-23 更新）**：三条腿（手动/条件/定时）+ 未读 + 三档权限 + 防抖 + 熔断全部落地；不再是聊天框。

**闭环与防抖**：详见 **`docs/13-复盘官-闭环与防抖.md`**（消息流向 / 主 Agent 核对协议 / 自检五问 / 8 条防抖规则 / 熔断 / 落库字段）。

| 新增子项（原设计里有、后来差点说丢的） | 现状 |
|---|---|
| 主 Agent 收到建议必须**核对现状**后回「接受/拒绝/已过期 + 依据」 | ✅ mainagent 提示词硬协议段（`mainagent_prompt_review_protocol_v1` 一次性刷库） |
| 审查官投递前**自检五问**（重复/过期/有依据/是它的事/说了有用） | ✅ `internal/review.Decide`（含单测 gate_test.go） |
| **只对变化说话**（dedupe_key，状态未变不发第二次） | ✅ `review_runs.dedupe_key` + 最近 30 条比对 |
| 被拒 2 次 → 同类建议降权（只留红点） | ✅ `reason_class` + `ack_status='rejected'` 计数 |
| 自动动作≥3 次且无改善 → 熔断转 observe | ✅ `review_state.tripped_at` + 面板说明 + 手工改档解除 |

**补齐方案（2026-10-23 已全部落地，按依赖顺序）**

1. ✅ `db/migrations/0006_review_loop.sql`：`review_runs` 加 `dedupe_key/level/reason/reason_class/seen_at/ack_status/ack_reason/auto_applied`，新增 `review_state`（配额/冷却/熔断）。
2. ✅ 设置项 `review.cond`（默认开）、`review.tier`（默认 lowrisk）、`review.interval_min`（10）、`review.cooldown_min`（5），Settings 页有开关/档位/间隔。
3. ✅ 条件触发：`progressHook` 每轮结束 → `reviewCondHit`（4 条确定性条件）→ `reviewCondKick`（后台跑，冷却+配额）。
4. ✅ 定时触发：`reviewTicker`（60s）扫在跑任务，距上次 `review_runs.created_at` 超间隔就跑。
5. ✅ 自动执行：`internal/review.Decide` 只放行两类减浪费动作（self_error/env_error 重开、target_blocked≥3 标死），自动动作写 `review_feedback(by='auto')`，面板显示"它自己做了"。
6. ✅ UI：胶囊未读红点（`unseen`）、面板顶部「自动看过 N 次 · 自动处理 M 次」、档位切换、熔断提示。

## 二、能做到什么（B-01）

**原始意图**：不用切页面就知道"这个站我现在能拿到什么"，而且是**实时**的；不是又一个攻击链路图。

| 项 | 规格 | 现状 | 缺口 |
|---|---|---|---|
| 位置 | 会话页右上，和「旁路提问」**同一个框**（`side-question-workspace` 的 `ResizablePanel 38%/280px/65%`） | ⚠ 曾错做成独立 tab + 自绘画布；已定改为复用同一槽位 | 删 tab + 挂进槽位 |

## 四、写这张表的规矩
