# 环境适配与工具自愈（Kali 全局发现版）

> 你的环境：**Kali 虚拟机**，工具不一定在 PATH 里（`~/tools`、`/opt`、`/snap`、pipx/go/bin、桌面启动器、甚至被改名）。
> 所以"识别工具"必须是**全局发现**，不能只 `which`。
> 三个要求：**扫得全 → 缺了能自动装 → 装了能用（有适配器）**。

---

## §1 四段式架构（缺一不可）

```
① 全局发现（Discovery）  全盘扫 + 指纹 + 缓存，后台跑，不阻塞任务
② 安装/降级（Provision）  apt / pipx / go / GitHub Release / docker；失败走 fallback
③ 适配器（Adapter）       每个工具一个 typed wrapper，输出结构化 JSON（不是裸文本）
④ 资源治理（Governor）    并发/超时/限速/输出上限，避免把 VM 打崩
```

> **第 ③ 段是最容易被忽略的**：工具在不在是一回事，**agent 能不能可靠解析它的输出**是另一回事。
> 裸 Bash 跑 `nmap` 回来一屏文字，模型要么读错、要么烧掉几千 token。适配器把它变成 `{host,port,service,version}`。

## §2 ① 全局发现：怎么"扫得全"

### 2.1 扫描顺序（从便宜到昂贵，命中即记录，最后全盘兜底）

```bash
# L1 PATH 与 shell 层（毫秒级）
command -v $t; type -a $t; alias | grep -w $t

# L2 常见安装目录（秒级）
for d in /usr/bin /usr/local/bin /usr/sbin /sbin /snap/bin \
         /opt /opt/*/bin ~/.local/bin ~/bin ~/tools ~/go/bin ~/.cargo/bin \
         /usr/share/*/bin /root/tools; do ls -1 "$d" 2>/dev/null; done

# L3 包管理器清单（秒级，能拿到"装了但没在 PATH"的）
dpkg -l | awk '{print $2}' | sed 's/:.*//'
pipx list --short
pip list --format=freeze | cut -d= -f1
go env GOPATH; ls "$(go env GOPATH)/bin" 2>/dev/null
gem list --no-versions; npm ls -g --depth=0 --parseable 2>/dev/null
snap list 2>/dev/null | awk 'NR>1{print $1}'
docker images --format '{{.Repository}}:{{.Tag}}' 2>/dev/null

# L4 桌面启动器（Kali 的 GUI 工具常只在这里）
ls /usr/share/applications/*.desktop 2>/dev/null | xargs grep -h '^Exec=' 2>/dev/null

# L5 全盘兜底（昂贵，但必须做；用 plocate 优先）
command -v plocate >/dev/null && plocate -r '/bin/|/tools/' 
# 没有 plocate 就 find（-xdev 不跨挂载点，排除虚拟文件系统）
find / -xdev \( -path /proc -o -path /sys -o -path /dev -o -path /run -o -path '*/node_modules' \) -prune -o \
     -type f -perm -u+x -size +100k -print 2>/dev/null
```

**全盘扫描注意**：
- 必须 `-xdev`（否则会扫挂载的网络盘/NAS，卡死）
- 排除 `/proc /sys /dev /run`、`node_modules`、`*.so`、`.cache`
- `-size +100k`（过滤掉一堆 shell 脚本噪声；**但工具可能小于 100k**，所以再补一轮 `-size -100k -name '*'` 对已知名字精确匹配）
- 用 `timeout 180` 包住，**扫不完也算部分结果**（先出 L1–L4，全盘在后台继续）
- 结果落缓存，**不要每轮任务都扫**

### 2.2 认不出来的二进制怎么办（改名/自编译）

```bash
# 1) 哈希指纹：与内置 known_hashes.json（工具名→sha256）比对
sha256sum "$f"

# 2) 魔数 + 特征串：即使改名也能认出
file "$f"                                        # ELF/Python script/Go binary
strings -n 8 "$f" | grep -m1 -iE 'nmap|nuclei|sqlmap|ffuf|gobuster|masscan|hydra'
# 3) 版本探针（只对"已知工具"用，避免盲目 -h 把工具探崩）
"$f" --version 2>&1 | head -3
```

> 纪律：**不要对所有未知二进制跑 `-h`/无参**——很多工具会弹窗卡死或触发自毁（商业壳/驱动类）。只对 known 列表做版本探针。

### 2.3 缓存（关键：一次扫描，多次复用）

`tools_cache`（SQLite 或 PG）：

```sql
CREATE TABLE tools_cache (
  id bigint PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  name text,              -- 规范化名（nmap / nuclei / ffuf）
  path text,              -- 绝对路径（可能有多个）
  kind text,              -- binary | python | go | docker | snap | script
  version text,
  sha256 text,
  caps text[],            -- port_scan|tpl_scan|sqli|fuzz|pivot|oast...
  healthy bool,           -- 自检是否通过
  checked_at timestamptz,
  scan_source text,       -- path|dpkg|pipx|go|full|desktop|docker
  UNIQUE(name, path)
);
```

- **失效判定**：记录每个目录的 `mtime`；目录变了才重扫对应目录。
- **全盘扫描频率**：开机一次 + 每 7 天一次 + 手动"重扫"按钮。
- **任务启动只读缓存**（毫秒级），不阻塞。

### 2.4 不只是二进制：还要扫"素材"

工具能用，靠的是数据和模板。这些也必须入缓存：

```bash
/usr/share/seclists            # 字典
/usr/share/nuclei-templates    # 模板（+ 版本：nuclei -tv）
/usr/share/metasploit-framework/modules
/usr/share/wordlists           # Kali 自带（rockyou.gz 常在这里）
/opt/*/  (Burp 插件/自定义工具)
~/.gf, ~/.config/...           # 工具配置
```

**没有字典的 ffuf、没有模板的 nuclei = 装了个空壳**，必须一起检测。

## §3 ② 安装与降级

### 3.1 安装源优先级（只允许这三类）

| 优先级 | 方式 | 例 |
|---|---|---|
| 1 | 发行版官方源 | `apt install -y nmap` |
| 2 | 语言官方源 | `pipx install sqlmap` / `go install github.com/projectdiscovery/nuclei/v3/cmd/nuclei@latest` |
| 3 | 项目官方 Release | `gh release download -R jpillora/chisel -p 'chisel_*linux_amd64.gz'` → sha256 校验 → 解压到 `~/tools` |

**禁止**：`curl | bash`、非官方镜像、来源不明的二进制。

### 3.2 幂等 + profile（学 Kali 社区脚本的做法）

```bash
# profile: min | web | redteam | ctf | cloud
install_profile() {
  for t in "${TOOLS[@]}"; do
    command -v "$t" >/dev/null && { echo "[skip] $t"; continue; }
    apt-get install -y "$t" || pipx install "$t" || go install "$PKG[$t]"
  done
}
```

- **幂等**：已装即跳过（脚本可反复跑）
- **profile**：按任务类型只装需要的，避免一次装 3GB
- **日志**：每次安装写 `tool_events`（tool/action/result/duration）

### 3.3 降级（装不上时）

| 缺什么 | 降级方案 |
|---|---|
| sqlmap | 用 curl + 布尔/时间盲注脚本（`skills/` 内置） |
| nuclei | 用 curl 手工验 CVE 特征 + 本地 kb 的 PoC |
| ffuf | 用 `xargs -P` + curl 并发（限速） |
| chisel | `ssh -D` / `ligolo-ng` / `socat` |
| nmap | `masscan` + `nc` 探端口 |

**规则**：降级要在 fact 里记 `degraded: <tool> → <fallback>`，让报告能说明"哪些结论是在降级条件下得出的"。

### 3.4 竞赛 toolbelt（profile = `ctf`，来自 `docs/专家级自主渗透能力建设.md` §5）

> 2026-10-23 收编（源文件已删除）。ARTEX 镜像本身只有 `nmap/curl/dig/nc/telnet/whois/jq/rg/node/playwright`，
> 竞赛要用的工具面靠这一层补；走 §3.1 的安装源优先级，`profile=ctf` 时才装。

```dockerfile
# 建议单独一层 toolbelt（或用 kali-rolling 基础镜像）
apt-get install -y --no-install-recommends \
  ffuf gobuster feroxbuster nuclei sqlmap hydra john \
  chisel proxychains4 sshpass \
  smbclient ldap-utils nbtscan \
  postgresql-client default-mysql-client redis-tools \
  python3-pip && pip install impacket netexec
# 可选（体积大，按需）：metasploit-framework、ligolo-ng、bloodhound.py
```

**代理与隧道是横移的命门**：`chisel` + `proxychains4` + `ligolo-ng` 三件套必须预装，
并且 `proxychains4.conf` 要能被 `routes` 表**动态改写**（每任务一份，与 M20 跳板选路同源）。
没这三件套，`skills/kill-chain` 的 §四横移只能在纸面上跑。

## §4 ③ 适配器层（把 CLI 变成结构化工具）★新增关键模块

每个常用工具一个 Go 适配器，**agent 不再拼 shell 字符串**：

```go
type Adapter interface {
    Name() string
    Caps() []string
    HealthCheck(ctx) error
    // 输入强类型参数，输出结构化结果
    Run(ctx context.Context, in any) (any, error)
}
```

| 工具 | 输入 | 输出（结构化） |
|---|---|---|
| nmap | host, ports, flags | `[]Port{host,port,proto,service,version,cpe}`（解析 `-oX`） |
| httpx | urls | `[]Web{url,status,title,tech,cdn,tls}`（解析 `-json`） |
| nuclei | targets, severity, tags | `[]Finding{template,severity,matched_at,curl_command}`（`-jsonl`） |
| ffuf | url, wordlist, rate | `[]Hit{path,status,size,words}`（`-of json`） |
| sqlmap | url, param, level/risk | `{injectable,dbs,tables,technique}`（`--batch --output-dir`） |
| hydra | target, service, userlist, passlist | `[]Cred{user,pass,service}` |
| netexec | targets, proto, action | `[]Result{host,ok,detail}`（`--json`） |

**收益**（很实在）：
- 消除"命令拼错"这一整类失败（hxbai 复盘中"命令幻觉"是三大失败模式之一）
- 输出变小变准，**token 降 50%+**
- 可以统一加：超时、重试、限速、代理、审计

**降级路径也走适配器**：`sqlmap` 适配器缺工具时自动切到内置的纯 Python 注入器，接口不变。

## §5 ④ 资源治理（防止把 Kali VM 打崩）

| 限制 | 默认 | 说明 |
|---|---|---|
| 并发扫描进程 | 3 | 超了排队 |
| 单命令超时 | 300s（可配） | 到点 kill，记 `timeout` |
| 单命令输出上限 | 2MB | 超出落文件 + 摘要 |
| 全局速率 | nmap/ffuf/nuclei 各设 `--max-rate`/`-rate` | 防封禁 |
| CPU/内存 | `nice -n 10`，内存超 80% 暂停新任务 | VM 保护 |
| 磁盘 | 剩余 <5GB 停止写大文件 | 防写满 |

## §6 与 ARTEX 的接线

| 位置 | 改动 |
|---|---|
| 新包 `env/` | `discover.go`（五层扫描）、`cache.go`（tools_cache）、`provision.go`（安装/降级）、`governor.go` |
| 新包 `adapter/` | 每个工具一个文件，注册进 `ToolSet`（作为 host tools 注入，不写进主流程） |
| `guard/guard.go` `PreToolUse` | 命令首词不在缓存 → 触发 provision；仍不可用 → 返回**降级建议**（不返回 "command not found"） |
| `agent/prompt` | system 里只给"环境摘要"（有哪些关键工具、哪些降级中），**不给全表** |
| `db` | `tools_cache` / `tool_events` |
| 前端 | 「环境」页：工具列表（路径/版本/健康/来源）+ 一键重扫 + 一键安装 + 降级记录 |
| 启动 | 后台跑一次 discovery（30–90s），期间任务可正常开始（缓存可能不全，边跑边补） |

**验收**：
1. 在 Kali 里把 `sqlmap` 移出 PATH（`mv` 到 `~/tools`）→ 仍能被发现（L5 全盘）
2. 删掉 `nuclei` → 自动 `go install` 装回，或降级到 curl+PoC
3. 把 `ffuf` 改名成 `fff` → 通过 strings/哈希识别出来
4. 跑 3 个并发 nmap → 不把 VM 打满（governor 生效）
5. 无网环境 → 全部走降级，任务继续

## §7 落地顺序（嵌进总方案 P1）

| 步 | 内容 | 工期 |
|---|---|---|
| 1 | `discover.go` L1–L4 + `tools_cache` | 1d |
| 2 | L5 全盘兜底（plocate/find + xdev + 排除表） | 0.5d |
| 3 | `provision.go`（apt/pipx/go/release + 幂等 + profile） | 1d |
| 4 | `adapter/` 前 5 个（nmap/httpx/nuclei/ffuf/sqlmap） | 1.5d |
| 5 | `governor.go`（并发/超时/输出/速率） | 0.5d |
| 6 | 「环境」页 + 重扫/安装按钮 | 1d |

**合计 5.5 天**（原计划 1.5 天，因为补了全盘扫描 + 适配器 + 治理）。

## §8 一句话

**"能扫到"靠五层发现 + 哈希/strings 指纹；"能用"靠适配器把 CLI 变成结构化工具；"不崩"靠资源治理。**
只做 `which` 的工具检测，在 Kali 上大概会漏掉三分之一的东西。
