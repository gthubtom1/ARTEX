## 4. 一键部署脚本

```bash
bash -n install.sh && bash -n scripts/deploy_vps.sh      # 两个都 OK
bash scripts/deploy_vps.sh --dry-run                     # exit 0，43 行计划，不发一个包
bash install.sh --help                                   # exit 0，只打用法
bash install.sh                                          # Git Bash：走 Windows 分支，exit 2 ✅
```

- `--dry-run` **真的不发包**：输出全是 `[dry-run] 会执行：…`，跑完 `git status` 仍为空、没生成 `.env`。①～⑥ 六步 + 收尾提示都打印了（含"8788 只绑 127.0.0.1"、POSTGRES_PASSWORD 在第几行）。
- Windows 分支符合设计：`./install.sh` 在 Git Bash 下打印"照做就行"指引并 **exit 2**（不是 die / exit 1）。
- 但 **`./install.sh --docker` 在 Windows 上永远是 exit 2**，即使 Docker Desktop 已经装好——因为 `ensure_docker()` 第一行就 `if is_windows; then windows_guide; fi`，**在检测 docker 之前**就打印指引并退出。而指引第 4 步恰恰写着"回到 Git Bash 重新执行 `./install.sh --docker`"。这是个死循环（§6-#1）。

## 7. 三条硬结论

- **干净克隆可构建：是**（`go build ./...` ✅ / `go vet` ✅ / `go test ./internal/... ./agent/... ./guard/...` 38 包全绿 / `git status` 空 / 前端需首次 `NODE_ENV=development npm ci --include=dev --ignore-scripts`）
- **首次部署所需人工步骤：8 项**
  1. 准备 PostgreSQL 16 并建库（`createuser -P artex` / `createdb -O artex artex`），或走 `install.sh --docker` / `deploy_vps.sh` 由脚本起 PG
  2. 写 `config.json`（`database.dsn`）或设 `ARTEX_PG_DSN`；Docker 路线写 `.env` 的 `POSTGRES_PASSWORD`
  3. 联网拉 Go 模块（仓内无 `vendor/`），首次 `go build ./...` 需外网
  4. 前端首次装依赖 + 静态导出：`cd web && NODE_ENV=development npm ci --include=dev --ignore-scripts && npm run build:static`
  5. 首次打开页面设置管理员密码（用户名固定 `ARTEX`，`server/auth.go:275`）
  6. 配一个可用模型（provider + model + api_key；首配向导第二步或 `.env`）
  7. 宿主层出网（VPS 直连 / 本机 TUN）；只打本机靶场时启动前 `ARTEX_ALLOW_DIRECT=1`
  8. 打靶场：`docker compose -f bench/compose.yml up -d`（3 个靶标，且 `dsvw` 需要能访问 raw.githubusercontent.com）
