## 一、判定标准（判断"要不要做一件事"的唯一依据）

**问：使用者站在这两个页面上，要做的是不是同一件事。**

| 情况 | 结论 |
|---|---|
| 同一件事 | 砍掉第二个入口，或扩展已有页面的后半段动作 |
| 不同的事 | 独立新建，哪怕看起来像 |

**独立新建必须同时满足三条**：
1. 它回答的问题在现有页面里没有"家"（不是没有答案，是没地方放）
2. 它需要的输入，现有页面结构上拿不到
3. 它不制造第二个真相源（只读现有表 + 调现有接口）

**底线**：上游页面语义不动（`FORK-NOTES.md` 第 2 条）——`function/capabilities/page.tsx` 等原页面 **diff 必须为 0**。

**禁止**：用"有没有相似功能"作为合并理由（这是错误判据，已导致 2 次误砍）。

## 三、B1 / B2 混合规格（地图「拿到了什么 / 下一步」）

**默认渲染 B1（模板）**：五类走法固定 + 对象从数据里替换。**0 token，秒出。**

**侧边栏一个按钮「让它详细分析」→ 触发 B2（AI），后台跑，不阻塞页面。**

```
侧边栏（点卡片后）
  ├ 人话说明（B1 模板，永远在）
  ├ 清单表：能拿什么 | 有多少 | 操作 | 说明（B1）
  ├ 决策点：五类走法 + 耗时/风险（B1）
  ├ [ 让它详细分析 ]  ← 仅此按钮花 token
  └ 指令框（可直接复制 / 直接发给它）
```

**按钮状态机**

```
① 初始      [ 让它详细分析 ]
② 已提交    分析中…可离开本页（后台跑）        ← 可以切 tab/关页面
③ 完成      内容替换为 AI 版
            卡片标记 ✦ · 侧栏标注「AI 分析 · 21:44」· 按钮变 [ 重新分析 ]
④ 过期      之后有新 fact → 标注「已过期（之后有新发现）」+ [ 重新分析 ]
⑤ 失败      保留模板版 + 一行「分析失败，可重试」，绝不空屏
```

**关键约束**

| 项 | 规则 |
|---|---|
| 粒度 | **按节点**，不是整页。点哪个算哪个 |
| 缓存 | 键 = `(task_id, node_key, evidence_hash)`；命中直接返回，**再点不花钱** |
| 并发 | 同任务同时只跑 1 个细化任务，其余排队 |
| 上限 | 每任务 ≤20 次（超了提示"已到上限"） |
| 模型 | 复用 `adviser` 的绑定（Agent 页可改）；不新增角色 |
| 标注 | AI 生成的部分必须标「AI 分析 · 时间」；模板部分不标 |
| 证据 | AI 版每条结论必须挂证据 id；无引用标「推测」并置灰 |
| 存储 | 新表 `cando_annotations`（不是第二份战果：只存"解释文本 + 证据引用 + hash"） |

**成本**：一次 1–2k 输入 / 0.5k 输出，flash 级即可。**一个任务点 5 次 ≈ 1 万 token**（对比任务本身 2000 万）。

## 四、待拍板（执行者不得自行决定）

| # | 问题 | 选项 |
|---|---|---|
| P1 | 缺的 3 个工具（chisel / sshpass / go）怎么办 | **已定：② 环境页提示 + 每条附“装了有什么用 / 不装怎么替代 / 风险” + 可“忽略不再提醒”** |

### P1 的展示规格（每条缺工具一张小卡）

```
缺 chisel          价值：低（可替代）
  用途：把内网端口转到你这边；打内网/横向时用
  不装怎么办：用 ssh -L / socat 也能做，但要目标开 ssh 或能连出去
  装了能快多少：每次省 10–20 分钟手拼隧道
  风险：单个 apt 包，不动系统依赖
  [ 复制安装命令 ]  [ 忽略，不再提醒 ]
```

价值分级只能填三个值，不得模糊：

| 等级 | 含义 | 本次三个工具的判定 |
|---|---|---|
| 必需 | 没它这活干不了，替代物明显差 | — |
| 低（可替代）| 有等价物，效果差不多 | **chisel / sshpass / go 全部属于这一档** |
| 无所谓 | 几乎用不到 | — |

**诚实结论必须写在页面上**：这三个装了**不会明显变快**。真正拖慢速度的是另一件事：
实测本次任务 `curl 178 次 / python3 140 次 / nmap 4 次 / sqlmap 1 次`，
而 `httpx / nuclei / ffuf / whatweb / hydra` **全部 0 次**——系统里有 8422 个工具被发现，
但“端口/指纹/目录/口令”这四类活用工具的次数约等于零。

### “开箱即用”真正要补的是这三条（不是装包）

1. 开局三件套写死：`nmap_scan` → `httpx_probe` → （有目录再）`ffuf`
2. worker 提示词加硬规矩：“端口/指纹/目录/口令必须先用现成工具；注入/文件读取/带内回显可以手写”
3. 环境页显示：已发现 N 个工具 + 缺哪几个 + 每条的价值分级与替代方案

## 五、执行方式（防漂移的工作纪律）

1. **只做"零判断"的改动先做**：需要解释"为什么这样设计"的，等本文件定了再做。
2. **一条改动 = 一个 diff + 一条验证命令**，不接受"方案第 X 节说要…"这种无代码承诺。
3. 每轮汇报只报三样：改了什么（diff）、验了什么（命令+输出）、下一步一条。
4. 用户可用一句话否掉：`停` / `不对，理由是 X` / `这条先不做`。
5. 执行者（含子代理/压缩后的自己）**只读任务卡 + 本文件**，不重读全部方案。
