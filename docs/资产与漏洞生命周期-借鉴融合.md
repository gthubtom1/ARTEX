# 资产与漏洞生命周期：借鉴什么、融合什么、不要什么

> 目标：让这套东西**像干了 20 年的老手**——不是功能多，是**什么都不丢、什么都追得回、一眼知道轻重**。
> 原则：**借模型，不借系统**。CMDB/ASM/漏洞管理平台各抄一块，绝不整体搬进来（那会立刻臃肿）。

---

## §1 借鉴来源（实测，`gh search` 抓的）

| 来源 | 代表项目 | 我们抄什么 |
|---|---|---|
| **CMDB**（配置管理数据库） | `TencentBlueKing/bk-cmdb`、`veops/cmdb`、`open-cmdb/cmdb` | **CI 模型**：资产属性、标签、所有者、环境(prod/test)、重要性、生命周期、变更历史 |
| **ASM**（攻击面管理） | `natlas`、`oasm-platform/open-asm`、`red-kite/stalker`、`kernelstub/Nox`、`EasyEASM` | **持续监控**：定时重扫 → 与上次 diff → 变更告警（新端口/新子域/证书变化） |
| **Recon 数据管理** | `yogeshojha/rengine` | **数据关联**：子域↔IP↔端口↔指纹 的关联查询 + 历史快照 |
| **漏洞管理** | `ThreadFix`、`VMC`、`razorpay/bhadra`、`VulnScan-Platform` | **Finding 生命周期**：new→triaged→confirmed→reported→fixed→retest→closed；**去重合并**；SLA/时效；**重测闭环** |

## §2 只抄这六块（够了，再多就臃肿）

### ① 资产 CI 模型（借 CMDB，砍到 12 个字段）

```sql
-- 在既有 assets 表上扩列，不新建体系
ALTER TABLE assets ADD COLUMN IF NOT EXISTS owner        text;      -- 归属业务/部门
ALTER TABLE assets ADD COLUMN IF NOT EXISTS env          text;      -- prod|test|dev|unknown
ALTER TABLE assets ADD COLUMN IF NOT EXISTS criticality  int;       -- 1..5（业务重要性）
ALTER TABLE assets ADD COLUMN IF NOT EXISTS tags         text[];    -- 任意标签
ALTER TABLE assets ADD COLUMN IF NOT EXISTS lifecycle    text;      -- discovered|scanned|owned|lost|retired
ALTER TABLE assets ADD COLUMN IF NOT EXISTS first_seen   timestamptz;
ALTER TABLE assets ADD COLUMN IF NOT EXISTS last_seen    timestamptz;
ALTER TABLE assets ADD COLUMN IF NOT EXISTS last_change  timestamptz;
```

**为什么不搬 CMDB 全套**：CMDB 的 CI 类型树、关系图、自动发现代理、审批流，是给运维管的；我们只要"这资产是什么、重不重要、现在什么状态"。

### ② 持续监控与变更检测（借 ASM）

每次复查时比对四样，**任何一样变了就写一条 `change_event`**：

| 比对项 | 怎么取 | 变化意味着 |
|---|---|---|
| 开放端口集合 | nmap 结果 diff | 新服务上线 / 防守加了端口 |
| 子域集合 | 与上次枚举 diff | 新业务上线（最有价值） |
| 技术栈/版本 | httpx -tech-detect | 打补丁了 / 换了框架 |
| 证书指纹 + 到期日 | openssl | 换供应商 / 快过期（可做钓鱼/接管） |

**告警不做消息轰炸**：只在"新增"时提示（消失的一般是下线，不重要）。

### ③ Finding 生命周期（借 ThreadFix，砍到 6 态）

```
new → triaged → confirmed → reported → fixed → retest → closed
                              ↘ false_positive
```

- **去重合并**：同一 (host, path, param, vulnclass) 归并成一条，保留多条证据（ARTEX 已有 `finding_cases` 归并逻辑，补一条指纹级 key）
- **证据版本**：报告绑定 evidence 版本，避免"报告说 A，证据已变 B"（已设计）
- **SLA/时效**：从 confirmed 到 reported 超过 N 天 → 标 stale（竞赛里就是"别拖到结束才写报告"）

### ④ 重测闭环（借漏洞管理平台，这块最容易被忽略）

```sql
CREATE TABLE finding_retests (
  id bigint PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  finding_id bigint, ts timestamptz DEFAULT now(),
  result text,      -- fixed | still_vulnerable | changed
  evidence text,    -- 复测请求/响应
  by text           -- agent | human
);
```

**价值**：竞赛评审问"你确认它修好了吗"，你有记录；真实项目里这是二次收费点。

### ⑤ 凭据生命周期（这块没人做得干净，做了就是差异化）

```
discovered → verified → in_use → rotated → invalid → archived
```

- `verified` 必须有"真实认证成功"的证据（不是"看起来能用"）
- `in_use` 记录"用在哪台/哪个服务"，**复用上限 3**
- **`rotated`/`invalid` 自动检测**：复查时登录失败 → 自动改状态（这就是"10 天后还能看出掉了没有"）
- 全字段加密存储，报告/日志/知识库只出现引用 id

### ⑥ 时间线与证据链（老手和新手最大的区别）

每条 finding 必须能回答：**什么时候、用什么命令/请求、对哪个资产、得到什么响应、谁（哪个 agent/step）做的**。

```sql
CREATE TABLE evidence_timeline (
  id bigint PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  task_id bigint, asset_id bigint, finding_id bigint,
  ts timestamptz DEFAULT now(),
  kind text,        -- request | command | screenshot | dns | file
  content_ref text, -- 指向 traffic / cmd-output / blob 的引用
  sha256 text,
  actor text        -- planner|worker:<id>|adviser|human
);
```

**这张表是"报告可信度"的全部来源**。没有它，报告就是自述。

## §3 明确不抄（臃肿来源）

| 不抄 | 为什么 |
|---|---|
| 完整 CMDB（CI 类型树、关系图谱、自动发现代理） | 给运维用的，我们没有配置管理需求 |
| 工单/审批流系统 | 竞赛与个人使用不需要 |
| 合规映射（ISO 27001 / NIST / PCI-DSS） | 增加 90% 的字段，换来 0 的实战价值 |
| 多租户 + 完整 RBAC | 一个人的工具，不需要 |
| SLA 计费与客户门户 | 同上 |
| 资产自动发现 agent（装在目标上的） | 我们是被动打，不是运维监控 |

## §4 20 年资深渗透的"隐性知识"清单（这才是真差异）

功能谁都能加，**下面这十条才是"老手"**。全部可以写成 skill + 代码检查：

| # | 老手习惯 | 怎么落进系统 |
|---|---|---|
| 1 | **先判轻重**：不是所有资产都值得打 | `criticality` + 打分排序，只打 top3 |
| 2 | **同一条结论三种复现才写报告** | 三门校验 + 复现门 |
| 3 | **打完立刻记"下次怎么更快"** | MEMORY 接力块 + `kb/cases` 自动沉淀 |
| 4 | **资产分级持有**：核心/跳板/一次性 | `tags: core|jump|throwaway` + 复查频率不同 |
| 5 | **报告是写给要修的人看的** | reporter 的修复建议必须可执行（不是"加强校验"） |
| 6 | **时间盒与止损**：超时就走 | 阶段预算 + 冻结门 |
| 7 | **不用别人的资产当跳板** | `via_asset` 链路必须可追溯到自己的 `assets_owned` |
| 8 | **证据比结论重要** | evidence_timeline + sha256 |
| 9 | **每次结束写"如果重来"** | 任务收尾强制一条 retrospective（写进 cases） |
| 10 | **走之前清理**：不留后门 | 赛后 `cleanup` 流程 + `status=cleaned` 记录 |

## §5 与现有表的映射（不重复造）

| 概念 | 已有 | 要补 |
|---|---|---|
| 资产真值 | `assets`（root_domain→subdomain→ip→service→app→endpoint） | 扩 8 个列（§2①） |
| 已持有 | — | `assets_owned` + `access_refs` |
| 可达 | — | `routes` |
| 复查 | — | `asset_checks` + `change_event` |
| 漏洞 | `exploration_nodes(kind=finding)` + `finding_cases` | `finding_retests` + 指纹去重 key |
| 凭据 | `insert_assets.auth` / `record_intelligence` | `creds_vault`（加密+生命周期） |
| 证据 | `traffic_*` + `cmd-output/` | `evidence_timeline`（索引层） |
| 知识 | `kb/` + `kb/cases` | 补 `result: dead-end` 负案例 |
| 审计 | — | `audit_log` |

## §6 落地优先级

| 序 | 做什么 | 工期 | 为什么先它 |
|---|---|---|---|
| 1 | `assets` 扩列 + `change_event` | 1d | 持续监控的前提 |
| 2 | `finding_retests` + 指纹去重 | 1.5d | 报告可信度 |
| 3 | `creds_vault`（加密 + 生命周期） | 2d | 凭据是最容易出事的地方 |
| 4 | `evidence_timeline` | 1.5d | 老手与新手的差别 |
| 5 | `assets_owned` + `access_refs` + `routes` | 2d | 长期持有与横移 |
| 6 | 十条隐性知识写成 `skills/veteran/SKILL.md` | 0.5d | 立刻生效，零代码 |

**第 6 项今天就能做**：把 §4 那十条写成一个 skill 绑给 planner/worker，它立刻开始"像老手一样思考"。

---

## §7 一句话

**老手的强不在知道更多漏洞，在于：知道什么不值得打、结论要三种复现、打完不忘记录、资产分级持有、走前清理。**
这些全是**流程**，不是功能——所以最便宜，也最容易被参赛队忽略。
