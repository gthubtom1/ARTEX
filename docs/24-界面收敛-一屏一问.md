# 24 · 界面收敛：一屏一问（给零基础的人看）

> 起因（2026-10-24 用户原话）：
> "我没有办法第一眼就找到我想要的东西……加的东西太多了，我现在也糊涂了。
>  到底应该怎么设计，就是简洁明了，你能懂我的意思吗？"
>
> 结论：**不是再加东西，是减。** 每个屏只回答一个问题；主视线最多 3 个可点按钮；
> 其余全部折叠，折叠的标签上写数量（"6 个洞 / 2 条链 / 4 个越界动作"）。

---

## 一、一条原则：看 vs 做（AI 按钮到底多余不多余）

用户的困惑："我明明可以在主对话里让主对话去做，为什么还要 AI 按钮？"

答案：两者**不是同一件事**，把这张表记住就不会再乱：

| 入口 | 它干什么 | 花多少 | 会改目标站吗 | 谁在等 |
|---|---|---|---|---|
| **卡上的 AI 按钮**（✦ 分析我现在能做什么） | **只读**：把已经拿到的证据翻成"我现在真能做什么" | 几秒、按证据缓存、重复点不花钱 | 不会 | 你一个人，随时点 |
| **卡上的「就做这个」**（复制一句） | 把"帮我…"这句**填进输入框**，你自己按发送 | 不发就 0 | 不会（没发就没动） | 你 |
| **主对话里说「帮我…」** | **真的去做**：打洞、取数、落文件 | 贵（一次可能几十万 token） | **会** | 规划者/worker 排队 |

所以：**AI 按钮回答"能做什么"，主对话负责"去做"。** 不允许 AI 按钮派任务
（那等于让它替你做决定，还要你等、还烧钱）。

## 二、任务页:一屏一问

主视线（打开就看到，不用滚）**只放一张卡**，五行：

```
┌─ 战况 ─────────────────────────────────────────────────────────────┐
│  我在哪   E2 应用控制   ●●○○○○   已确认 6 个洞                    │
│  我有什么 [后台管理员会话] [业务数据样本]                            │  ← 最多 3 个
│                                                                     │
│  现在能做到（真的能做到，有证据）                                    │
│   ① 把订单表导出来（证据 #298）                        [就做这个]    │
│   ② 看后台用户和密码（证据 #316）                      [就做这个]    │
│   … 还有 1 件                                                       │
│                                                                     │
│  还差一步   3 个洞差一步就能换到东西 → 进后台（差：管理员会话）      │  ← 一行，不铺开
│  换不到东西 2 个洞目前换不到任何后果 → 看是哪两条                     │  ← 一行
│                                                                     │
│  想让我做就说一句，或者点上面的 [就做这个]（只填入，不发送）  ✦ 分析 │
└─────────────────────────────────────────────────────────────────────┘
```

规则：

- **后果清单最多显示 3 条**，多的收成「还有 N 件」（折叠里看全部 7 条 + AI 补充的站点特有后果）；
- **每个洞只出现在一个分组里**（已成立 / 差一步 / 换不到），不重复列；
- **主视线只有一个 AI 按钮**（`✦ 分析`），点一次刷新三处（漏洞解释 / 站点特有后果 / 该说什么）；
- 原来散落的三个 AI 按钮（每个洞一个、补站点特有、补战果项）**移进折叠区**，主视线不放；
- 灰着的后果**不代表假**：它是"可能的后果清单"，只有证据到了才点亮 —— 卡片里写明这句，避免"灰色=假的"误解。

## 三、折叠区（点开才看，标签带数量）

| 折叠标题 | 里面是什么 | 默认 |
|---|---|---|
| `6 个洞 · 每个能换到什么（AI）` | 逐条洞的三段式 + AI 一句话 + 证据号 | 收起 |
| `7 件后台能做的事（含 AI 补充）` | 全量后果 + 前置 + 留证要求 + 工单状态 | 收起 |
| `2 条利用链` | 每条链的步骤 + 下一步 | 收起 |
| `4 个越界动作（默认不做）` | 只读状态，无按钮 | 收起 |
| `任务描述 / 目标 / 约束 / token 用量` | 管理类信息 | 收起 |

## 四、会话页：只回答"有新东西吗、该说什么"

- 顶部一条状态行：`战果 5（+2 新）` + `它下一步想做：…`（一句话，无按钮）；
- 战果面板每行主句是白话，点开看证据；
- 输入框上方：`这个站现在能说`（3–5 条短语 + ⟳ 重算），点一下只填入。

**会话页不放**：战况卡、利用链、越界动作、AI 分析按钮（都在战况页）。

## 五、信息分三层（决定"第一眼"看到什么）

| 层 | 什么时候看到 | 放什么 |
|---|---|---|
| L0 一眼 | 打开就有 | 等级 / 已拿到 / **能做到 3 条** / 差一步 / 换不到（各一行） |
| L1 点开 | 点折叠标题 | 全量洞、全量后果、链、越界动作 |
| L2 证据 | 再点一次 | 证据号 → 原始请求响应 |

**判据（零基础可用）**：打开任务 5 秒内能说出"我现在能做什么"；主视线可点按钮 ≤ 3 个；
任何一屏不需要横向滚动。

## 六、和 docs/23 的关系

- `docs/23` 定**数据与判定**（三层模型、三段式 standing、AI 只写文案、闸门、顺序）；
- 本文定**界面与信息层级**（一屏一问、看 vs 做、折叠规则、5 秒判据）。
- 两者冲突时：**数据判定以 docs/23 为准，展示取舍以本文为准。**

## 七、实施清单（合并进 docs/23 §七 的第 2 步）

1. 战况卡重排：五行布局 + 三个分组（每条洞只进一组）+ 后果只显示 3 条 + 「还有 N 件」；
2. 一个 AI 按钮（`✦ 分析`）放卡头右侧，点一次刷三处；其余 AI 按钮进折叠区；
3. 折叠区标题带数量，默认全收；
4. 卡片底部一句固定说明：「灰的是可能清单，只有拿到证据才会点亮；AI 只做解释，不替你决定」；
5. 「就做这个」= 复制/填入，不发送（沿用 P1 的 `pickPhraseIntoMain`）。
