# 跑偏判别与纠正 · 通用版

> 前一篇 `顾问agent设计.md` 只解决了"只打前端"这一种。本文解决**所有**跑偏类型：
> 在错误的地方越挖越深、换皮绕圈、被假事实带跑、目标漂移……
> 结论先行：**光加提示没用，必须加"减法"**（冻结 / 配额 / 假设回溯）。原因见 §1.0。

---

## §1.0 根因：探索图是"单调累积"的，这是正反馈陷阱

代码事实（`agent/tools.go` `addOneIntent`）：

- 意图的 `parent_ids` **只能是 fact / finding 节点**（代码硬校验，`n.Kind != KindFact && != KindFinding` 直接报错）。
- 所以：**图里 fact 越多 → 可供派生的 parent 越多 → planner 越容易沿着已有 fact 继续往下派。**
- 而"某个方向打不通"这件事，在图上表现为**没有新 fact**——于是它连"这个方向已经死了"都表达不出来。

结果：**越挖越深的不是模型，是数据结构。** 越丰富的图，越奖励局部深化，越不奖励"换一层"。

这就是为什么必须引入**减法**：冻结某方向、给方向设预算、把假设判为已证伪。
只靠 `add_hint` 说"换个方向"，等于在正反馈环里加一句劝告，会被图自己冲掉。

## §1 九种跑偏类型（每种都有代码级成因）

| # | 类型 | 现象 | 代码级成因 | 主检测信号 |
|---|---|---|---|---|
| 1 | **局部深挖**（沉没成本） | 同一入口派生 5+ 条意图，越挖越细 | 意图 parent 必须是 fact → 有 fact 的锚点天然高产 | `(asset,tactic)` 方向内意图数 ≥ 4 且 finding=0 |
| 2 | **换皮绕圈** | 同一件事换措辞反复派 | 去重靠 summary 文本比对，无手法分类 | 同方向 3-gram Jaccard ≥ 0.7 |
| 3 | **假事实传染** ★最致命 | 一条猜出来的 fact 生出整条错误链 | fact 有 `confidence` 字段，但 `derived_from` 不区分置信度，inferred fact 与 observed fact 派生力相同 | 方向链条上首个 fact 为 inferred，且下游 ≥ 3 个 |
| 4 | **状态误读** | 403 当"有防护"、302 当"登录成功"、版本号当漏洞 | 没有语义层，只有 HTTP 码 | finding.evidence 里只有状态码 / 只有版本串 |
| 5 | **环境幻觉** | 命令不存在、代理不通、目标不可达，仍继续推进 | Bash 报错被当成目标响应；`proxyEnv` 注入的代理失败时无区分 | 连续 Bash 报"command not found / connection refused / proxy" |
| 6 | **广度爆炸** | coverage 涨但 finding=0，一堆浅意图 | 为了规避"重复"去挖新浅面 | 意图数 ↑ / fact 唯一率 ↓ / finding = 0 |
| 7 | **目标漂移** | 把"完成意图"当目标；收尾靠 prove_goal 却没人核对距离 | 只有 `prove_goal` 一个收尾口，没有 goal↔intent 距离度量 | 最近 10 条意图与 goal 关键词重合度 ↓ |
| 8 | **记忆丢失** | compaction 后重复已做过的动作 | cold_digest 折叠冷节点（`coldgraph.go`），折叠后细节不可见 | 新意图与"已 done 且冷"的意图高度相似 |
| 9 | **预算失控** | 一条意图跑 40 分钟 | `maxTurns=0` 默认不限；`run_seconds` 默认 1200 | 单 run 时长 / 任务总时长 |

> 类型 3 是"在错误地方越陷越深"的**主因**。必须先治它。

## §2 方向的定义：`(锚点, 手法)`

一切度量都建立在这个二元组上。没有它，"跑偏"无法计算。

### 2.1 手法分类器（Tactic Classifier）

`db/tactic.go`（新增，纯 Go，无 LLM，< 80 行）

```go
// Tactic 手法类别。分类器是确定性的关键词映射，允许误判——它只用于统计方向，
// 不参与任何安全判定，误判的代价是多算一个方向，可接受。
type Tactic string

const (
    TRecon   Tactic = "recon"    // 指纹/子域/端口/目录
    TEnum    Tactic = "enum"     // 参数/接口/版本枚举
    TAuth    Tactic = "auth"     // 登录/令牌/越权/会话
    TInject  Tactic = "inject"   // sqli/xss/ssti/xxe/cmdi/ldap
    TUpload  Tactic = "upload"   // 文件上传/包含/写入
    TSSRF    Tactic = "ssrf"     // ssrf/重定向/内网探测
    TDeser   Tactic = "deser"    // 反序列化/gadget
    TRCE     Tactic = "rce"      // 命令执行/shell 落地
    TPrivEsc Tactic = "privesc"  // 提权
    TLateral Tactic = "lateral"  // 横向/凭据复用
    TData    Tactic = "data"     // 数据读取/导出/备份
    TOther   Tactic = "other"
)

var tacticRules = []struct{ t Tactic; kw []string }{
    {TRecon,   []string{"指纹", "子域", "目录", "端口", "扫描", "nmap", "whatweb", "robots", "sitemap"}},
    {TEnum,    []string{"枚举", "参数", "接口", "版本", "路径", "端点"}},
    {TAuth,    []string{"登录", "口令", "弱口令", "jwt", "token", "会话", "越权", "idor", "认证", "cookie"}},
    {TInject,  []string{"注入", "sqli", "xss", "ssti", "xxe", "命令注入", "ldap", "盲注", "payload"}},
    {TUpload,  []string{"上传", "包含", "写入", "webshell", "解析"}},
    {TSSRF,    []string{"ssrf", "重定向", "内网", "169.254", "gopher", "回连"}},
    {TDeser,   []string{"反序列化", "gadget", "链", "pop", "ysoserial"}},
    {TRCE,     []string{"rce", "命令执行", "反弹", "shell", "getshell"}},
    {TPrivEsc, []string{"提权", "sudo", "suid", "cron", "内核", "capability"}},
    {TLateral, []string{"横向", "凭据复用", "跳板", "内网"}},
    {TData,    []string{"数据", "备份", "导出", "泄露", "日志", "dump"}},
}

func Classify(summary string) Tactic {
    s := strings.ToLower(summary)
    for _, r := range tacticRules {
        for _, k := range r.kw {
            if strings.Contains(s, k) { return r.t }
        }
    }
    return TOther
}
```

**方向 key** = `assetID + ":" + tactic`。锚点为空的意图归到 `global:<tactic>`。

### 2.2 方向矩阵 SQL（一次查清"我在哪几个格子里"）

```sql
-- 本任务每个方向：试了几次 / 产出几条 fact / 有几个 finding / 烧了多久
SELECT
  COALESCE((n.payload->>'asset_ids')::text,'global')  AS anchor,
  n.id, n.state,
  (SELECT count(*) FROM exploration_edges e
     WHERE e.from_id = n.id AND e.rel = 'yields')     AS yielded,
  n.started_at, n.ended_at
FROM exploration_nodes n
WHERE n.task_id = $1 AND n.kind = 'intent';
-- tactic 在 Go 里对 summary 调 Classify() 后聚合（避免在 SQL 里维护词表）
```

## §3 三个度量（全确定性，0 token）

```
progress_velocity = (unique_new_facts + 5*findings) / max(1, rounds_since_last_progress)
   unique = 与已有 fact 的 3-gram Jaccard < 0.75 的才算新

drift_ratio = 最近 10 条意图中 (tactic 与 goal 关键词不相关 且 锚点不在覆盖路径上) 的占比

confidence_taint = 方向链上首个 fact 为 inferred 的链条数 / 总链条数
```

阈值（写入 settings，可调）：

| 指标 | 触发 | 含义 |
|---|---|---|
| `progress_velocity` | < 0.5 连续 2 轮 | 在空转 |
| 同方向意图数 | ≥ 4 且 finding = 0 | 局部深挖，该冻 |
| `drift_ratio` | ≥ 0.4 | 目标漂移 |
| `confidence_taint` | ≥ 0.3 | 假事实传染严重，先做假设回溯 |
| 单 run 时长 | > 任务 timeout 的 25% | 预算失控 |

## §4 减法三件套（这是本文的核心）

### 4.1 冻结硬门（阻止继续深挖）

新表：

```sql
CREATE TABLE IF NOT EXISTS task_freeze (
  task_id   bigint NOT NULL,
  asset_id  bigint NOT NULL DEFAULT 0,
  tactic    text   NOT NULL,
  reason    text   NOT NULL,
  by        text   NOT NULL DEFAULT 'adviser',
  round_no  int    NOT NULL,
  until_round int  NOT NULL,
  PRIMARY KEY (task_id, asset_id, tactic)
);
```

**硬门补丁**（`agent/tools.go` `addOneIntent`，紧跟已有的资产拦截校验之后）：

```go
// 冻结门：方向被顾问冻结后，除非本轮出现了该锚点上的新 fact，否则拒绝派意图。
if t.ts != nil {
    if fr, hit := t.ts.IsFrozen(t.taskID, anchors, db.Classify(it.Summary)); hit {
        return 0, fmt.Errorf("方向 [%s] 已被冻结（%s）。要重开该方向，必须先给出与上次机理不同的新材料（新 fact / 新凭据 / 新入口），并在 summary 里写明不同点。", fr.Tactic, fr.Reason)
    }
}
```

注意这是**硬拒绝**，不是提示词劝告——所以模型的"再试一次"在这一层直接失效。

### 4.2 方向预算（阻止预算被单点吃光）

引擎侧按 `(asset,tactic)` 累计 run 秒数；超过 `方向预算 = max(5min, 任务timeout/8)` 时，
自动写入 `task_freeze`，并 emit 一条 activity。**不需要 LLM 参与。**

### 4.3 假设账本（治"假事实传染"）

新表 + advisor 工具 `audit_assumption`：

```sql
CREATE TABLE IF NOT EXISTS assumptions (
  id bigint PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  task_id bigint NOT NULL,
  text text NOT NULL,                 -- "目标存在 /admin 后台"
  status text NOT NULL DEFAULT 'unverified',  -- unverified|verified|refuted
  evidence_node bigint DEFAULT 0,
  created_round int, resolved_round int
);
```

规则（写进 planner 与 worker 提示词，且由顾问维护）：

- 任何 `confidence=inferred` 的 fact，必须能对应到一条 assumption。
- **从 inferred fact 派生的意图，worker 的第一件事是验证该事实本身**，不是往下利用。
- assumption 一旦 `refuted`，所有派生意图立即冻结（复用 4.1）。
- 连续 3 条 inferred fact 未被验证 → 全部降级并冻结其派生链。

这一条把"在错误地方越陷越深"从根上断掉：**错误的地基不能盖楼。**

## §5 顾问的决策表（不让 LLM 自由发挥）

顾问不是"随便给建议"，而是**按信号查表执行**。LLM 只负责把动作翻译成能执行的具体 hint。

| 命中信号 | 顾问动作（固定） |
|---|---|
| 同方向意图 ≥ 4 且 finding=0 | 冻结该方向 + hint「停止 X，改打 Y」 |
| `progress_velocity < 0.5` ×2 轮 | kill 最长 run + hint 换层 + 列负空间前 3 |
| `confidence_taint ≥ 0.3` | 不派新方向；先让 worker 验证被污染的 assumption |
| HTTP 码当证据 / 版本当漏洞 | hint「必须实际触发一次，否则降级 inferred」 |
| 连续 Bash 环境类报错 ≥ 3 | hint 环境自检（命令在不在、代理通不通、目标活不活），**先修环境再打** |
| `drift_ratio ≥ 0.4` | hint 回读 goal 原文 + 重列「目标达成的判据」 |
| 单 run > 25% 总时长 | kill 该 run + 顾问读 trace 判断"是否已接近突破"，是则改写意图续跑 |
| 意图数 ↑ 而 finding=0 | 停派浅方向，改派"把已有 fact 里最可疑的一条打穿" |
| 与已冷 done 意图高度相似 | 直接拒绝重派，hint 指向冷节点 detail |

**沉默优先**：以上都不命中 → 输出 0 条 hint。顾问每轮都说话本身就是噪声源。

## §7 接线顺序与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0** | §2 手法分类器 + §2.2 矩阵 + §6 面板（只读，不纠正） | 跑一台靶机，面板能正确显示"在哪个格子挖了几次、产出几个" |
| **P1** | §4.1 冻结硬门 + §5 决策表（顾问按表出 hint） | 同方向 4 次无产出 → 第 5 次派意图**被代码拒绝** |
| **P2** | §4.2 方向预算（引擎侧自动冻结） | 单方向耗时不再超过总预算 12.5% |
| **P3** | §4.3 假设账本 | 人为注入一条假 fact（如"存在 /admin"），下游 3 条意图先验证它而不是继续利用 |

**核心验收指标**：`同方向最大意图数`。现状经常是 6–10；P1 之后应稳定 ≤ 4。
这个数比"找到几个洞"更能证明它不再跑偏——因为它衡量的是**它有没有能力停下来**。
