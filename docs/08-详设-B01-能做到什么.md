## 1. 用户故事

**谁**：不懂技术的委托人（会点鼠标、会复制粘贴，不懂 LFI/注入/权限）。
**什么时候**：任务跑起来之后，他每隔几分钟会回来看一眼；或者跑完了要看"我到底拿到了什么、够不够"。
**想完成什么**：一眼知道①现在在打哪个方向 ②手里已经有什么（具体到"有未售卡密/有用户密码"这一档）③还能往哪走 ④够不够，要不要停。
**成功长什么样**：打开页面 3 秒内能回答"能不能进它的系统"；点一张已拿下的卡片能拿到一句可复制的指令；不需要读任何技术名词。

## 2. G0 三问

1. **谁在什么场景用**：任务详情页，跑着的时候 + 跑完之后。
2. **解决哪一件具体事**：把"零散的洞"变成"我手里有什么 + 下一步派什么活"。
3. **现有页面为什么不够**：
   - 「发现」：列出洞有几条，回答"有多少"，不回答"串起来能干什么"。
   - 「能力菜单」：跨任务、按能力分组、做"这张卡要不要深挖"的商业裁决；结构上是卡片列表，**拿不到 `exploration_nodes`（谁在跑）**，画不出链路。
   - 「探索链路」：是"它做了什么"（意图→事实→漏洞），不是"我得到了什么"。

独立三门槛：① 问题没家（11 个 tab 里没有一个放"战果+下一步"）② 输入拿不到（能力菜单没有图节点数据）③ 不造第二真相源（只读现有表 + 调现有接口）。**三条全过 → 独立新建。**

## 3. 界面规格

> **实现方式已修正（2026-10-23）**：不自绘 React Flow，而是**直接复用探索链路的 `ExplorationGraph` 组件**
> （同一套分层布局 / barycenter 排序 / 连线关系标签 / 小地图 / 点击详情 Sheet），只通过 `labels`
> 把节点语义换掉：`goal→目标`、`intent→入口`、`finding→能做到`、`fact→拿到了什么`、`hint→建议`。
> 教训：手搓一份画布只能抄到外表，抄不到“真实关系 + 自动布局 + 实时轮询”这三件让它好看的东西。
> 旧的自绘实现已删除。

**位置**：`web/src/app/(main)/function/tasks/detail/page.tsx` 的 `const TABS`，插入在「发现」之后：

```
会话 总览 探索链路 播报板 发现 [能做到什么] 任务情报 复测 测试资产 资产覆盖图 拦截审批 报告
```

**布局**：上方顶栏（目标 + 达成标记 + 两个按钮）→ 一条"你现在就能拿"横条 → 画布（可缩放/拖动/小地图）→ 右侧栏 392px（点节点后出现）。

**顶栏**
```
目标：拿下它的服务器权限    [未达成 0/1]      但已经能：读全部文件 · 读写数据库
                                                    [ 够了，停 ]  [ 继续冲权限 ]
```
空态：目标是空的 → 显示"这个任务没有写目标，只做盘点"（不报错）。

**横条（loot）**
```
你现在就能拿： [数据库 3 类] [服务器文件 4 类] [用户密码] [数据库口令] ...
```
空态：无任何已拿下项 → 整条不渲染（不占位置）。

**画布节点（6 类 + 1 横幅）**：见 §4 状态与 §7 字段来源。视觉与「探索链路」同库同风格（点阵底、236px 圆角卡、4px 左色条、顶部同色淡底带、右上状态胶囊、实线/虚线带标签连线、选中蓝框、右下小地图）。

**右侧栏（点节点后）**
```
① 人话说明（B1 模板，永远有）
② 清单表：能拿什么 | 有多少 | 操作(取样本/全量/不做) | 说明
③ 决策点（仅"已拿下"节点）：五类走法 + 耗时/风险/得到什么，★推荐
④ [ 让它详细分析 ]        ← 唯一花 token 的按钮（B2，按需）
⑤ 指令框 + [复制指令] + [直接发给它]
```

**三态**：加载（骨架屏，不闪白）／空（"这个任务还没有可展示的战果"）／失败（"战果数据取不到，30 秒后重试" + 重试按钮）。

## 4. 状态机

**节点状态**（互斥，按优先级判断）

| 状态 | 判定 | 视觉 |
|---|---|---|
| 正在攻 | 该 lane 关联的 intent `state='running'` | 蓝胶囊 + 呼吸点 + 蓝框 |
| 已拿下 | 该 lane 的能力项 `proof_level ∈ {P2,P3}` 且 `confidence='observed'` | 绿绸带「已拿下」+ 绿胶囊 |
| 空转 | 连续 ≥3 轮无新 fact（复用 stale 判定） | 黄胶囊 |
| 封死 | `task_error_events.class='target_blocked'` 且同 lane ≥3 次 | 红胶囊 |
| 我方故障 | 同 lane 最近一条错误 `class ∈ {self_error, env_error}` | 灰胶囊「我方故障」 |
| 未试 | 无 finding、无 running、无错误 | 默认灰胶囊 |

**细化按钮状态**

```
idle → [让它详细分析]
submitted → ● 分析中…可离开本页
done → 内容替换 + ✦ 标记 + 「AI 分析 · HH:MM」+ [重新分析]
stale → 「已过期（之后有新发现）」+ [重新分析]
failed → 保留模板版 + 「分析失败，可重试」
```

## 5. 数据结构

```sql
-- 只存"解释文本 + 证据引用"，不存战果本身（不造第二真相源）
CREATE TABLE IF NOT EXISTS cando_annotations (
  id           BIGSERIAL PRIMARY KEY,
  task_id      BIGINT NOT NULL,
  node_key     TEXT   NOT NULL,           -- 'ep:/Templatize.asp' | 'err:target_blocked' | 'neg'
  evidence_hash TEXT  NOT NULL,           -- sha256(该节点证据集合)，变化即失效
  status       TEXT   NOT NULL,           -- pending|done|failed
  text         TEXT   NOT NULL DEFAULT '',-- AI 写的人话（粗粒度：只定性，不写数量）
  cites        JSONB  NOT NULL DEFAULT '[]', -- [{"kind":"finding","id":31},{"kind":"fact","id":16}]
  model        TEXT,
  tokens_in    INT DEFAULT 0,
  tokens_out   INT DEFAULT 0,
  error        TEXT,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  finished_at  TIMESTAMPTZ,
  UNIQUE (task_id, node_key, evidence_hash)
);
CREATE INDEX IF NOT EXISTS idx_cando_task ON cando_annotations(task_id, node_key, created_at DESC);
```

不新增表也能做（放 `capabilities.next_if_approved`），但会与能力菜单抢同一字段 → 违反"不造第二真相源"的反面（两个页面写同一列）。**故独立表，且只写解释。**

## 6. 接口契约

| 方法 | 路径 | 入参 | 出参 | 错误 |
|---|---|---|---|---|
| GET | `/api/tasks/{id}/cando` | `id` (path) | `{banner, loot[], lanes[], annotations{node_key:Annotation}, budget}` | 404 任务不存在；500 |
| POST | `/api/tasks/{id}/cando/annotate` | `{node_key}` | `202 {status:"pending"}` 或 `200 {cached:true, annotation}` | 429 已有任务在跑；409 超上限(20)；404 node 不存在 |
| GET | `/api/tasks/{id}/cando/annotate?node_key=x` | — | `{status, text, cites[], finished_at, stale:bool}` | 404 |
| POST | `/api/tasks/{id}/hint` | `{text, asset_ids[]}` | `{ok:true, id}` | 400 空文本；403 任务已终止 |

**超时**：GET 5s；annotate 提交立即返回（后台跑，单次上限 45s）。
**轮询**：前端 15s 刷 `cando`；annotate 在跑时 5s 轮询该 node。

**hint 端点说明**：现在只有 agent 工具 `add_hint`，没有 HTTP 入口。实现时把 `agent/tools.go:1743 addHint` 的落库逻辑（AddNode(KindHint) + NotifyHint + 唤醒 planner）抽成 `server.addHintForTask(taskID, text, assetIDs)`，两个入口共用，**不许复制一份写库逻辑**。

## 7. 字段来源映射（每字段←哪张表哪列）

| 展示字段 | 来源 | 缺失时降级 |
|---|---|---|
| 顶栏目标 / 达成 | `tasks.goal` / `exploration_nodes(kind='goal').state` | 目标空 → 「未写目标」 |
| lane 入口 | `assets` where `type='endpoint'`，label=路径 | 无 endpoint → 用 finding 的 asset label |
| lane 能力 | `findings` join `task_asset_links`（该 endpoint） | 无 → lane 不渲染"能做到"节点 |
| 拿到了什么 | `capabilities.impact`（B2 填）／`findings.evidence` 摘要（B1） | 都空 → 显示"还没确认具体数据" |
| 卡住了 | `task_error_events(class='target_blocked')` 按 asset 归并 | 无关联 → 挂 lane 级 |
| 已排除 | `s.negativesFromTask(t)`（已存在，报告在用） | 空 → 隐藏该节点 |
| 下一步 | `capabilities.next_if_approved` | 空 → B1 五类走法模板 |
| 状态胶囊 | `exploration_nodes.state` + `activity`(最近 fact 时间) + `task_error_events.class` | — |
| loot 横条 | `capabilities` where `proof_level≥P2 and evidence<>''`，取前 6 | 空 → 不渲染 |
| 预算 | `tasks.timeout_seconds` / `first_run_at` / `llm_usage` 汇总 | 无 → 隐藏该行 |

**红线**：任何一个字段若映射不出来，**显示"未确认"，不许猜**。

## 8. 失败态与降级

| 依赖挂了 | 表现 |
|---|---|
| PG 查询失败 | 整页"数据取不到 + 重试"，不显示半截数据 |
| `negativesFromTask` 失败 | 少一个节点，其余正常 |
| annotate 排队中 | 按钮禁用 + "前面还有一个在分析" |
| annotate 超时/模型挂 | status=failed，保留模板版 + 「可重试」；**不弹红字**，不写错误条 |
| 证据 hash 变了 | 标 stale，不自动重算（省钱），给按钮 |
| 任务已终止 | 「够了，停」按钮置灰；其余照常看 |

## 9. 成本与性能

- 画布：15s 轮询；单次查询 ≤3 条 SQL；节点数 ≤50（超出折叠，不进画布）
- annotate：**按节点**触发；缓存键 `(task_id,node_key,evidence_hash)` 命中即 0 token
- 单次预算：输入 ≤2k / 输出 ≤600（**只写定性，不写数量**）
- 上限：每任务 20 次；同任务并发 1，排队 1
- 模型：复用 `adviser` 的 agentKey 绑定（Agent 页可改），不新增角色

## 10. 权限与安全

| 动作 | 限制 |
|---|---|
| 看 | 登录即可（与任务详情同权限） |
| annotate | 登录即可；每任务 20 次上限 |
| 直接发给它（hint） | **含不可逆动词（改数据/写文件/删/上传）时禁止**，只允许复制；其余二次确认 |
| 不变量 | 本功能**只读**战果表；唯一写操作是 `cando_annotations` 与 hint 节点 |

## 13. 不许动清单 + 已知坑 + 停止条件

**不许动**
- `web/src/app/(main)/function/capabilities/page.tsx`（diff 必须为 0）
- `report/report.go` 现有 findings 渲染（摘要行已由 CARD-A01 改过）
- planner / worker 主循环、`agent/tools.go` 现有工具签名
- 不得复制 `addHint` 的写库逻辑（抽公共函数）

**已知坑**
1. `@xyflow/react ^12.3.0` 已在依赖里，**不要引入新图库**；布局函数可照抄 `exploration-graph.tsx` 的 barycenter 段。
2. `tasks.status` 从不写 `running`（只有 paused/done/timeout），**不要用 status 判断"在跑"**，用 activity 最近时间。
3. `assets` 里 endpoint 的 label 可能重复 → lane 用 `label+id` 去重。
4. `capabilities.impact` 目前几乎全是空（agent 不填）→ B1 必须有降级，不能等 B2。
5. React Flow 的 Handle 要 `opacity-0`（照抄探索链路），否则卡片边缘出现小圆点。
6. `evidence_hash` 用「finding ids + fact ids + 关键字段」排序后 sha256，**不许用时间**（时间会天天变，缓存永远失效）。

**停止条件**
- 若发现 `capabilities.proof_level` 无法区分"已拿下"（例如恒为 P1）→ 停下回报，改用 `findings.status='confirmed'` 判定。
- 若 `negativesFromTask` 返回结构与预期不符 → 停下回报，不许自己改它。
- 若 endpoint 资产与 finding 的关联缺失超过半数 → 停下回报，lane 归并规则需重定。
